TDialog

Classe Base Herda de TWindow source/classes/dialog.prg

TDialog é a classe usada para criar caixas de diálogo modais e não-modais no FiveWin. Ela herda de TWindow e adiciona comportamentos específicos de diálogos: ativação modal/não-modal, criação baseada em recursos, seleção de sistema de coordenadas (texto, pixel, pixel real), fundos transparentes de controles, suporte a modo escuro e um ciclo de vida estruturado com fases ON INIT / VALID.

Herança

Principais Métodos

New() — Construtor

METHOD New( nTop, nLeft, nBottom, nRight, cCaption, cResName,
      hResources, lVbx, nStyle, nClrText, nClrBack, oBrush, oWnd,
      lPixels, oIco, oFont, nHelpId, nWidth, nHeight, lTransparent,
      aGradColors, cVarName, lUnicode, lTruePixel, lResizable )

Cria um objeto TDialog. Se cResName for fornecido, o layout do diálogo vem de um recurso compilado. Caso contrário, as coordenadas definem o tamanho do diálogo. Quando nWidth e nHeight são diferentes de zero, eles substituem nBottom/nRight e forçam o modo pixel.

Define() — Construtor Alternativo

METHOD Define( nTop, nLeft, nBottom, nRight, cCaption, nStyle,
      lVbx, nClrText, nClrBack, oBrush )

Construtor mínimo usado principalmente pelo designer visual. Cria o objeto com menos parâmetros.

Activate()

METHOD Activate( bLClicked, bMoved, bPainted, lCentered,
      bValid, lModal, bInit, bRClicked, bWhen, lResize16,
      lCenterInWnd, lMdiChild, oMdiChild, bMdiSetup, oMonitor )

Cria o diálogo Win32 e entra no loop de mensagens. Para diálogos modais (padrão), esta chamada bloqueia até que End() seja chamado. Para diálogos não-modais (lModal := .F. ou cláusula NOMODAL), retorna imediatamente.

End()

METHOD End( nResult )

Fecha o diálogo. Se bValid estiver definido, ele é avaliado primeiro; se retornar .F., o diálogo permanece aberto. O parâmetro opcional nResult define ::nResult antes de fechar.

cToChar()

METHOD cToChar( hActiveWnd )

Gera uma representação em string do diálogo e todos os seus controles — usado pelo designer visual para serializar um diálogo em código-fonte.

SetDarkMode()

METHOD SetDarkMode( nClrText, nClrBack )

Habilita a estilização em modo escuro para o diálogo e seus controles filhos.

Ciclo de Vida do Diálogo

Entender o ciclo de vida do diálogo é fundamental para inicialização e limpeza corretas:

flowchart TD A["DEFINE DIALOG
(TDialog:New)"] --> B["Add Controls
@ ... GET, SAY, BUTTON, etc."] B --> C["ACTIVATE DIALOG
(TDialog:Activate)"] C --> D["Win32 CreateDialog /
DialogBoxParam"] D --> E["Initiate()
Distribute child controls"] E --> F["ON INIT block
bInit evaluated"] F --> G["Message Loop
User interaction"] G --> H{"End() called
or close button"} H -->|"VALID returns .F."| G H -->|"VALID returns .T."| I["Destroy controls
DestroyWindow"] I --> J["Activate() returns
nResult available"]

Importante: os controles devem ser criados entre DEFINE DIALOG e ACTIVATE DIALOG. O bloco ON INIT dispara depois que a janela do diálogo existe (tem um hWnd válido), tornando-o o lugar certo para inicialização que precisa do handle da janela.

Sistemas de Coordenadas

Os diálogos do FiveWin suportam três sistemas de coordenadas. Escolher o correto é essencial para um layout adequado em diferentes configurações de DPI:

SistemaCláusulaUnidadeQuando Usar
Coordenadas de texto(padrão)Células de caractere: 1 linha ~ 16px, 1 coluna ~ 8px (a 96 DPI)Código legado, diálogos simples. Coordenadas como @ 1, 2 posicionam controles em posições de grade de texto.
PIXELPIXELUnidades de diálogo (DLUs), não pixels reais. Escaladas pela fonte do sistema.Compatibilidade com editores de recurso. Ainda não é 1:1 com pixels da tela.
TRUEPIXELTRUEPIXELPixels reais da tela (mapeamento 1:1)Aplicações modernas. Controle total sobre posicionamento exato. Recomendado para código novo.

Comparação de Coordenadas

// Text coordinates (default) - relative to character grid
DEFINE DIALOG oDlg TITLE "Text Coords" ;
   FROM 2, 5 TO 20, 60

   @ 1, 1 SAY "Name:" OF oDlg
   @ 1, 6 GET oGet VAR cName OF oDlg SIZE 100, 11

ACTIVATE DIALOG oDlg CENTER

// TRUEPIXEL - exact screen pixels, recommended for new code
DEFINE DIALOG oDlg TITLE "True Pixels" ;
   SIZE 500, 400 TRUEPIXEL

   @ 20, 20 SAY "Name:" OF oDlg SIZE 60, 22 TRUEPIXEL
   @ 20, 90 GET oGet VAR cName OF oDlg SIZE 200, 24 TRUEPIXEL

ACTIVATE DIALOG oDlg CENTER

Dica: No Windows 10/11 com telas de alto DPI, as coordenadas de texto e o modo PIXEL podem produzir resultados inesperados. Use TRUEPIXEL para layouts com precisão de pixel. Você também pode defini-lo globalmente com FW_SetTruePixel( .T. ) ou no nível da classe com TDialog():lClsTruePixel := .T..

Exemplo: Diálogo Modal com GETs e Botões

#include "FiveWin.ch"

function EditCustomer( oWnd )

   local oDlg, oFont, oBtnOk, oBtnCancel
   local cName   := Space( 40 )
   local cEmail  := Space( 60 )
   local cPhone  := Space( 20 )
   local cCity   := Space( 30 )
   local nResult

   DEFINE FONT oFont NAME "Segoe UI" SIZE 0, -14

   DEFINE DIALOG oDlg TITLE "Edit Customer" ;
      SIZE 480, 340 TRUEPIXEL ;
      FONT oFont OF oWnd TRANSPARENT

   @ 20,  20 SAY "Name:"  OF oDlg SIZE 80, 22 TRUEPIXEL
   @ 20, 110 GET cName    OF oDlg SIZE 340, 24 TRUEPIXEL

   @ 55,  20 SAY "Email:" OF oDlg SIZE 80, 22 TRUEPIXEL
   @ 55, 110 GET cEmail   OF oDlg SIZE 340, 24 TRUEPIXEL

   @ 90,  20 SAY "Phone:" OF oDlg SIZE 80, 22 TRUEPIXEL
   @ 90, 110 GET cPhone   OF oDlg SIZE 200, 24 TRUEPIXEL

   @ 125, 20 SAY "City:"  OF oDlg SIZE 80, 22 TRUEPIXEL
   @ 125, 110 GET cCity   OF oDlg SIZE 200, 24 TRUEPIXEL

   @ 260, 250 BUTTON oBtnOk PROMPT "&OK" OF oDlg ;
      SIZE 100, 30 TRUEPIXEL ;
      ACTION ( oDlg:End( IDOK ) )

   @ 260, 360 BUTTON oBtnCancel PROMPT "&Cancel" OF oDlg ;
      SIZE 100, 30 TRUEPIXEL ;
      ACTION ( oDlg:End( IDCANCEL ) ) CANCEL

   ACTIVATE DIALOG oDlg CENTER ;
      VALID ( oDlg:nResult != IDOK .or. ;
              !Empty( cName ) .or. ;
              MsgAlert( "Name is required" ) == nil )

   nResult := oDlg:nResult

   oFont:End()

   if nResult == IDOK
      // Save the data...
      MsgInfo( "Saved: " + AllTrim( cName ) )
   endif

return nResult

Exemplo: Diálogo Não-Modal

Um diálogo não-modal não bloqueia o código chamador. O usuário pode interagir tanto com o diálogo quanto com outras janelas. Use NOMODAL ou NOWAIT:

#include "FiveWin.ch"

static oDlgFind   // keep reference alive!

function ShowFindDialog( oWnd )

   local cSearch := Space( 40 )

   if oDlgFind != nil .and. IsWindow( oDlgFind:hWnd )
      oDlgFind:SetFocus()
      return nil
   endif

   DEFINE DIALOG oDlgFind TITLE "Find" ;
      SIZE 400, 140 TRUEPIXEL ;
      OF oWnd STYLE nOR( DS_MODALFRAME, WS_POPUP, WS_CAPTION, WS_SYSMENU )

   @ 20, 20  SAY "Search:" OF oDlgFind SIZE 60, 22 TRUEPIXEL
   @ 20, 90  GET cSearch   OF oDlgFind SIZE 200, 24 TRUEPIXEL

   @ 20, 300 BUTTON "Find" OF oDlgFind SIZE 80, 26 TRUEPIXEL ;
      ACTION DoSearch( cSearch )

   @ 56, 300 BUTTON "Close" OF oDlgFind SIZE 80, 26 TRUEPIXEL ;
      ACTION oDlgFind:End()

   ACTIVATE DIALOG oDlgFind CENTER NOMODAL ;
      ON INIT ( oDlgFind:SetFocus() )

   // Code here runs IMMEDIATELY (dialog is modeless)

return nil

static function DoSearch( cSearch )
   MsgInfo( "Searching for: " + AllTrim( cSearch ) )
return nil

Diálogos Baseados em Recurso

Diálogos podem ser carregados a partir de recursos .RC compilados (embutidos no EXE ou em uma DLL de recursos). Isso é útil para editores visuais ou ao migrar de aplicações C/C++:

#include "FiveWin.ch"

function ShowAbout()

   local oDlg

   DEFINE DIALOG oDlg RESOURCE "ABOUTDLG"

   REDEFINE BUTTON ID 101 OF oDlg ACTION oDlg:End()

   ACTIVATE DIALOG oDlg CENTER

return nil

Use os comandos REDEFINE (em vez de @) para vincular objetos FiveWin a controles já definidos no template de recurso pelos seus IDs numéricos.

Fundos Gradientes e Transparentes

Fundos gradientes requerem TRANSPARENT para que os controles filhos pintem corretamente sobre o gradiente:

DEFINE DIALOG oDlg TITLE "Gradient Dialog" ;
   SIZE 500, 350 TRUEPIXEL TRANSPARENT ;
   GRADIENT { { 0.5, nRGB(30,60,120), nRGB(15,30,60) }, ;
              { 0.5, nRGB(15,30,60),  nRGB(5,10,20) } }

Dicas de Uso

  • Sempre use CENTER a menos que tenha um motivo específico para posicionar o diálogo manualmente. Posições fixas em pixels quebram em diferentes resoluções de tela.
  • Mantenha referências de diálogos não-modais em variáveis static para evitar que o coletor de lixo os destrua.
  • Use ON INIT para código que precisa que a janela do diálogo exista (definir foco, popular XBrowse, chamar API Win32). Não confie no código entre DEFINE e ACTIVATE para isso.
  • VALID dispara a cada tentativa de fechamento, incluindo o botão X da barra de título e pressionar Escape. Retorne .T. para permitir o fechamento, .F. para impedi-lo.
  • Modo escuro — Chame oDlg:SetDarkMode( nClrText, nClrBack ) no bloco ON INIT para um diálogo com tema escuro.
  • Diálogos redimensionáveis — Use a cláusula RESIZABLE. Combine com ancoragem de controles (AdjClient(), AdjTop()) para redimensionar automaticamente os controles filhos.
