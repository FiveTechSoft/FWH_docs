TControl

Classe Base Herda de TWindow source/classes/control.prg

TControl é a classe base abstrata para todos os controles UI no FiveWin. Ela herda de TWindow e adiciona comportamentos específicos de controles: vinculação de dados via bSetGet, notificações de alteração, suporte a arrastar e soltar, ancoragem/encaixe dentro de janelas pai, redimensionamento em modo design e o padrão REDEFINE para diálogos baseados em recurso. Você nunca instancia TControl diretamente; em vez disso, usa suas subclasses concretas como TButton, TGet, TXBrowse, etc.

TControl é o ancestral comum de todo controle visual. Aqui está a árvore de herança mostrando as principais subclasses:

Principais Métodos

Refresh()

Herdado de TWindow. Força o controle a repintar. Para controles vinculados a dados (aqueles com bSetGet), também relê o valor da variável vinculada.

SetFocus()

Dá o foco do teclado a este controle. Internamente envia FM_CHANGEFOCUS e chama a API Win32 SetFocus().

VarGet() / VarPut()

METHOD VarGet() INLINE If( ValType( ::bSetGet ) == "B", Eval( ::bSetGet ), )
METHOD VarPut( uVal ) INLINE If( ValType( ::bSetGet ) == "B", Eval( ::bSetGet, uVal ), )

Lê ou escreve a variável vinculada do controle através do bloco bSetGet. Esta é a forma padrão de obter/definir programaticamente o valor de um controle.

cToChar()

METHOD cToChar( cCtrlClass )

Gera código-fonte que recria este controle. Usado pelo designer visual para serializar diálogos.

Move()

METHOD Move( nTop, nLeft, nWidth, nHeight, lRepaint )

Reposiciona e/ou redimensiona o controle dentro do seu pai.

End()

Destrói a janela Win32 do controle e o remove do array aControls do pai.

Encaixe e Ancoragem

TControl fornece métodos de encaixe que posicionam automaticamente um controle para preencher regiões específicas da janela pai. Estes são essenciais para construir layouts redimensionáveis:

AdjClient()

METHOD AdjClient()

Redimensiona o controle para preencher toda a área cliente do pai, menos qualquer espaço ocupado por controles encaixados (oTop, oBottom, oLeft, oRight) e a barra de mensagem. Este é o método de encaixe mais comumente usado.

Internamente, AdjClient() inspeciona as propriedades oTop, oBar, oBottom, oMsgBar, oLeft e oRight do pai para calcular o retângulo restante, e então chama WndAdjClient() para posicionar o controle.

AdjTop() / AdjBottom()

Encaixa o controle na borda superior ou inferior do pai. O controle se estica pela largura total, e sua altura permanece como definida.

AdjLeft() / AdjRight()

Encaixa o controle na borda esquerda ou direita. O controle se estica pela altura total (entre quaisquer controles encaixados no topo/base), e sua largura permanece como definida.

Encaixe na Prática

#include "FiveWin.ch"

function Main()

   local oWnd, oTree, oBrw, oBottom

   DEFINE WINDOW oWnd TITLE "Docking Layout"

   // Toolbar docks automatically to top via oWnd:oBar
   DEFINE BUTTONBAR oBar OF oWnd SIZE 48, 48 2007
   DEFINE BUTTON OF oBar RESOURCE "OPEN" ACTION nil

   // Status bar docks automatically to bottom via oWnd:oMsgBar
   SET MESSAGE OF oWnd TO "Ready" CENTERED

   // Left panel: tree view
   oTree := TTreeView():New( 0, 0, oWnd, , 220, 400 )
   oWnd:oLeft := oTree
   oTree:AdjLeft()

   // Client area: browse control fills the rest
   oBrw := TXBrowse():New( oWnd )
   oBrw:SetArray( GetCustomerData() )
   oBrw:CreateFromCode()
   oWnd:oClient := oBrw
   oBrw:AdjClient()

   ACTIVATE WINDOW oWnd MAXIMIZED ;
      ON RESIZE ( oTree:AdjLeft(), oBrw:AdjClient() )

return nil

O padrão principal: atribua o controle ao slot de encaixe do pai (oWnd:oLeft, oWnd:oClient), depois chame o método Adj*() correspondente. No handler ON RESIZE, chame-os novamente para que o layout se adapte.

Vinculação de Dados com bSetGet

O bloco de código bSetGet é o coração da vinculação de dados do FiveWin. Ele segue a convenção getter/setter do xBase:

// When creating a GET, FiveWin generates this block automatically:
local cName := Space( 30 )

@ 10, 10 GET oGet VAR cName OF oDlg   // Internally creates:
// oGet:bSetGet := { |u| If( u == nil, cName, cName := u ) }

// Reading the value:
? oGet:VarGet()       // returns cName

// Writing a value:
oGet:VarPut( "John" ) // sets cName := "John"
oGet:Refresh()        // updates the visual display

Para controles vinculados a banco de dados, bSetGet referencia um campo:

@ 10, 10 GET oGet VAR Customers->Name OF oDlg
// bSetGet := { |u| If( u == nil, Customers->Name, Customers->Name := u ) }

Exemplo: Criando um Controle Personalizado

Você pode criar subclasses de TControl para criar controles personalizados com pintura e comportamento especializados:

#include "FiveWin.ch"

// A simple LED indicator control

CLASS TLed FROM TControl

   DATA lOn       INIT .F.     // LED state
   DATA nClrOn    INIT CLR_GREEN
   DATA nClrOff   INIT CLR_RED
   DATA nRadius   INIT 12

   METHOD New( nTop, nLeft, oWnd, nWidth, nHeight, lOn )
   METHOD Paint()
   METHOD Toggle() INLINE ::lOn := !::lOn, ::Refresh()

ENDCLASS

METHOD New( nTop, nLeft, oWnd, nWidth, nHeight, lOn ) CLASS TLed

   DEFAULT nWidth := 30, nHeight := 30, lOn := .F.

   ::nTop    := nTop
   ::nLeft   := nLeft
   ::nBottom := nTop + nHeight
   ::nRight  := nLeft + nWidth
   ::oWnd    := oWnd
   ::lOn     := lOn

   ::nStyle := nOR( WS_CHILD, WS_VISIBLE )

   if oWnd != nil
      ::Create( "TLed" )
      oWnd:AddControl( Self )
   endif

return Self

METHOD Paint() CLASS TLed

   local hDC  := ::BeginPaint()
   local aRect := ::GetCliRect()
   local nCx  := ( aRect[4] - aRect[2] ) / 2
   local nCy  := ( aRect[3] - aRect[1] ) / 2
   local nClr := If( ::lOn, ::nClrOn, ::nClrOff )

   // Fill background
   FillSolidRect( hDC, aRect, GetSysColor( COLOR_BTNFACE ) )

   // Draw the LED circle
   FW_FillCircle( hDC, nCy, nCx, ::nRadius, nClr )

   // Draw border
   FW_Circle( hDC, nCy, nCx, ::nRadius + 1, CLR_BLACK )

   ::EndPaint()

return 0

Uso:

function TestLed()

   local oDlg, oLed1, oLed2

   DEFINE DIALOG oDlg TITLE "LED Demo" SIZE 300, 200 TRUEPIXEL

   oLed1 := TLed():New( 30, 40, oDlg, 36, 36, .T. )   // ON
   oLed2 := TLed():New( 30, 90, oDlg, 36, 36, .F. )   // OFF

   @ 30, 140 SAY "Server"  OF oDlg SIZE 80, 22 TRUEPIXEL
   @ 30, 190 SAY "Offline" OF oDlg SIZE 80, 22 TRUEPIXEL

   @ 100, 40 BUTTON "Toggle" OF oDlg SIZE 100, 30 TRUEPIXEL ;
      ACTION ( oLed1:Toggle(), oLed2:Toggle() )

   ACTIVATE DIALOG oDlg CENTER

return nil

Modo Design

TControl inclui suporte integrado para o modo de design visual (usado pelo editor de diálogos do FiveWin). Quando lDrag é definido como .T.:

  • O controle pode ser movido arrastando com o mouse.
  • Alças de redimensionamento (pontos) aparecem ao redor do controle quando focado (ShowDots() / HideDots()).
  • O método MResize() trata as 8 direções de redimensionamento (NO, N, NE, L, SE, S, SO, O).
  • Os blocos bDragBegin, bDrag, bPreDrag e bPostDrag disparam em diferentes estágios do arraste.
  • Os blocos bPreDelControl e bPostDelControl disparam antes/depois que um controle é excluído no designer.

O Padrão REDEFINE

Para diálogos baseados em recurso, os controles são criados pelo template de recurso do diálogo. Os comandos REDEFINE do FiveWin vinculam objetos FiveWin a esses controles Win32 existentes pelos seus IDs numéricos:

METHOD Redefine( nId, oWnd ) CONSTRUCTOR
DEFINE DIALOG oDlg RESOURCE "MYDIALOG"

   REDEFINE GET oGet VAR cName ID 101 OF oDlg
   REDEFINE BUTTON oBtn ID 102 OF oDlg ACTION SaveData()
   REDEFINE COMBOBOX oCbx VAR cCity ID 103 OF oDlg ;
      ITEMS { "NYC", "London", "Tokyo" }

ACTIVATE DIALOG oDlg CENTER

Dicas de Uso

  • Use lUpdate := .T. para controles que devem ser atualizados ao navegar registros do banco de dados. Chame oWnd:Update() ou oDlg:Update() após um SKIP para atualizar todos os controles marcados com lUpdate.
  • Acesso lChanged — Verifique oGet:lChanged para saber se o usuário modificou um campo antes de salvar.
  • Ordem de tabulação é determinada pela ordem em que os controles são adicionados ao aControls (ou seja, a ordem dos seus comandos @).
  • Controles transparentes — Defina lTransparent := .T. (ou cláusula TRANSPARENT) ao colocar controles sobre fundos gradientes ou bitmap.
  • oJump — Defina oGet1:oJump := oGet3 para pular um campo na sequência de tabulação condicionalmente.
  • Redimensionamento proporcional — Os métodos CalcSize() e SetResizeType() (adicionados em 2024) habilitam layout com coordenadas relativas onde os controles escalam proporcionalmente com o pai.
  • Cores — O método Colors( hDC ) trata mensagens WM_CTLCOLOR. Sobrescreva-o em subclasses para comportamento de cores personalizado.
