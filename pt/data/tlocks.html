TLocks

Fonte: source/classes/tlocks.prg

Classe independente

TLocks fornece um mecanismo de bloqueio de registros para tabelas ODBC. Gerencia uma tabela de bloqueios dentro do banco de dados que rastreia quais registros estão bloqueados e por qual conexão. Isso possibilita um controle de concorrência pessimista básico para fontes de dados ODBC que não fornecem bloqueio nativo em nível de registro.

Principais Membros DATA

DATATipoDescrição
oOdbcObjetoObjeto de conexão TODBC para acesso ao banco de dados
cTableCaractereNome da tabela que está sendo bloqueada
nIdNuméricoIdentificador de conexão ou sessão

Métodos

MétodoDescrição
New( oOdbc, cTable )Cria um novo gerenciador de bloqueios para a conexão ODBC e tabela especificadas
CreateEnviroment()Cria o ambiente de rastreamento de bloqueios (tabela de bloqueios) caso não exista
Lock( nRecNo )Bloqueia um pseudo-registro pelo número do registro
UnLock( nRecNo )Libera um bloqueio em um pseudo-registro
RefreshLock( nRecNo )Atualiza o timestamp do bloqueio para evitar a expiração por tempo limite
SeekRegLock( nRecNo )Verifica se um pseudo-registro está atualmente bloqueado

Exemplo: Bloquear/Desbloquear um Pseudo-Registro

#include "FiveWin.ch"

function Main()

   local oOdbc, oLocks

   oOdbc := TODBC():New( "MyDSN", "user", "pass" )

   if oOdbc:lSuccess
      oLocks := TLocks():New( oOdbc, "CUSTOMERS" )

      // Garante que o ambiente de bloqueio exista
      oLocks:CreateEnviroment()

      // Bloqueia o registro número 101
      if oLocks:Lock( 101 )
         MsgInfo( "Record 101 locked" )

         // Realiza o trabalho com o registro...

         // Libera o bloqueio
         oLocks:UnLock( 101 )
         MsgInfo( "Record 101 unlocked" )
      else
         MsgAlert( "Could not lock record 101" )
      endif
   endif

return nil

Notas

  • TLocks usa uma tabela de bloqueios separada no banco de dados ODBC para rastrear bloqueios em nível de registro. Essa tabela é criada automaticamente por CreateEnviroment() e armazena informações essenciais, incluindo número do registro, ID da sessão e timestamp do bloqueio.
  • O bloqueio pessimista significa que um bloqueio é adquirido antes da edição e mantido até ser explicitamente liberado. Outras sessões que tentarem bloquear o mesmo registro falharão até que o bloqueio seja liberado.
  • Use RefreshLock() periodicamente durante sessões de edição longas para evitar que o bloqueio expire por tempo limite.
  • SeekRegLock() permite verificar se um registro específico está atualmente bloqueado sem tentar adquirir o bloqueio.
  • Sempre libere os bloqueios com UnLock() assim que a edição for concluída para evitar bloquear outros usuários.
