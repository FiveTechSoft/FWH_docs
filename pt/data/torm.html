ORM_Connection + ORM_Table

Fonte: source/classes/fworm.prg

As classes ORM (Mapeamento Objeto-Relacional) fornecem uma camada de abstração multi-backend que funciona com conexões ADO, FWH (MariaDB) e Dolphin (DLP). ORM_Connection gerencia o vínculo com o banco de dados e expõe tabelas como objetos ORM_Table. ORM_Table fornece uma interface fluente de construção de consultas com métodos encadeáveis Where/OrderBy/Select, funções de agregação, navegação por relacionamentos e acesso dinâmico a campos por meio de um manipulador de erros.

Arquitetura

flowchart LR App[Aplicação] --> OC[ORM_Connection] OC --> OT[ORM_Table] OT --> RS[Conjunto de Resultados] OC --> ADO[ADO] OC --> FWH[FWMariaConnection] OC --> DLP[Dolphin]

ORM_Connection

ORM_Connection abstrai conexões de banco de dados em três backends: ADO (para qualquer SGBD compatível com ODBC), FWH (MariaDB nativo via FWMariaConnection) e DLP (biblioteca Dolphin para MariaDB). Aceita tanto parâmetros de conexão quanto um objeto de conexão existente.

ORM_Table

ORM_Table fornece navegação de recordset, construção de consultas e manipulação de dados para uma única tabela do banco de dados. Seu manipulador de erros expõe valores de campos como propriedades dinâmicas e subtabelas como objetos ORM_Table relacionados.

Acesso Dinâmico a Campos

ORM_Table usa um manipulador de erros para fornecer acesso direto a valores de campos no estilo de propriedades. Qualquer mensagem que corresponda ao nome de um campo da tabela é automaticamente traduzida para uma leitura/escrita do campo: 

// Em vez de: oTable:Get( "name" )
? oTable:name        // acesso dinâmico via manipulador de erros
oTable:city := "Madrid"   // define o valor do campo

De forma semelhante, acessar uma propriedade que corresponda ao nome de outra tabela retorna um novo ORM_Table para essa tabela, permitindo navegação fluida entre tabelas relacionadas: 

// Se "orders" for uma tabela, isto retorna o ORM_Table de orders:
oTable:orders:Where( "status = 'active'" )

Exemplo: Encadear Consultas com Relacionamentos

#include "FiveWin.ch"

function Main()

   local oCn, oCustomers

   // Cria conexão com o MariaDB via backend FWH
   oCn := ORM_Connection():New( "FWH", "localhost", "mydb", "root", "password" )
   if oCn == nil
      MsgStop( "Connection failed" )
      return nil
   endif

   // Obtém uma tabela e encadeia filtros de consulta
   oCustomers := oCn:Table( "customers" )

   oCustomers:Where( "city", "Madrid" ):OrderBy( "name" )

   oCustomers:First()
   while !oCustomers:oRs:Eof()
      ? oCustomers:name, oCustomers:email   // acesso dinâmico a campos
      oCustomers:Next()
   end

   // Agregação
   ? "Total customers in Madrid:", oCustomers:Count()
   ? "Max credit:", oCustomers:Max( "credit_limit" )

   // Localiza pela chave primária
   oCustomers:Find( 101 )
   ? oCustomers:name

   // Adiciona um novo registro
   oCustomers:Add( { "name", "email" }, { "New Client", "client@test.com" } )

   oCn:Close()

return nil

Notas

  • Os métodos Where(), OrderBy() e Select() do ORM_Table são encadeáveis -- cada um retorna o objeto Self, permitindo sintaxe fluente como oTable:Where(...):OrderBy(...):First().
  • O método Where() aceita várias convenções de chamada: Where( "field = value" ), Where( "field", value ), Where( "field", "LIKE", "%pattern%" ) ou Where( "field", ">=", 100 ).
  • O método Relate() vincula duas instâncias de ORM_Table de modo que navegar pela tabela pai filtre automaticamente o recordset da tabela filha com base no valor da chave estrangeira.
  • O manipulador de erros dinâmico faz com que o acesso a campos pareça acesso nativo a propriedades: oTable:fieldname (leitura) e oTable:fieldname := value (escrita).
  • Os métodos de agregação (Count, Sum, Max, Min, Avg, Std) respeitam as condições Where() atuais.
