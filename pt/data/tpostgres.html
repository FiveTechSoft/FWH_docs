TPostgreSQL + Funções FWPG_*

Origem: source/function/pgsuport.prg

O FiveWin fornece integração com PostgreSQL através do módulo pgsuport.prg, que conecta a biblioteca Harbour hbpgsql (um wrapper de libpq) com componentes FWH como TXBrowse e TDataRow. Em vez de exigir uma vinculação em tempo de compilação com hbpgsql, o módulo usa um mecanismo de carregamento sob demanda (lazy-loading) para resolver os ponteiros de funções de libpq em tempo de execução, tornando a dependência da biblioteca opcional.

PGLinked() - Resolução de Funções por Carregamento Sob Demanda

A função estática interna PGLinked() é chamada automaticamente na primeira invocação de qualquer função FWPG_. Ela usa HB_FUNCPTR() para localizar os wrappers libpq de nível Harbour fornecidos pela biblioteca hbpgsql. Se PQEXEC for encontrado, os ponteiros são armazenados em cache para as seguintes operações:

Variável de PonteiroFunção hbpgsqlFinalidade
pPQExecPQEXECExecução síncrona de comandos
pPQExecParamsPQEXECPARAMSExecução de comandos parametrizados
pPQMetaDataPQMETADATAObtenção do esquema do conjunto de resultados
pPQGetValuePQGETVALUEObtenção de dados para linha/coluna específica
pPQResultStatusPQRESULTSTATUSVerificação de status (Sucesso / Tuplas / Erro)
pPQlastrecPQLASTRECObtenção da contagem de linhas
pPQFCountPQFCOUNTObtenção da contagem de colunas
pPQcmdTuplesPQCMDTUPLESLinhas afetadas em comandos DML
pPQresultErrorMessagePQRESULTERRORMESSAGETexto detalhado de erro do servidor

Esses ponteiros de função resolvidos são invocados através do mecanismo HB_ExecFromArray() por meio de macros #xtranslate (PQ_Exec, PQ_ExecParams, PQ_MetaData, etc.).

FWPG_Execute() - Execução de Consultas

A função central para toda interação com PostgreSQL é FWPG_Execute:

Assinatura:

FWPG_Execute( pDB, cSql, aParams )  && -> aResult | nAffected | .F.

Parâmetros:

  • pDB - O objeto de conexão com o banco de dados (ou seu handle :pDB).
  • cSql - A instrução SQL a ser executada.
  • aParams - Array opcional de valores de parâmetros para consultas parametrizadas.

Valores de retorno:

  • Para consultas SELECT (PGRES_TUPLES_OK): Retorna um array 2D (linhas x colunas) de valores tipados em Harbour.
  • Para comandos DML (PGRES_COMMAND_OK): Retorna a contagem numérica de linhas afetadas.
  • Em caso de erro: Define o estado de erro no objeto de conexão e retorna .F..

Quando os parâmetros são fornecidos via aParams, cada valor é convertido em uma string segura para SQL usando FW_ValToSQL(u, , "PG") e a consulta é executada via PQ_ExecParams, prevenindo injeção de SQL.

Funções de Metadados e Estrutura

FWPG_MetaStruct()

FWPG_MetaStruct( res )  && -> aStruct

Retorna um array de metadados de colunas para o resultado de uma consulta. Cada elemento é um array indexado pelas seguintes constantes:

ÍndiceConstanteValorDescrição
1_STRU_FIELDNAME1Nome do campo (coluna)
2_STRU_FIELDTYPE2Código de tipo Harbour
3_STRU_FIELDLEN3Comprimento do campo
4_STRU_FIELDDEC4Casas decimais
5_STRU_TABLE5OID da tabela
6_STRU_TABLECOL6Posição ordinal da coluna na tabela
7_STRU_TABLENAME7Nome da tabela de origem
8_STRU_COLNAME8Nome da coluna na tabela de origem
9_STRU_DEFAULT9Expressão de valor padrão
10_STRU_PRI10Indicador de chave primária ("PRI" se for chave)

FWPG_Structure()

FWPG_Structure( oQry )  && -> aStruct

Retorna um array de estrutura aprimorado para um objeto de consulta PostgreSQL. Enriquece o aStruct base com informações de nome de tabela, nome de coluna e chave primária consultando information_schema.columns. Ajusta os tipos de campo para bytea (mapeado para "m"), timestamp (mapeado para "T") e colunas auto-incremento (mapeadas para "+").

FWPG_FieldGet()

FWPG_FieldGet( oQry, nFldNo )  && -> uVal

Um getter de campo especializado que trata a formatação específica do PostgreSQL:

  • Converte prefixos hexadecimais \x (de colunas bytea) em strings binárias.
  • Processa valores timestamp com FW_STR2DT().
  • Aplica preenchimento Unicode via FW_UTF8PADCHAR() quando o modo Unicode está ativo.
  • Aceita nomes de campos (caractere) além de posições numéricas de campos.
  • Recorre à avaliação de blocos de expressão para colunas calculadas.

FWPG_Skipper()

FWPG_Skipper( oQry, nSkip )  && -> nSkipped

Auxiliar de navegação usado pelos codeblocks de TXBrowse para avanço de registros. Calcula o novo deslocamento de registro relativo à posição atual, limitando ao intervalo válido [1, nLastRec]. Retorna o número real de registros avançados.

Integração com TXBrowse

O TXBrowse consome conjuntos de dados PostgreSQL através das interfaces padrão de codeblocks. A função FWPG_Skipper fornece o codeblock bSkip; os codeblocks bGoTop, bGoBottom, bEof, bBof e bBookMark do objeto de consulta são definidos diretamente no objeto de consulta. A edição direta nas células é suportada via FWPG_XBrSaveData( oCol, xValue ), que constrói e executa SQL UPDATE direcionado à chave primária da tabela de origem.

Integração com TDataRow

O TDataRow fornece suporte nativo a PostgreSQL através de dois métodos internos:

  • ReadPQQ: Lê valores de campos e metadados de um objeto de consulta PostgreSQL para o buffer de edição do TDataRow (aData/aOrg).
  • SavePQQ: Gera e executa as instruções SQL UPDATE ou INSERT necessárias via FWPG_Execute para persistir as alterações feitas através da interface da linha de dados.

Exemplo: Conectar, Consultar e Navegar

#include "FiveWin.ch"

function Main()

   local oServer, oQry, oWnd, oBrw, aDbs

   // Abre uma conexão PostgreSQL usando hbpgsql
   oServer := TPostgreSQL():New( "localhost", "mydb", "postgres", "password", 5432 )

   if oServer:lError
      MsgStop( "Connection failed: " + oServer:cError )
      return nil
   endif

   // Lista os bancos de dados disponíveis
   aDbs := FWPG_ListDbs( oServer )
   XBROWSER aDbs TITLE "Databases on Server"

   // Executa uma consulta
   oQry := TPostgreSQLQuery():New( oServer, "SELECT id, name, email, city FROM customers ORDER BY name" )

   if oQry:nLastRec > 0
      DEFINE WINDOW oWnd TITLE "Customers"

      @ 0, 0 XBROWSE oBrw OF oWnd ;
         COLUMNS "id", "name", "email", "city" ;
         COLSIZES 50, 200, 250, 150

      oBrw:nMarqueeStyle   := 3
      oBrw:lCanPaste       := .t.

      // Conecta o XBrowse à consulta PostgreSQL via codeblocks
      oBrw:bSkip       := { |nSkip| FWPG_Skipper( oQry, nSkip ) }
      oBrw:bGoTop      := { || oQry:GoTop() }
      oBrw:bGoBottom   := { || oQry:GoBottom() }
      oBrw:bEof        := { || oQry:RecNo() > oQry:nLastRec }
      oBrw:bBof        := { || oQry:RecNo() == 0 }
      oBrw:bBookMark   := { || oQry:RecNo() }
      oBrw:bStrData    := { |n| FWPG_FieldGet( oQry, n ) }
      oBrw:bKeyNo      := { || oQry:RecNo() }

      oBrw:CreateFromCode()

      ACTIVATE WINDOW oWnd MAXIMIZED
   else
      MsgInfo( "No records found" )
   endif

   oQry:End()
   oServer:End()

return nil

Notas

  • O suporte a PostgreSQL exige que a biblioteca Harbour hbpgsql esteja vinculada à sua aplicação. A função PGLinked() resolve os ponteiros de função da biblioteca em tempo de execução; se hbpgsql não estiver vinculado, todas as funções FWPG_ retornam .F. de forma controlada.
  • Consultas parametrizadas via aParams são fortemente recomendadas para SQL dinâmico a fim de prevenir ataques de injeção. Os valores são escapados usando FW_ValToSQL( u, , "PG" ).
  • A integração com TDataRow (ReadPQQ/SavePQQ) permite a edição registro a registro com rastreamento automático de alterações e geração de SQL.
  • A edição nas células via XBrowse (FWPG_XBrSaveData) exige que a tabela de origem da consulta tenha uma chave primária definida e que FWPG_Structure() tenha sido chamada para preencher os metadados da estrutura.
  • A função FWPG_Structure() consulta automaticamente information_schema.columns para resolver nomes de tabelas e colunas a partir de referências OID, fornecendo metadados completos para consultas JOIN complexas.
