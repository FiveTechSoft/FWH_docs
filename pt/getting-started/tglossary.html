Glossário FWH

Definições de termos específicos do FiveWin, abrangendo a arquitetura do framework, recursos das linguagens Harbour/xHarbour, conceitos de controles de UI, conectividade com bancos de dados, codificações de caracteres e paradigmas de programação utilizados em todo o código-fonte do FWH. Os termos estão organizados em ordem alfabética.

ACCESS / ASSIGN

Acessores de propriedades de classe em Harbour. ACCESS define um método getter somente leitura; ASSIGN define um método setter de escrita. Eles são usados em conjunto com DATA para controlar como as variáveis membro da classe são lidas e escritas externamente, permitindo validação e propriedades calculadas.

ADO (ActiveX Data Objects)

Framework de acesso a dados da Microsoft baseado em COM. A classe TRecordSet do FWH encapsula o ADO para fornecer acesso a bancos de dados cliente-servidor (SQL Server, Access, etc.) com navegação em estilo cursor e execução de SQL.

Cláusula ALIGN

Uma cláusula do FiveWin em definições de controles que especifica o alinhamento do texto ou conteúdo dentro da área do controle. Os valores incluem ALIGN LEFT, ALIGN CENTER e ALIGN RIGHT, comumente usados com controles SAY e BUTTON.

ANSI (Windows-1252)

A code page padrão do Windows (Latin-1, CP-1252). O FWH usa CP_ACP (que mapeia para ANSI) para a conversão de texto de templates de diálogo em dlg2chr.c e ctrl2chr.c. Veja também as entradas OEM e Unicode neste glossário.

Recursos BITMAP / IMAGE

Um tipo de recurso incorporado em executáveis compilados através de arquivos .res / .rc. Os controles FWH os referenciam por nome ou ID inteiro, por exemplo, RESOURCE "MYBITMAP". Os formatos suportados incluem BMP, ICO, PNG e JPEG, dependendo do contexto de renderização.

BOM (Byte Order Mark)

O caractere Unicode U+FEFF, colocado no início de arquivos de texto UTF-16 ou UTF-8 para indicar a codificação. Em contextos FWH, o BOM é relevante ao ler ou escrever arquivos de texto Unicode, particularmente em operações de E/S de arquivos do Harbour e na geração de conteúdo HTML.

Buffer (aOrg / aData)

O mecanismo de edição de registros do FWH em TDataRow e TDataBase. Dois arrays paralelos rastreiam as alterações: aOrg armazena os valores originais carregados do disco, aData mantém as modificações pendentes do usuário. As alterações são gravadas no banco de dados apenas quando o registro é salvo explicitamente.

BWCC (Borland Windows Custom Controls)

Uma biblioteca de UI legada da Borland que fornece molduras cinzeladas, fundos em cinza pontilhado (dithered) e controles personalizados (BorBtn, BorCheck, BorRadio, BorStatic, BorShade). O FWH inclui uma reimplementação clean-room de 64 bits em dll/bwcc64.dll para aplicações de 64 bits.

CLASSDATA

Uma palavra-chave do Harbour que declara membros de dados de nível de classe (estáticos) compartilhados entre todas as instâncias de uma classe. Ao contrário de DATA (que cria cópias por instância), CLASSDATA armazena um único valor para toda a hierarquia de classes.

Codeblock

Um bloco anônimo e compilável de código Harbour delimitado por { |params| ... }. Os codeblocks são a base do sistema de eventos e callbacks do FWH. Propriedades como bAction, bChange, bWhen e bValid são todas referências a codeblocks.

COM (Component Object Model)

A tecnologia de objetos e comunicação entre processos da Microsoft. O FWH usa COM através de TActiveX para incorporar controles ActiveX e TComObject para automação OLE/COM, como a interação com Excel ou ADO.

Objeto de Conexão (Connection Object)

Na integração MariaDB/MySQL do FWH, uma instância de FWMariaConnection (criada por maria_Connect()) que gerencia a conexão TCP, a autenticação e a sessão de consultas com um servidor MariaDB ou MySQL.

Cue Text / Cue Banner

Texto de espaço reservado (placeholder) exibido dentro de um controle TGet quando este está vazio e não tem o foco. Definido via TGet:cCueText. Implementado usando a mensagem EM_SETCUEBANNER do Windows (0x1501).

DATA (variável de instância de classe)

Uma palavra-chave do Harbour que declara variáveis por instância em uma definição de classe. Cada objeto mantém sua própria cópia. Exemplo: DATA nValue em uma definição de classe cria um membro nValue para cada instância.

Modo de Design (Design Mode)

Um estado de tempo de execução (TWindow:lDesign := .T.) onde os controles podem ser movidos e redimensionados interativamente. Usado pela IDE Visual (visualfw.exe) para o layout de formulários por arrastar e soltar durante o desenvolvimento.

DSN (Data Source Name)

Uma entrada de configuração ODBC do Windows que especifica qual driver de banco de dados, endereço de servidor e autenticação usar para uma conexão. A classe TODBC do FWH pode conectar usando um DSN predefinido ou uma string de conexão sem DSN (DSN-less).

Manipulador de Erros (ON ERROR)

O mecanismo de recuperação de erros do Harbour, acionado por ON ERROR ou através da função ErrorBlock(). O manipulador de erros padrão do FWH (source/function/errsysw.prg) fornece um diálogo visual com rastreamento de pilha (stack trace) e inspeção de variáveis para depuração.

FiveWin.ch

O arquivo de cabeçalho principal das aplicações FWH. Define todas as traduções de pré-processador #xcommand e #xtranslate que habilitam a sintaxe de linguagem natural (DEFINE WINDOW, @ ... SAY, @ ... GET, etc.). Toda aplicação FWH inclui este arquivo.

Convenção de prefixo FW_

O FWH prefixa suas funções e constantes globais com FW_ (por exemplo, FW_ReadImage(), FW_JsonDecode()) para evitar colisões de nomes com o código do usuário e as funções de tempo de execução do Harbour/xHarbour.

Abreviação FWH

"FiveWin for Harbour" (também "FiveWin for xHarbour"). Um framework de GUI que encapsula a API do Windows em um ambiente de programação orientada a objetos Clipper/xBase, fornecendo classes para janelas, diálogos, controles, impressão, acesso a bancos de dados e integração com IA.

GDI / GDI+ (Graphics Device Interface)

Subsistemas gráficos do Windows. O GDI cuida do desenho 2D básico (linhas, formas, texto). O GDI+ (acessado via gdipfwh.cpp) adiciona mesclagem alfa (alpha blending), antisserrilhamento (anti-aliasing), suporte a JPEG/PNG e preenchimentos com gradiente. O FWH usa GDI+ para renderização moderna em TBtnBmp, TImage e na pré-visualização de impressão.

Harbour vs xHarbour

Dois compiladores Clipper/xBase de código aberto. O Harbour é a implementação moderna e ativamente mantida, usada pela maioria dos usuários do FWH. O xHarbour é um fork mais antigo, suportado para compatibilidade com código legado; ele requer um cabeçalho de compatibilidade (fwhxhb.h) para builds de 64 bits.

hbcompat.ch

Um cabeçalho de compatibilidade do Harbour que mapeia funções e comandos específicos do xHarbour para os equivalentes do Harbour. Ele não é incluído automaticamente por fivewin.ch de forma deliberada, porque sua tradução de IN para $ quebraria código que usa padrões como BOEK->IN.

Estilo Infield

Um modo de exibição do TGet (lInfield := .T.) onde o título ou rótulo do campo é renderizado dentro da área do controle de edição, sobreposto ou ao lado do texto do valor. Usado para layouts de UI compactos e sem rótulos.

Estilo Marquee (XBrowse)

Uma propriedade do TXBrowse (nMarqueeStyle) que controla como a seleção da linha atual é destacada visualmente. Valores comuns: MARQSTYLE_HIGHLROW (linha única sólida), MARQSTYLE_HIGHLROWMS (seleção de múltiplas linhas).

MDI (Multiple Document Interface)

Um paradigma de janelas onde as janelas de documento filhas ficam confinadas dentro de uma única moldura (frame) MDI pai. O FWH suporta MDI através das classes TMDIFrame e TChild, com organização automática de janelas e mesclagem de menus.

METHOD

Uma palavra-chave do Harbour que define uma função pertencente a uma classe. Os métodos recebem o parâmetro implícito Self que referencia a instância do objeto. Os métodos FWH são definidos como METHOD Name() dentro da definição da classe e implementados posteriormente.

ODBC (Open Database Connectivity)

Uma API C padronizada para acesso a bancos de dados. O FWH fornece TODBC para conexões baseadas em ODBC usando um DSN nomeado ou uma string de conexão sem DSN (DSN-less).

OEM (Code Page 437/850)

A codificação de caracteres usada pelo console do MS-DOS e pela fonte OEM do Windows. No código de suporte Unicode do FWH (fwunicode.c), as code pages OEM (valores abaixo de 1250) são ignoradas quando bAnsiOnly é TRUE, evitando que texto CP437/CP850 seja convertido incorretamente.

OLEDB

O sucessor do ODBC da Microsoft, baseado em COM, para acesso universal a dados. O TRecordSet do FWH pode usar provedores OLEDB para conectividade com bancos de dados, oferecendo uma alternativa às conexões ODBC baseadas em DSN.

OOP vs xBase tradicional

O FiveWin traz a programação orientada a objetos completa (classes, herança, encapsulamento, polimorfismo) para o mundo Clipper/xBase. O xBase tradicional usa funções procedurais e áreas de trabalho (USE, SELECT), enquanto o código FWH define e instancia objetos com métodos e dados.

Cláusula PIXEL

Uma cláusula em definições de controles (@ nRow, nCol ... PIXEL) que interpreta as coordenadas em pixels em vez da grade baseada em caracteres padrão. Essencial para o posicionamento preciso, especialmente com DEFINE WINDOW (em oposição a DEFINE DIALOG) em layouts puros em PRG.

#pragma /b+ (depurador)

Uma diretiva do compilador Harbour que habilita o depurador embarcado. Colocar #pragma /b+ no topo de um arquivo-fonte ativa o motor HB_DBG, permitindo pontos de interrupção (breakpoints), inspeção de variáveis e depuração passo a passo.

#pragma BEGINDUMP

Uma diretiva do Harbour que faz o compilador transicionar da sintaxe Harbour para a sintaxe C dentro do mesmo arquivo-fonte. Usada em arquivos .prg para incorporar código C inline que é compilado pelo compilador C, permitindo chamadas de baixo nível à API do Windows sem um arquivo .c separado.

RDD (Replaceable Database Driver)

Uma camada de abstração no Harbour/xHarbour que permite que o mesmo código funcione com diferentes formatos de arquivos de banco de dados. RDDs comuns: DBFNTX (compatível com Clipper), DBFCDX (índices FoxPro), DBFDBT (campos memo). Todas as classes de banco de dados do FWH ficam sobre a camada RDD.

REDEFINE

Uma sintaxe de comando do FiveWin para vincular uma instância de classe a um controle existente em um recurso de diálogo (arquivo .rc). Exemplo: REDEFINE GET oVar ID 101 OF oDlg conecta um objeto TGet a um controle de diálogo pelo seu ID de recurso.

RowSet

Uma representação em memória do resultado de uma consulta SQL, especificamente na integração MariaDB/MySQL do FWH. Criada por mysql_RowSet(), fornece navegação em estilo cursor, busca preguiçosa (lazy fetching) através de uma estrutura de lista encadeada e suporta bOnMove para eventos de mudança de linha.

SDI (Single Document Interface)

O paradigma de janelas moderno onde cada documento ou visão tem sua própria janela independente de nível superior, em oposição ao MDI, onde as janelas filhas ficam confinadas dentro de uma moldura pai. A maioria das aplicações FWH contemporâneas usa SDI.

SeekBar (busca incremental)

Um elemento de UI integrado no TXBrowse (TXBrowse:oSeek) que exibe um campo de edição flutuante. Os usuários digitam os critérios de filtro de forma incremental, e o browse rola automaticamente até as linhas correspondentes à medida que digitam. Habilitado via codeblock bSeek.

Nomenclatura de classes com prefixo T

A convenção do FWH de prefixar todos os nomes de classes com T (por exemplo, TWindow, TButton, TXBrowse, TGet). Isso distingue os tipos de classe dos nomes de função tradicionais do xBase e fornece um padrão de nomenclatura consistente e reconhecível.

Controles com Tema (Themed Controls)

O suporte do FWH aos estilos visuais do Windows, controlado por membros DATA como TBtnBmp:lThemed, TBtnBmp:l2007, TBtnBmp:l2010, TBtnBmp:l2013 e TBtnBmp:l2015. Os controles com tema adaptam automaticamente sua aparência ao tema atual do Windows do usuário.

Cláusula TRANSPARENT

Uma cláusula que define o estilo estendido WS_EX_TRANSPARENT em um controle, tornando-o transparente a cliques do mouse e permitindo que os controles da janela pai apareçam através do fundo. Usada em designs de UI em camadas.

Unicode (UTF-8 / UTF-16)

Padrões universais de codificação de caracteres. O Windows usa UTF-16 internamente; o FWH converte entre strings Harbour (tipicamente ANSI ou OEM) e UTF-16 para chamadas à API do Windows. O UTF-8 é usado para comunicação JSON, payloads de APIs REST (classes de IA) e a documentação HTML.

WYSIWYG

"What You See Is What You Get" (O Que Você Vê É O Que Você Obtém). Os sistemas de relatórios e pré-visualização de impressão do FWH (TReport, TPreview) fornecem exibição WYSIWYG, mostrando na tela exatamente como a saída aparecerá no papel, incluindo fontes, margens e posicionamento de gráficos.

#xcommand / #xtranslate

Diretivas do pré-processador Harbour que definem traduções de texto baseadas em padrões. O FiveWin.ch do FWH as utiliza extensivamente para criar a linguagem específica de domínio (DSL) em linguagem natural para definir janelas, diálogos, controles e menus com sintaxe intuitiva.
