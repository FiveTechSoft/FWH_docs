Novidades no FWH 26.09

Destaques do FiveWin for Harbour/xHarbour versão 26.09 (setembro 2026). Veja também whatsnew.txt na raiz do FWH para o log dia a dia.

Barra de título escura automática + FW_SetCaptionColors

Com FW_SetDarkMode( .T. ) agora toda WINDOW e todo DIALOG recebe automaticamente uma barra de título escura, com as cores do modo escuro: sem código adicional (source/classes/dialog.prg, source/classes/window.prg).

A nova função FW_SetCaptionColors() personaliza a barra de título (source/classes/dialog.prg): 

// Cores personalizadas de texto/fundo do título (também no modo claro)
FW_SetCaptionColors( nClrText, nClrBack )

// Voltar às cores automáticas
FW_SetCaptionColors( nil, nil )

// Consultar as cores personalizadas: { nClrText, nClrBack } ou nil
aClrs := FW_SetCaptionColors()

O tema do título usa o DWM (DwmSetWindowAttribute, com dwmapi.dll carregada em tempo de execução, sem nova dependência). Requer Windows 11; em Windows mais antigos não faz nada. Veja cores do título em TDialog e modo escuro em TWindow.

TBitmap ASPECT: escala proporcional

Nova opção ASPECT para @ ... BITMAP e REDEFINE BITMAP, e nova propriedade lAspectRatio (source/classes/bitmap.prg): o bitmap é desenhado em escala proporcional e centrado dentro do controle, sem distorção, deixando a área restante na cor de fundo do controle. Tem precedência sobre ADJUST; dimensões zero não desenham nada. Também é possível atribuir oBmp:lAspectRatio := .T. e chamar oBmp:Refresh(). Veja TBitmap.

TScrollPanel: salto de foco após rolagem horizontal corrigido

Após uma rolagem horizontal, o handler bGotFocus que SetRange() atribui aos controles com tab-stop ainda chamava ControlIntoView(), arrastando o painel de volta. Agora também é ignorado após rolagem horizontal (lHScrolled), como já ocorria com a vertical (source/classes/scrlpanl.prg). Não requer mudanças no código do usuário. Veja TScrollPanel.

TWebView2: de 10 para mais de 40 nativos

TWebView2 (source/classes/twebview2.prg, source/internal/twebview/cwebview.cpp, source/winapi/webview2.c, include/WebView2.ch) cresce de 10 para mais de 40 nativos. Novos métodos: NavigateEx( cUrl, cMethod, cHeaders, cBody ) (POST nativo), GoBack/GoForward/Reload/Stop, CanGoBack/CanGoForward, GetSource, GetDocumentTitle, GetBrowserVersion, Print, SetZoomFactor/GetZoomFactor, SetDefaultScriptDialogs, SetDefaultContextMenus/SetContextMenuExclude, CapturePreview (PNG assíncrono) / PrintToPdf (PDF assíncrono), Add/RemoveWebResourceRequestedFilter, ClearSession/ClearBrowsingData, EnableConsole, CloseWebView, Reinitialize, SetSizeRatio e diagnósticos Diag/Reregister. Novos eventos bOn*: NavigationStarting (cancelável), SourceChanged, HistoryChanged, DocumentTitleChanged, NewWindow, Permission (permitir/negar), FullScreen, ProcessFailed, FrameNavStarting/Completed e Console. A pasta de dados do usuário padrão é %LOCALAPPDATA%\FWH_webview2_UserData. Totalmente compatível com versões anteriores; novo exemplo em samples/webview2/.

TProlog: um motor Prolog dentro do FiveWin

Nova classe TProlog (source/classes/tprolog.prg): um motor Prolog embutido no Harbour/FiveWin, com fatos e regras, backtracking, unificação (occurs-check opcional), corte (!), negação (not/\+), findall/3, aritmética (is/2, =:=/2, ...) e builtins nativos rápidos de listas (member, append, permutation, numlist, alldiff, sort, between, ...). Query() retorna um array de hashes { VarName => "term" }. O núcleo em C (source/function/prolog.c, trail + heap de termos próprio) resolve o problema das 8 rainhas (as 92 soluções) cerca de 230 vezes mais rápido que o interpretador Harbour anterior. Exemplos: samples/ai/tprolog.prg, samples/ai/tprologbench.prg e samples/ai/plpad.prg, um editor Prolog com realce de sintaxe, grafo 3D da base de conhecimento e botão de explicação com TOpenCode.

MAPI: preenchimento de endereço SMTP com tipo

MAPISendMail() / DEFINE MAIL com TO cEmail de um único parâmetro: o fallback da 26.07 copiava o nome simples para lpszAddress (sem prefixo de tipo), o que fazia o Outlook criar um destinatário ocasional e o Exchange Online nunca entregar o anexo. mapi.c agora preenche a forma com tipo SMTP:user@domain, apenas quando o nome contém @. A nova função opcional SetMapiAddrFill( .F. ) restaura o comportamento anterior à 26.07 de deixar lpszAddress vazio para o cliente resolver. A forma dupla TO cName, cAddress não muda.

IsWindows10() corrigido no Windows Server

IsWindows10() agora lê o número de build, da mesma forma que IsWindows11(), em vez do nome do produto no registro, que nas edições servidor diz "Windows Server": retornava .F. por engano no Windows Server 2016/2019/2022.

Correções de linkedição no xHarbour 64 e MinGW

xHarbour + BCC 64 (xb64): faltava em Fivexh64.a tudo o que está em source/function/harbour.prg (ASend(), OSend(), OClone(), ParamCount(), OleInvoke() e mais), então os aplicativos xHarbour 64 bits não linkedidavam, com erros como Unresolved external 'HB_FUN_ASEND'; também faltava TVistaMenu. Já estão incluídos, e mfwh_new.bat xb64 agora lista qualquer fonte que não compile e para, em vez de deixá-la fora da biblioteca sem avisar.

As bibliotecas FiveWin também voltam a compilar com MinGW 32 (source/internal/remoteview/capture.c define SM_CXPADDEDBORDER quando os headers do SDK não o têm), e os aplicativos FWMariaDB linkedidam com xHarbour + MSVC 32 (source/internal/fwmaria.prg usa seu próprio nxs_crypt e Adler-32 ali).

TOpenCode volta a falar com o OpenCode Zen

TOpenCode (source/classes/topencode.prg) funciona novamente com o serviço Zen: o cabeçalho x-opencode-session: public é enviado (as requisições antigas falhavam com MissingSessionID), o catálogo de modelos gratuitos está atualizado (ling-3.0-flash-fin-free padrão) e o status HTTP usa o valor de retorno como reserva. Veja TOpenCode.

Novos exemplos

  • samples/menus/vistamenu.prg — um exemplo mínimo de TVistaMenu (menu lateral com três itens); esta classe não tinha nenhum exemplo para compilar.
  • samples/ai/plpad.prg — editor Prolog: cole ou abra um arquivo .pl, consulte com TProlog e execute consultas, com um grafo TWebView2/three.js de node()/edge().

PrinterKeepSetup

Novo: PrinterKeepSetup( lOn ) mantém a impressora escolhida em PrinterSetup() ou PageSetup() para os próximos trabalhos de impressão (desativado por padrão, usa em silêncio a padrão se a mantida deixou de existir, PrinterResetSetup() a esquece). Ver TPrinter.
