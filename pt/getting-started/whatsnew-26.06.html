Novidades no FWH 26.06

Esta página resume as mudanças e adições no FiveWin para Harbour/xHarbour versão 26.06 (Junho 2026), em relação à versão anterior 26.05 (Maio 2026).

Novo exemplo: XBrowse com Tree e pesquisa

Novo exemplo samples\xbrowses\xbrwtre.prg que demonstra XBrowse com modo Tree e pesquisa incremental. Características:

  • Alterna entre XBrowse normal e visualização Tree (agrupado por um campo selecionado).
  • Combo para selecionar o campo de pesquisa/agrupamento (First, Last, Street, City, State).
  • A pesquisa funciona nos modos normal e tree através de XbrTreeSeek().
  • Nós do tree expansíveis/colapsáveis com agrupamento visual.

Novo exemplo: Diálogo com recursos e zoom proporcional

Novo exemplo samples\dialog\resdlg.prg que demonstra diálogos baseados em recursos com zoom proporcional. Quando o diálogo é redimensionado, todos os controles (rótulos, campos de edição, botões) são redimensionados proporcionalmente, incluindo posições, larguras, alturas e tamanhos de fonte.

  • Escalonamento DPI — o tamanho inicial do diálogo adapta-se ao DPI do sistema usando GetDeviceCaps(LOGPIXELSX).
  • Zoom uniforme — os fatores de escala nSX = nW / 300 e nSY = nH / 180 são aplicados a todas as propriedades dos controles.
  • Escalonamento de fonte — o tamanho da fonte é recriado com o tamanho escalonado via SetFont() a cada redimensionamento.
  • Recurso RC — o template do diálogo é definido em resdlg.rc com diretivas #define para os IDs dos controles.

TSmartButton — Correcções

O controle TSmartButton (source\classes\smartbtn.prg) tinha dois erros no tratamento da ação, ambos corrigidos:

  • Botões ativos não executavam seu ACTION. Os métodos LButtonDown, LButtonUp e KeyChar tinham a condição de desabilitado invertida (IF ! ::lDisabled RETURN 0), pulando o caminho de captura/clique em botões ativos. Corrigido para IF ::lDisabled.
  • Botões desabilitados ainda executavam seu ACTION. New() definia por padrão bWhen := {||.t.}. Como o AEvalWhen() do proprietário reativa qualquer controle com bWhen não nulo a cada evento (chamando ::Enable(), que limpa ::lDisabled), um botão desabilitado via :lDisabled / :Disable() era reativado silenciosamente. O valor padrão de bWhen foi removido para que o estado desabilitado persista.
  • Removido um MsgInfo() de depuração esquecido em SetImage().
  • O exemplo samples\ui\testsmart.prg mostra as quatro formas (retangular, arredondada, pílula, círculo) nos estados normal / hover / pressionado / desabilitado.

Correção de compilação relacionada: faltavam em vitem.prg os #define BDR_RAISEDOUTER (0x0001) e BDR_SUNKENOUTER (0x0002); as macros EDGE_* referenciavam esses símbolos não definidos, gerando avisos W0001 de referência ambígua que abortavam a compilação de FiveH.lib com -es1.

Classe Agent — Melhorias Importantes

A classe Agent (source\classes\agent.prg) recebeu melhorias substanciais desde sua introdução no 26.05:

  • Streaming SSE — Step() agora envia "stream": true com stream_options.include_usage para métricas de tokens em tempo real. A resposta é analisada de fragmentos SSE via AG_SseParse().
  • Tool_Shell() — completamente implementado: executa via cmd.exe (Windows) ou /bin/sh (Unix), captura stdout+stderr, trunca em 30 KB, informa código de saída. Anteriormente um stub.
  • Tool_Python() — completamente implementado: busca interpretador python3/python/py, escreve arquivo .py temporário, executa, captura saída. Anteriormente delegava ao stub Tool_Shell().
  • Tool_WebSearch() — implementado: curl ao DuckDuckGo HTML, extrai trechos de resultados via AG_ExtractDdgResults(). Anteriormente um stub.
  • Tool_WebFetch() — implementado: curl a URL, remove tags HTML via AG_StripHtml(), trunca em 40 KB. Anteriormente um stub.
  • ExecTool() tratamento de erros — BEGIN SEQUENCE / RECOVER envolve cada chamada de ferramenta para que uma falha não trave o loop do agente.
  • Run() interrupt/inject — codeblock bInterrupt verificado antes de cada passo e de cada tool call; codeblock bInject injeta mensagens de usuário no meio da execução. Permite cancelamento externo e interjeições.
  • BuildToolsArray() — agora inclui descrição e esquema de parâmetros para cada ferramenta integrada (antes só tinha nome).
  • ToggleSkill() — bug corrigido: filtro ASort não removia itens; agora usa hb_ADel() com .T. para remoção in-place.
  • ExecUserTool() — corrigido: construção de sys.argv agora tokeniza corretamente argumentos separados por espaços em uma lista Python.
  • SendToLLM() — sincronizado com Step(): streaming + parse SSE.

Novas funções helper: AG_SseParse(), AG_UrlEncode(), AG_ExtractDdgResults(), AG_StripHtml(), AG_ToolDesc(), AG_ToolParams().

AgenticAI — Aplicação GUI de Desktop

Uma aplicação desktop completa para o motor agente ccharbour, portada da versão Agents Web para um app FiveWin nativo usando um WebView2 Edge incorporado (TWebView2):

  • Raciocínio ao vivo ("thinking mode") — eventos reasoning_delta fluem em uma caixa de vidro roxa enquanto o modelo pensa (ex. /model deepseek-reasoner).
  • Chip de status — cabeçalho mostra tempo decorrido, fluxo de tokens da sessão (upload/download) e tok/s, atualizado 5 vezes por segundo.
  • Markdown ao vivo — balões do assistente renderizam markdown ENQUANTO transmitem (re-parse throttled via marked.js), não apenas no fim do turno.
  • /goal /plan /run — sistema de plano de ação. /plan pede ao modelo 3-6 passos JSON e os mostra como cartão "Plano de Ação" editável (ciclar estado de cada passo, editar títulos, excluir/adicionar passos); /run executa o plano um passo por turno do agente.
  • /btw — interjeição "o que você está fazendo?" enquanto o agente trabalha; entregue entre ações sem interromper a execução. Usa o novo hook CC_AgentRun hOpts["inject"].
  • /cost — cartão de métricas da sessão com preços DeepSeek cientes de cache (prompt_cache_hit_tokens com 98% de desconto).
  • /compact + monitor de janela de contexto — passado 85% da janela de 128k aparece cartão "Janela de Contexto Crítica" oferecendo Comprimir / Limpar; /compact dobra o meio do histórico em uma mensagem de resumo.
  • /init + AGENTS.md — o agente escreve o arquivo de regras do projeto; AGENTS.md (alternativa CLAUDE.md) é injetado no system prompt a cada turno.
  • Novos cartões — execução-abortada (Stop), limite de passos atingido com botão "Continuar", /help como grade de botões clicáveis.
  • Permitir/rejeitar — cartão por ação para ferramentas mutantes (shell/write/edit) quando "Auto-approve" está desligado; o turno do agente bloqueia até que você decida.
  • ask_user — cartão de múltipla escolha conectado ao webview.
  • Visualizador Diff — barra "Código gerado" com toggle "Ver Alterações (Diff)" mostrando linhas vermelhas/verdes.
  • UX — histórico de prompts Cima/Baixo, Esc para parar, Ctrl+K para limpar, prompt permanece habilitado enquanto executa para usar /btw. Comando /key integrado para definir a chave LLM em tempo de execução.

Transporte é libcurl em processo (hbcurl), o mesmo caminho que TOpenAI:SendStream, conectado ao ccharbour via hOpts["transport"]. Exemplo: samples\AgenticAI\ (build multi-módulo com agenticai.hbp + build.bat).

Motor ccharbour e Console

  • CC_AgentRun — aceita um codeblock opcional hOpts["inject"], consultado no início de cada iteração; quando retorna uma string não vazia ela é anexada como mensagem de usuário antes da próxima solicitação ao modelo (interjeição no meio da execução que não interrompe o loop).
  • Cartões de console (cc.exe) — as respostas agora são renderizadas como "cartões" estilo GUI: linhas com fundo colorido como os balões do AgenticAI. Respostas em slate, raciocínio em caixa roxa, erros em vermelho escuro, /cost em cartão esmeralda com preços DeepSeek cientes de cache. A saída simples não muda quando a cor está desligada.

Classe Transformer — Multi-Head, GELU, LR Scheduler e Padding

  • LRScheduler — nova classe implementando warmup + decaimento inverso de raiz quadrada do paper Transformer: lr = d_model^(-0.5) * min(step^(-0.5), step*warmup^(-1.5)). Metodos: New(d_model, warmup_steps, base_lr), GetLR(step), Update(optimizer, step).
  • MultiHeadAttention — valida d_model % n_heads == 0 na construção com ALERT() se nao for divisivel. Usa divisao inteira exata para head_dim ao inves de Int() para evitar truncamento.
  • FeedForward — ativacao GELU substitui ReLU (aproximacao tanh: 0.5*x*(1+tanh(√(2/π)*(x+0.044715*x³)))). A derivada do GELU usa formula CDF+PDF para fluxo de gradientes correto. ff_dim agora configuravel (default 4*d_model). Valida d_model > 0 e ff_dim > 0.
  • EmbeddingLookup — o token PAD (indice 0) agora retorna um vetor de zeros ao inves de falhar com "Bound error: array access" em aVocab[0].
  • Backward — ignora a acumulacao de gradientes para tokens PAD (indice 0 em src_indices e pos_indices). Corrige o treinamento com sequencias de comprimento variavel preenchidas ate max_seq_len.
  • transxbrowse.prg agora usa nHeads=2 e LRScheduler para demonstrar attention multi-head com agendamento de warmup.
  • transxbrowse.prg agora usa nHeads=2 para demonstrar attention multi-head.

    • Remote View — Multi-Cliente e Login

    • Multi-cliente — cada visualizador obtém seu próprio servidor em sua própria porta, completamente isolado, para que vários navegadores possam ver/controlar a mesma janela ao mesmo tempo. Estado por thread via TLS (sockets, frame diff, viewport, cursor) — sem globais compartilhadas.
      • Cliente único, SEM multithread (sem -mt): RemoteViewStart()/Stop() acionado por um WM_TIMER oculto na thread GUI.
      • Multi cliente, multithread (-mt): lança uma thread Harbour por porta com hb_threadStart, cada uma chamando o bloqueante RemoteViewServe(); parar todas com RemoteViewStopAll().

    • Título de página personalizado — RemoteViewStart([hWnd], [nPort], [cTitle]) agora aceita um parâmetro de título opcional. Padrão "FWH Remote View".
    • Exemplo de login — samples\RemoteView\testrvauth.prg mostra como autenticar um usuário remoto antes que a UI do app seja aberta. O login é um diálogo FiveWin normal owned pela janela servida, composto pelo RemoteView por cima. Detalhe chave: NÃO lance UI modal dentro de ON INIT (a janela ainda não foi pintada).     • Correção zero-init — o CRT do VC98/xHarbour não zera variáveis __declspec(thread); o estado de captura por thread agora é reiniciado explicitamente em CaptureInit e o rect do monitor recorre à tela principal em caso de falha.

    Sistema de Build

    Limpeza de Warnings do Compilador

    Todos os warnings emitidos pelos builds de biblioteca GCC32, GCC64, MSVC32 e MSVC64 (~170 locais) foram eliminados preservando o comportamento em todos os toolchains suportados (BCC32/64, MSVC32/64, GCC32/64, Harbour e xHarbour). Cobre:

    • -Wcast-function-type — casts GetProcAddress/FARPROC agora usam o intermediário portátil ( void (*)( void ) ).
    • -Wdangling-else, -Wimplicit-fallthrough, -Wsign-compare, -Wunused-function (callbacks vtable COM IDataObject apenas 32-bit protegidos com #ifndef _WIN64), -Wold-style-declaration, -Wmisleading-indentation.
    • Macros redefinidos e MSVC C4996.

    Dois bugs reais encontrados: um buffer overflow em BlankQuotes() (vstrfun1.prg) quando seu segundo argumento excede 3 caracteres, e uma sobre-leitura de 3 bytes do bloco de controle gráfico GIF em fwgif.c. As nove variantes de biblioteca agora compilam sem warnings.

    xHarbour Commercial Restaurado

    O target xHB Commercial (xhbc) — abandonado desde 2016 — agora compila, vincula e executa novamente com o toolchain VC98:

    • A biblioteca C (Fivehcm.lib) passou de stub vazio ao motor C completo do FiveWin; a biblioteca PRG (Fivehmx.lib) foi reconstruída completamente.
    • source/internal/xhbcompat.c + include/xhbcompat.h: API C de arrays "vector" do Harbour-3.x implementada sobre o que o xHarbour fornece.
    • Correções de compilação VC98/xHarbour por arquivo (themes, msgs, files, elevation, winsock, calendar, scintilc, richedit, brushes, ribbon, odbc32x, ...), cada uma atrás de um guard __XHARBOUR__.
    • Todos os shims protegidos por __XHARBOUR__ — builds Harbour compilam byte-por-byte como antes.

    Scripts de build: makes/build_fivehcm.ps1 + makes/build_fivehmx.ps1.

    Projetos de Teste makes/

    Cada pasta makes/<compilador>/ agora compila, vincula e executa um app FiveWin mínimo para sua combinação Harbour/xHarbour + compilador C (11 variantes confirmadas). Duas variantes faltantes foram adicionadas (xhb_bcc64, xhb_msvc32). Cada go.bat respeita FW_NORUN=1 e usa o toolchain VS 18.

    Correções Notáveis

    TGet — Caracteres ANSI (Turco, CP1250-1258)

    A entrada de teclado de caracteres ANSI com ponto de código Unicode acima de 255 (Turco ş-cedilha, ğ-breve, İ com ponto; Polonês, Tcheco, Báltico, Cirílico e Grego) mostrava "?" em aplicações não Unicode (FW_SetUnicode(.F.)) usando codepages de byte único CP1250–CP1258.

    Regressão introduzida quando is2byteansi() começou a tratar todas as sequências de 2 bytes como pares ANSI nesses codepages: WideKey2Asc() construía UTF-8 genuíno a partir do código largo WM_CHAR mas a heurística isutf8() do fw_Utf8ToStr() se recusava a convertê-lo, rejeitando a tecla.

    WideKey2Asc() agora converte com codepages explícitos via FW_CdpTranslate(cUtf8, 65001, -1), contornando a heurística. O comportamento de exibição do is2byteansi() não muda.

    Novos exemplos: samples\test\trwincdp.prg (verificação da cadeia de conversão) e samples\test\trwinget.prg (envia códigos WM_CHAR ş ğ İ para um GET e verifica se o buffer recebe bytes CP1254 FE F0 DD).

    TGraph ADD SERIE / SET Y LABELS

    Ambas as regras #xcommand expandiam para um oGraph: hard-coded em vez do matchmarker <oGraph>, então ADD SERIE TO oMyGraph / SET Y LABELS OF oMyGraph chamavam uma variável oGraph inexistente a menos que o objeto se chamasse casualmente oGraph. Agora expandem para <oGraph>:AddSerie() / <oGraph>:SetYVals().

    Novas Funcionalidades

    TRichEdit5 e TRichEdit — SetTextColor()

    SetTextColor(nColor) aplica cor de texto à seleção atual (SCF_WORD | SCF_SELECTION) usando apenas a máscara CFM_COLOR, preservando toda a outra formatação (negrito, itálico, sublinhado, fonte, tamanho). Se nenhum texto estiver selecionado, a cor é aplicada à palavra sob o cursor. Funciona tanto no TRichEdit5 (RichEdit 5.0) quanto no TRichEdit (RichEdit 2.0 via riched20.dll).

    Exemplos: samples\test\testchclr.prg (Azul/Vermelho/Preto + Negrito/Itálico), samples\test\testreclr.prg (mesmo para RichEdit 2.0).

    TRichEdit5 — Modo Escuro

    Novo METHOD SetDarkMode(nClrText, nClrBack), aplicado em cascata automaticamente por TDialog:SetDarkMode / FW_SetDarkMode como os outros controles. Usa a mesma paleta escura do TMultiGet/TGet.

    TURLLink — Alinhamento de Texto

    Novo DATA nAlign e METHOD AlignText(nAlign). Method Default() agora auto-detecta o alinhamento a partir dos estilos de janela (SS_RIGHT, SS_CENTER) quando ::nAlign é nil. Method EraseBkGnd() agora aceita o parâmetro hDC. Agradecimentos a Carlos Sincuir.

    fwhxhb.h — Compatibilidade C Harbour/xHarbour

    include/fwhxhb.h mapeia a API C exclusiva do Harbour (hb_parvc/parvni/parvnl/parvnll/parvnd/parvl, hb_storvc/storvni/storvnl/storvnll/storvnd/storvl, hb_vmCDP, hb_retclen_buffer, hb_rettdt, hb_timeStampStrGetDT) para primitivas comuns a ambas as VMs. Um único conjunto de arquivos objeto C vincula contra Harbour ou xHarbour.

    Novos Exemplos

    transxbrowse — Classificador de Texto Transformer no XBrowse

    samples\ai\transxbrowse.prg treina uma rede neural Transformer para classificar frases em espanhol em 6 categorias (Saudacao, Despedida, Agradecimento, Pergunta, Comando, Resposta) usando um vocabulario de 25 tokens. Mostra todas as previsoes em uma grade XBrowse com porcentagem de confianca e status OK/FAIL. O titulo da janela mostra a precisao. Usa LRScheduler para agendamento de warmup.

    transsave — Salvar/Carregar Modelo Transformer

    samples\ai\transsave.prg demonstra o ciclo de vida completo do modelo: treina um classificador Transformer, salva em disco com Save() (hb_Serialize), carrega de volta com Load(), e verifica que as previsoes coincidem. Resultados no XBrowse.

    transgen — Geracao de Texto Transformer

    samples\ai\transgen.prg treina um Transformer em sequencias de caracteres e gera novo texto autoregressivamente a partir de tokens semente. Usa Generate() com amostragem por temperatura. Resultados no XBrowse com pontuacoes de confianca.

    githubdb — githubDB + XBrowse

    samples\githubdb\githubdb.prg navega um fork githubDB (SQL+banco de dados vetorial no GitHub Actions) do FiveWin usando dois caminhos HTTP:

    • Leitura rápida (CDN) — busca data/<db>.json do raw.githubusercontent.com, sub-segundo, sem token.
    • Action query — envia SQL via repository_dispatch, consulta resultado, 10-30 s, precisa de token GitHub com Contents R/W.

    Transporte HTTP via objeto COM WinHttp (sem dependência curl/DLL). Compilado com build_new.bat (todas as variantes). Documentação em githubdb.

    testrsz — Redimensionamento de XBrowse sem Flicker

    samples\testrsz.prg demonstra como redimensionar um XBrowse em tempo de execução sem flicker. O método correto: adicione WS_CLIPCHILDREN ao estilo do diálogo, congele o diálogo com WM_SETREDRAW durante o redimensionamento, então repinte ambos. Inclui botões do "método antigo" lado a lado para comparação. Também documentado na documentação HTML do TXBrowse.

    seqedit e xbrseqed — Edição Sequencial no XBrowse

    samples\seqedit.prg e samples\ui\xbrowse\xbrseqed.prg demonstram edição sequencial guiada por teclado para fontes de dados Array no XBrowse. Pressione ENTER em uma linha para começar a editar a primeira coluna da sequência; cada ENTER subsequente valida a coluna atual e auto-avança; ESC cancela. Totalmente configurável via array estático aEditSeq (padrão {3,5,7}). Usa avanço de coluna baseado em PostMessage (sem timers).

    Correções de Erros

    • TFolder crash "No exported method: MOVE" — AdjustRect() chamava oDlg:Move() em elementos de ::aDialogs sem verificar se eram NIL. Adicionada verificação de NIL para ::aDialogs[1] e cada oDlg no callback do AEval, consistente com o padrão usado no resto da classe.

    Resumo

    O FWH 26.06 oferece maturidade importante da classe Agent (streaming SSE, ferramentas reais, tratamento de erros, interrupt/inject), duas novas classes de integração de sistema (TGit, TSSH), o port GUI desktop AgenticAI, suporte multi-cliente do Remote View, uma limpeza completa de warnings do compilador (~170 locais, dois bugs reais encontrados e corrigidos), restauração do target xHarbour Commercial, e expansão significativa da documentação para mais de 36 páginas HTML.
