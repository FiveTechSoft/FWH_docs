Novidades no FWH 26.05

Esta página resume as mudanças e adições no FiveWin para Harbour/xHarbour versão 26.05 (Maio 2026), em relação à versão anterior 26.03 (Março 2026).

Classe Agent — Agente Autônomo de IA

Uma nova classe source\classes\agent.prg implementa um agente de IA autônomo para codificação em Harbour/FiveWin — o mesmo motor agente que alimenta o Agents Web.

  • Loop — Run()/Step(): observar → decidir → agir. 14 passos máx., DeepSeek V4 via libcurl.
  • 15 ferramentas integradas — list_files, read_file, write_file, delete_file, shell, python, sql, web_search, web_fetch, register_tool, unregister_tool, user_tools, create_skill, toggle_skill, classify_disk.
  • Ferramentas dinâmicas — RegisterTool() permite ao agente criar suas próprias ferramentas a partir de scripts. UnregisterTool() as remove sem excluir o script. As ferramentas persistem em agent_state/user_tools.json.
  • Habilidades — instruções reutilizáveis injetadas no prompt do sistema. 5 integradas (reviewer, summarizer, refactor, documenter, tester) + habilidades em disco. ToggleSkill() ativa/desativa sem excluir o arquivo.
  • Multi-agente — DispatchAgents() lança até 4 sub-agentes em paralelo via hb_threadStart(). Cada um com sua própria instância, sem dispatch/ask_user. Contrato compartilhado para consistência.
  • Planejamento — GeneratePlan() solicita ao LLM de 3 a 6 passos JSON. ExecutePlan() os executa sequencialmente, marcando cada um como concluído.
  • Persistência — SaveState()/LoadState() salva ferramentas de usuário e habilidades ativas no disco. Sobrevive entre sessões.

Requer Harbour MT VM (libhbvmmt) para despacho multi-agente. Referência completa: Documentação da classe Agent. Ver exemplo: samples\agenticai\agenticai2.prg.

Remote View — Visualização e Controle ao Vivo pelo Navegador

Um novo subsistema (source/internal/remoteview/) permite que qualquer navegador na LAN veja e controle uma janela FWH em tempo real. A janela é capturada por GDI+, codificada diferencialmente em patches JPEG e transmitida por WebSocket para um canvas HTML5. Cliques, movimento, roda e teclado retornam do navegador para a janela real via PostMessage. Dois modos:

  • Cliente único — RemoteViewStart(hWnd, nPort) usa um temporizador WM_TIMER na thread GUI. O temporizador sobrevive a loops modais (MsgInfo, diálogos, menus). Sem necessidade de -mt.
  • Multi-cliente — RemoteViewServe(hWnd, nPort) executa dentro de uma thread Harbour (hb_threadStart), cada uma em sua própria porta com estado isolado por TLS. Vários navegadores podem ver e controlar a mesma janela simultaneamente. Requer Harbour MT VM (-mt).

O motor de captura compõe os popups owned (diálogos filhos, MessageBoxes) sobre a janela principal, e oferece suporte completo à interação com a barra de título: arrastar para mover, bordas de redimensionamento, botões min/max/fechar, e duplo clique para alternar maximizar — tudo compatível com DWM do Windows 10/11. Captura diferencial inteligente com hash FNV-1a omite frames idênticos para economizar largura de banda.

API: RemoteViewStart(hWnd, nPort), RemoteViewStop(), RemoteViewSetOffset(nX, nY), RemoteViewServe(hWnd, nPort, nOffX, nOffY), RemoteViewStopAll(). Consulte a documentação completa em Remote View.

Exemplos: samples/RemoteView/testrv.prg, testrv2.prg (diálogo), testrvmt.prg (multi-cliente). Já integrado em samples/database/fivedburv.prg (FiveDBU) via ON INIT RemoteViewStart().

Cobertura de compiladores: o Remote View foi verificado capturando e transmitindo em todas as variantes de Harbour e xHarbour, 32 e 64 bits, com os compiladores C BCC, MSVC e MinGW. O título da janela do testrv agora indica o build em execução (por exemplo “Harbour MSVC 64”). A única exceção é o xHarbour Commercial (toolchain VC98): apps FiveWin normais funcionam, mas a captura GDI+ de janela usada pelo Remote View falha em execução, portanto o Remote View não é suportado nesse build.

Novas Classes

TKnob — controle de knob rotativo (UI)

Um moderno controle de knob rotativo de Silvio Falconi (source/classes/tknob.prg), voltado para interfaces de áudio, MIDI e sintetizadores. Derivado de TControl e desenhado completamente com GDI (sem DLL adicional): indicador LED ou LINE, anel exterior iluminado com brilho, marcas externas opcionais, modos unipolar (0..127) e bipolar (-30..+30), controle com arraste e roda do mouse (CTRL para um passo mais fino), reinício com duplo clique, estado habilitado/desabilitado, valor interno mais rótulo externo com fontes separadas, e callbacks bSetGet / bChanged / bAction. Inclui um comando declarativo @ <linha>,<col> KNOB em include/tknob.ch. Ver TKnob. Exemplos: samples/knobtst1.prg, samples/knobtst2.prg.

THFTask e TChatAgent — utilidades FWAI (IA)

Mais duas classes utilitárias "FWAI". THFTask (source/classes/thftask.prg) é uma classe fina sobre a Inference API da HuggingFace para as tarefas NLP comuns — Classify, ZeroShot, NER, Summarize, Translate, Sentiment — cada uma retornando valores Harbour normais; o transporte é injectável (::bSender) para testes ou uma camada HTTP própria. TChatAgent (source/classes/tchatagent.prg) é um agente mínimo de "chat sobre seus dados" com tool-calling: New( bChat, bTool ) recebe um codeblock LLM e um codeblock de consulta, e o LLM responde TOOL <consulta> ou ANSWER <texto> até responder. Ambas documentadas em THFTask / TChatAgent. Além disso: GPT2Model (inferência de GPT-2 pré-treinado) agora é uma classe de biblioteca. Testes: samples/ai/thftasktest.prg, samples/ai/chatagenttest.prg.

TSemanticIndex — busca semântica sobre DBF/SQL (IA)

A primeira das classes utilitárias "FWAI" (source/classes/tsemanticindex.prg): busca por significado para apps de dados. Em vez de LIKE '%palavra%', ordena os registros por quão próximo seu texto está em significado de uma consulta, usando vetores de embedding e similaridade de cosseno. Agnóstica de backend — New( bEmbed ) recebe um codeblock { |cText| -> vetor }, então os embeddings podem vir de TEmbeddings (HuggingFace) ou de um modelo local. 

USE customers
oEmb := TEmbeddings():New()
oIdx := TSemanticIndex():New( { |c| oEmb:GetEmbeddings( c ) } )
oIdx:IndexDbf( "NOTES" )
aHits := oIdx:Search( "insatisfeito com entrega atrasada", 10 )   // { { RecNo, score }, ... }

Veja TSemanticIndex. Teste: samples/ai/semindextest.prg.

GPT-2 pré-treinado real rodando em FWH/Harbour puro (IA)

Um marco da linha de IA do FWH: samples/ai/gpt2test.prg constrói um GPT2Model sobre FW_Tensor, carrega os pesos reais do GPT-2 small (model.safetensors, 124M parâmetros, ~500 MB) um tensor de cada vez via FWT_LoadSafe (sem carregar o arquivo inteiro), e executa o forward pass completo na CPU — pre-norm, atenção causal multi-cabeça, MLP GELU, cabeça com pesos atados. Verificado numericamente contra uma referência GPT-2 em numpy: "The capital of France is" → " the" (token 262), correspondência exata de argmax, em menos de um segundo. Um laço de geração multi-token (greedy / temperatura / top-k) produz então texto real, p.ex. "The capital of France is the capital of the French Republic, and". Baixe model.safetensors de huggingface.co/gpt2 — não é distribuído com o FWH.

FW_Tensor e TFWLanguageModel — rumo a transformers locais (IA)

Dois passos rumo a executar modelos transformer reais dentro de apps FWH. FW_Tensor (source/function/fwtensor.c) é um tensor float32 plano com coleta de lixo: guarda os dados como um buffer contíguo em vez de arrays aninhados de Harbour, de modo que grandes conjuntos de pesos cabem em memória razoável e podem ser lidos diretamente de um arquivo safetensors (FWT_New, FWT_FromArray, FWT_ToArray, FWT_Shape, FWT_Size, FWT_Get/Set, FWT_MatMul, FWT_LoadSafe). Também inclui o conjunto completo de operações do forward pass do transformer: FWT_Add, FWT_Scale, FWT_AddBias, FWT_GELU, FWT_Softmax e FWT_LayerNorm por linha, FWT_Transpose, FWT_GatherRows (lookup de embeddings) e FWT_SliceCols/FWT_SetCols (divisão/junção de cabeças de atenção). Teste: samples/ai/fwtensortest.prg (10/10). É a Fase 1 do esforço PyTorch-lite — veja docs/{en,es,pt}/ai/pytorch-lite-roadmap.html para o porquê de cada passo.

TFWLanguageModel (source/classes/fwlangmodel.prg) é um modelo de linguagem autorregressivo em uma linha: envolve HFTokenizer + Transformer e um vocabulário compacto construído a partir do seu corpus, com treinamento em blocos sobre texto longo: 

oLM := TFWLanguageModel():New( "gpt2.tokenizer.json", 2, 64, 2, 64 )
oLM:Train( cCorpus, 100, 0.01 )
? oLM:Generate( "To be", 12, 0.8, 20 )

Demo treinando com texto real de Shakespeare: samples/ai/shakegpt.prg. Também novo: hb_MatrixSeed( n ) para inicialização de pesos reproduzível.

HFTokenizer — Tokenizador BPE da HuggingFace (IA)

O objetivo das classes de IA do FWH é oferecer a potência dos transformers nas suas aplicações FiveWin — e fazer isso reutilizando, o máximo possível, os recursos do ecossistema da HuggingFace. HFTokenizer é o primeiro marco desse esforço: uma implementação em Harbour puro do tokenizador BPE em nível de bytes da HuggingFace usado pelo GPT-2. Ele carrega um tokenizer.json padrão do Hub da HuggingFace e reproduz a tokenização do GPT-2 bit a bit (p.ex. "hello world" → { 31373, 995 }, com ciclos exatos Decode(Encode(texto))).

Uma ponte tokenizador → Transformer tokeniza texto real, constrói um vocabulário compacto apenas com os tokens que aparecem, treina o Transformer autorregressivo e decodifica os ids gerados de volta para texto — de modo que um modelo pode ser treinado e executado sobre linguagem real em vez de ids de brinquedo. Veja HFTokenizer para o pipeline completo e o roteiro de integração. Exemplos: samples/ai/hftoktest.prg, samples/ai/hflmtest.prg.

TGroupEx — Grupo Tipo Acordeão

Contribuição de Silvio Falconi (Itália). Um grupo recolhível tipo acordeão com um cabeçalho arredondado pintado, ícone opcional e botão de expandir/recolher. Múltiplos painéis TGroupEx podem ser vinculados com LINK GROUPS para se comportar como um acordeão vertical onde abrir um redistribui os demais. O último painel pode opcionalmente esticar para preencher a altura restante. Três temas visuais disponíveis. Exemplo: samples/test/ui/testgrpex.prg.

BWCC 64-bit dll/bwcc64.dll

Uma reimplementação limpa em 64 bits dos Controles Personalizados do Windows da Borland (BWCC) para aplicações de 64 bits. Exporta todas as 45 funções da DLL original de 32 bits:

  • Controles: BorBtn (com glifos predefinidos OK/Cancelar/Sim/Não/Ajuda), BorCheck, BorRadio, BorStatic, BorShade
  • Classes de diálogo: BorDlg, BorDlg_Gray, BorDlg_Std com pincel de padrão cinza pontilhado e manipulação de modelos
  • Glifos BorBtn: resolvidos dos recursos do módulo por ID inteiro, nome decimal ou texto do botão
  • BWCCMessageBox: caixa de mensagem com estilo Borland com ícone BWCC e botões BorBtn

Modo Escuro Nativo

A Visualização Prévia de Impressão (TPreview) agora suporta o modo escuro nativo via FW_SetDarkMode(.T.). O fundo da janela, a barra de ferramentas, a barra de status e o painel de miniaturas escurecem automaticamente sem alterações no código da aplicação. A barra de menu horizontal é escurecida usando uma nova função C FW_DarkMenuBar() que subclassifica a janela de visualização prévia e desenha os itens do menu de nível superior em cores escuras. Os submenus usam o estilo 2013 para menus pop-up escuros.

Correções Notáveis

TTrayIcon no Windows 11

Corrigido o problema do menu pop-up que não aparecia no Windows 11. O Windows 11 se recusa a exibir TrackPopupMenu pertencente a uma janela oculta/desabilitada. Um novo DATA oWndParent armazena a janela principal e Command() a ativa em vez de a janela oculta interna. A posição do cursor retornada por GetCursorPos agora é convertida corretamente para coordenadas de cliente.

Correções de Bugs no Modo Escuro

  • TMenu:SetDarkMode não mais faz recursão infinita. O método agora faz recursão no submenu real via oItem:bAction em vez de oItem:oMenu, que apontava de volta ao pai.
  • TBar:SetDarkMode corrigida a falha em bClrGrad não inicializado quando chamado antes de pintar a barra.

TXBrowse:SetColFromMySQL

Corrigido o erro do método que descartava um argumento de cabeçalho explícito na chamada clássica de dois parâmetros. O analisador de especificação de colunas agora verifica ValType(cHeader) != 'C' antes de sobrescrever, então os cabeçalhos fornecidos pelo usuário são preservados.

Resolução de Glifos de Botão BWCC

Os botões BorBtn genéricos agora exibem bitmaps dos recursos do módulo proprietário, testando três convenções: RT_BITMAP correspondendo ao ID do controle, IDs de bitmap baseados em estado e nome de bitmap correspondendo ao texto do botão. São correspondidos tanto IDs inteiros como nomes decimais, cobrindo as ferramentas de recursos da Borland.

Resumo

FWH 26.05 representa um grande esforço de documentação com mais de 200 novas páginas HTML de referência de classes, combinado com o novo subsistema Remote View para controle remoto de janelas pelo navegador, o controle acordeão TGroupEx, suporte completo a BWCC 64 bits, modo escuro nativo para Visualização Prévia de Impressão e múltiplas correções de bugs. A nova documentação é publicada em fivetechsoft.github.io/FWH_docs e é atualizada automaticamente a cada commit.
