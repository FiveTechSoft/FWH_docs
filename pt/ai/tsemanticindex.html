TSemanticIndex - Busca Semântica sobre DBF/SQL

Fonte: source/classes/tsemanticindex.prg

TSemanticIndex traz a busca por significado às apps de dados FiveWin. Em vez de LIKE '%palavra%', encontra os registros cujo texto está mais próximo em significado de uma consulta — p.ex. buscar "insatisfeito com entrega atrasada" recupera uma nota que diz "o pedido chegou duas semanas atrasado e o cliente está furioso", mesmo sem palavras em comum.

Funciona convertendo o texto em vetores de embedding e ordenando os registros por similaridade de cosseno. É a primeira das classes utilitárias "FWAI" — veja o roteiro PyTorch-lite.

Como funciona

flowchart LR subgraph Indexar F[Campo de texto DBF/SQL] --> E1[Embed por registro] --> N1[Normalizar] --> S[(vetores + ids)] end subgraph Consulta Q[Texto da consulta] --> E2[Embed] --> N2[Normalizar] --> D[Produto escalar vs todos] --> R[Top-N registros por score] end S --> D

Os vetores são guardados unit-normalizados, então a similaridade de cosseno é um simples produto escalar. Os scores vão de 1.0 (significado idêntico) para baixo.

Agnóstico de backend

New( bEmbed ) recebe um codeblock { |cText| -> vetor }, então os embeddings podem vir de qualquer fonte — a Inference API da HuggingFace, um modelo local, ou sua própria função. Para usar o MiniLM da HuggingFace via TEmbeddings: 

oEmb := TEmbeddings():New()                 // precisa de HF_API_KEY (MiniLM 384-dim)
oIdx := TSemanticIndex():New( { |c| oEmb:GetEmbeddings( c ) } )

Para dados privados/offline, conecte um modelo de embeddings local atrás do mesmo codeblock (veja a orientação local-vs-cloud do roteiro) — o código do índice não muda.

Métodos

MétodoDescrição
New( bEmbed )Cria um índice usando o codeblock de embedding dado.
Add( cText, uId )Faz embedding de cText e o guarda sob o id uId.
AddVector( aVec, uId )Guarda um vetor pré-calculado sob uId (sem embedding).
IndexDbf( cField, bId )Percorre a área de trabalho atual indexando cField; o id padrão é RecNo() (ou Eval(bId)).
Search( cQuery, nTop )Retorna { { uId, nScore }, ... } com as nTop melhores correspondências, a melhor primeiro.
Size()Número de registros indexados.
Save( cFile ) / Load( cFile )Persiste / restaura o índice (ids + vetores).

Exemplo: buscar em notas de clientes

USE customers
oEmb := TEmbeddings():New()
oIdx := TSemanticIndex():New( { |c| oEmb:GetEmbeddings( c ) } )
oIdx:IndexDbf( "NOTES" )                     // um vetor por registro, id = RecNo()
oIdx:Save( "customers.idx" )                 // construir uma vez, reutilizar

aHits := oIdx:Search( "insatisfeito com entrega atrasada", 10 )
for each h in aHits
   ( customers )->( dbGoto( h[ 1 ] ) )       // h[1] = RecNo, h[2] = score
   ? customers->NAME, h[ 2 ]
next

Notas

  • Construa o índice uma vez e faça Save; recarregue ao iniciar. Re-embede apenas os registros que mudam.
  • Embeddings cloud (TEmbeddings/HF) são o mais fácil para começar; para dados sensíveis ou alto volume, um modelo de embeddings local evita custo por chamada e mantém o dado na máquina.
  • A busca por cosseno aqui é uma varredura linear em Harbour — ok para milhares de registros. Para conjuntos muito grandes, agrupe os vetores numa matriz FW_Tensor e ordene com uma única multiplicação de matrizes.
  • O codeblock embedder deve retornar um array numérico; Add ignora registros cujo embedding falha (p.ex. erro de API).
