Class Agent

Fonte: source/classes/agent.prg

source\classes\agent.prg

An agente IA de codificação autônomo for Harbour/FiveWin. Implements the same motor agentic que impulsiona Agents Web: chat streaming, ferramentas reais, tools dinâmicas, skills e multi-agente via hb_threadStart().

Início Rápido

oAgent := Agent():New( cApiKey )
oAgent:Run( "Crea una app TODO en PHP+SQLite con 3 sub-agentes" )
? oAgent:UsageReport()

Métodos Principais

New( cKey, [cModel] ) → Agent

Construtor. Inicializa tools, skills, carrega estado salvo. Modelo padrão: deepseek-v4-pro.

Run( cPrompt ) → lastAssistantMessage

Loop principal: observar → decidir → agir. Máx nMaxSteps iterações (padrão 14). Retorna a última resposta de texto. As tool calls intermediárias são executadas e seus resultados alimentam a conversa.

Step() → cResponse

Envia a conversa atual para DeepSeek (POST api.deepseek.com/chat/completions), retorna a resposta bruta. Atualiza métricas de tokens. É o RPC central do LLM.

BuildSystemPrompt()

Constrói o system prompt: instruções base + skills ativos + lista de user tools + objetivo/plano.

BuildToolsArray() → aTools

Retorna o array completo de tools no formato OpenAI (integradas + usuário) para a requisição LLM.

Ferramentas Dinâmicas

MethodDescription
RegisterTool(cName,cDesc,cScript,[cType])Registra script como tool executável. Auto-detecta tipo python/shell.

As tools persistem em agent_state/user_tools.json. As integradas são fixas; as do usuário são dinâmicas e sobrevivem entre sessões.

Hooks

Hooks são callbacks que executam antes/depois de cada tool call, permitindo logging, auditoria, validação e cancelamento sem modificar o código das tools.

MethodDescription
RegisterHook(cName,cEvent,bBlock,[nPriority])Registra um hook. Eventos: pre_tool_use, post_tool_use, on_error, on_complete. Pre-hooks retornam .F. para cancelar.
UnregisterHook(cName)Remove um hook por nome.
ListHooks()Lista todos os hooks registrados com evento, prioridade e status.
RunHooks(cEvent,hContext)Executa todos os hooks de um evento. Chamado internamente por ExecTool().
LLMRegisterHook(cName,cEvent,cAction,[nPriority])Registra hook via LLM usando ações predefinidas: log, audit, block_shell, block_delete, block_write.

O hash de contexto hContext contém: {name, args, result}. Os pre-hooks recebem o nome da tool e seus argumentos; retornam .F. para cancelar. Os post-hooks recebem o resultado e podem modificar hContext["result"].

Skills

MethodDescription
CreateSkill(cName,cContent,[cDir])Escreve arquivo skill em skills/name.md
ToggleSkill(cName,lOn)Ativa/desativa sem apagar o arquivo
ActiveSkillsPrompt()Retorna string de prompt com skills ativos

5 skills integrados: reviewer, summarizer, refactor, documenter, tester. Skills injetam instruções reutilizáveis no system prompt. Eles moldam COMO o agente pensa, não O QUE ele pode fazer (isso é tratado pelas tools).

Orquestração Multi-Agente

A classe Agent fornece um framework completo de orquestração com 8 métodos para coordinar múltiplos agentes: despacho paralelo, pipelines sequenciais, roles especializados, contexto compartilhado, retry, timeout, agregação e monitoramento.

Roles

Cada Agent tem uma propriedade cRole e cRolePrompt. Os roles definem a especialização do agente. O prompt do role é injetado no system prompt.

oDev := Agent():New( cKey )
oDev:cRole       := "developer"
oDev:cRolePrompt := "Eres desarrollador senior. Escribe código limpio y documentado."

DispatchAgents( aTasks, cContract ) → aResults

Fan-out paralelo: lança até 4 sub-agentes simultaneamente. Cada sub-agente herda o role, contexto compartilhado e modelo do pai. Os resultados são coletados sincronamente.

DispatchAgentsPipeline( aTasks, cContract ) → aResults

Pipeline sequencial: a saída de cada agente alimenta o próximo. Útil para cadeias de tarefas dependentes onde o passo N precisa do resultado do passo N-1.

aResults := oAgent:DispatchAgentsPipeline( { ;
   "Analisa os requisitos do app", ;
   "Projeta o schema do banco de dados", ;
   "Gera o código backend", ;
   "Escreve os testes unitários" }, cContract )

DispatchAgentsWithRoles( aAgentDefs, cContract ) → aResults

Fan-out com roles especializados. Cada definição é um hash com: task, role, rolePrompt, model, nMaxSteps. Os agentes rodam em paralelo com sua própria configuração.

aDefs := { ;
   { "task" => "Projetar schema", "role" => "analyst", ;
     "rolePrompt" => "Eres analista de datos.", "nMaxSteps" => "8" }, ;
   { "task" => "Implementar API", "role" => "developer", ;
     "model" => "gpt-4o", "nMaxSteps" => "10" }, ;
   { "task" => "Escrever testes", "role" => "tester", ;
     "rolePrompt" => "Eres tester QA.", "nMaxSteps" => "6" } }
aResults := oAgent:DispatchAgentsWithRoles( aDefs, cContract )

Contexto Compartilhado (Padrão Blackboard)

Os agentes comunicam via um hash compartilhado. As mudanças são sincronizadas de volta ao pai após cada sub-agente completar. O contexto é injetado no system prompt.

MethodDescription
GetSharedContext([cKey])Obter todo o contexto ou uma chave específica.
SetSharedContext(cKey, xValue)Definir uma chave no contexto compartilhado.
oAgent:SetSharedContext( "schema", "CREATE TABLE users..." )
// os sub-agentes verão isso em seu system prompt

AggregateResults( aResults, cMethod ) → cCombined

Combinar resultados de múltiplos agentes. Métodos:

  • "join" — concatenar com cabeçalhos (padrão)
  • "json" — codificar como array JSON
  • "summary" — resumo em bullets via LLM

RetrySubAgent( cTask, cContract, nMaxRetries ) → cResult

Repetir um sub-agente falhado até nMaxRetries vezes (padrão 3). Cada tentativa roda em uma instância nova com recuperação de erros.

SubAgentRunWithTimeout( cTask, cContract, nTimeout ) → cResult

Executar um sub-agente com limite de tempo em segundos (padrão 120). Usa o mecanismo de interrupção para abortar se exceder o timeout.

NotifyProgress( cAgentName, cStatus, cMsg )

Enviar notificações de progresso. Configurar bOnAgentProgress para receber callbacks.

oAgent:bOnAgentProgress := {| cName, cStatus, cMsg | ;
   ? cName + ": " + cStatus + " — " + cMsg }

SubAgentRun( cTask, cContract ) → cResult

Execução individual de sub-agente. Chamado por DispatchAgents() em seu próprio thread.

Planejamento

GeneratePlan( cGoal ) → aPlan

Pede ao LLM para dividir o objetivo em 3-6 passos JSON. Retorna um array de {title, state} where the first step is "active" and the rest "pending".

ExecutePlan()

Executa o plano sequencialmente: para cada passo "active", chama Run() com a descrição, marca como "done", ativa o próximo. Para quando todos estão completos.

Persistência

MethodDescription
SaveState(cDir)Salva user tools e skills ativos em user_tools.json
LoadState(cDir)Restaura do disco ao iniciar. Também carrega skills do diretório skills/.

Exemplo Completo

PROCEDURE Main()
   LOCAL oAgent, cResult

   oAgent := Agent():New( "sk-xxxx" )

   // Registrar uma tool personalizada
   oAgent:RegisterTool( "contar", ;
      "Cuenta lineas, palabras y caracteres de un archivo", ;
      "contar.py" )

   // Criar e ativar um skill
   oAgent:CreateSkill( "prueba", ;
      "Responde siempre en español." + CRLF + ;
      "Verifica el disco antes de escribir código." + CRLF + ;
      "Escribe tests automáticamente." )
   oAgent:ToggleSkill( "prueba", .T. )

   // Registrar um hook para auditar todas as tool calls
   oAgent:RegisterHook( "audit_log", "post_tool_use", ;
      {| h | ? "AUDIT:", h["name"], hb_ValToStr( h["args"] ) }, 50 )

   // Registrar um hook para bloquear comandos shell (pre-hook)
   oAgent:RegisterHook( "safe_mode", "pre_tool_use", ;
      {| h | iif( h["name"] == "shell", .F., .T. ) }, 10 )

   // Ou usar presets predefinidos para o LLM
   oAgent:LLMRegisterHook( "llm_audit", "post_tool_use", "audit" )

   // Generate and execute a plan
   oAgent:GeneratePlan( "Crea una app TODO en PHP+SQLite" )
   oAgent:ExecutePlan()

   // Or run directly
   cResult := oAgent:Run( "Explica qué hay en el disco" )
   ? cResult

   // === Orquestração multi-agente ===
   oAgent:nSubAgentTimeout := 60

   // Despacho paralelo com roles
   aDefs := { ;
      { "task" => "Projetar schema", "role" => "analyst", ;
        "rolePrompt" => "Eres analista de datos." }, ;
      { "task" => "Implementar API", "role" => "developer", ;
        "model" => "gpt-4o" }, ;
      { "task" => "Escrever testes", "role" => "tester" } }
   aResults := oAgent:DispatchAgentsWithRoles( aDefs, cContract )

   // Agregar resultados
   cSummary := oAgent:AggregateResults( aResults, "summary" )
   ? cSummary

   // Pipeline: tarefas dependentes sequenciais
   aResults := oAgent:DispatchAgentsPipeline( { ;
      "Analisa requisitos", "Projetar schema", "Implementar API" }, cContract )

   oAgent:UsageReport()
RETURN

Notas

  • Requer Harbour MT VM for DispatchAgents(). Linkar contra libhbvmmt.
  • API Key: configurar via variável de ambiente DEEPSEEK_API_KEY ou construtor.
  • Streaming: Step() usa streaming SSE com stream_options para métricas de tokens em tempo real.
  • Orquestração: DispatchAgents() paralelo, DispatchAgentsPipeline() sequencial, DispatchAgentsWithRoles() com roles especializados. Contexto compartilhado via SetSharedContext(). Retry, timeout e agregação incluídos.
  • Roles: configurar cRole e cRolePrompt para especializar cada agente. O prompt do role é injetado no system prompt automaticamente.
  • Hooks: callbacks pre/post na execução de tools. Usar RegisterHook() para codeblocks personalizados, ou LLMRegisterHook() com presets (log, audit, block_*).
  • Contrato: o parâmetro cContract em DispatchAgents() é crítico. Sem ele, os sub-agentes paralelos divergem nas convenções de nomes. Forneça sempre nomes exatos de tabelas, colunas, funções e caminhos de arquivos.
  • Exemplo: samples\agenticai\agenticai2.prg — um app FiveWin GUI completo usando a Class Agent com painel de chat TWebView2.
