HFTokenizer - Tokenizador BPE da HuggingFace

Fonte: source/classes/hftokenizer.prg

HFTokenizer é uma implementação em Harbour puro do tokenizador BPE em nível de bytes (byte-level Byte-Pair-Encoding) da HuggingFace, usado pelo GPT-2 e por muitos modelos derivados. Ele carrega um arquivo tokenizer.json padrão (baixado do Hub da HuggingFace) e reproduz a tokenização do GPT-2 bit a bit: o mesmo texto gera exatamente os mesmos ids de tokens.

Isso conecta a classe Transformer do FiveWin a vocabulários reais, de modo que um modelo possa ser treinado ou executado sobre texto real em vez de ids de tokens de brinquedo.

Obter um tokenizer.json

Baixe um tokenizador do Hub da HuggingFace. Para o GPT-2:

https://huggingface.co/gpt2/resolve/main/tokenizer.json

O arquivo contém um objeto model com um mapa vocab (token → id) e uma lista merges (regras de fusão BPE ordenadas). O arquivo do GPT-2 tem cerca de 1,35 MB com 50.257 tokens e 50.000 fusões.

Métodos

MétodoDescrição
New( cFile )Constrói os mapas byte → unicode e, se cFile for informado, carrega esse tokenizer.json.
Load( cFile )Analisa um tokenizer.json: lê model.vocab e model.merges (aceita formato de string ou de par). Retorna NIL se o arquivo for inválido.
Encode( cText )Tokeniza o texto em um array de ids de tokens (base 0, ids crus da HuggingFace).
Decode( aIds )Reconstrói o texto original a partir de um array de ids de tokens.
Size()Número de tokens no vocabulário carregado.

Exemplo

#include "FiveWin.ch"

FUNCTION Main()
   LOCAL oTok, aIds, cBack

   oTok := HFTokenizer():New( "gpt2.tokenizer.json" )

   ? oTok:Size()                       // 50257

   aIds := oTok:Encode( "hello world" )
   ? hb_ValToExp( aIds )               // { 31373, 995 }

   cBack := oTok:Decode( aIds )
   ? cBack                             // hello world

RETURN NIL

Como Funciona

1. Mapa byte → unicode

O byte_to_unicode do GPT-2 mapeia cada um dos 256 valores de byte para um caractere Unicode imprimível, de modo que nenhum byte seja não imprimível ou espaço em branco dentro da etapa BPE. O byte de espaço (0x20) torna-se notoriamente U+0120 (exibido como Ġ). A classe constrói esse mapa uma única vez em New(), junto com seu inverso exato para o Decode().

2. Pré-tokenizador

Antes do BPE, o texto é dividido em pedaços seguindo a expressão regular do GPT-2, que mantém juntas as contrações ('s 't 're 've 'm 'll 'd) e anexa um único espaço inicial ao grupo de palavra, número ou símbolo seguinte (o conhecido comportamento " ?\p{L}+"). A implementação cobre letras ASCII, dígitos, símbolos e sequências de espaços; qualquer byte não ASCII é tratado de forma transparente pelo mapeamento em nível de bytes.

3. Fusões BPE

Cada pré-token é convertido em seus caracteres Unicode mapeados e então fundido de forma gulosa: a cada passo, o par de símbolos adjacente com o menor rank de fusão (sua posição em model.merges) é unido, até que não reste nenhum par conhecido. Os tokens resultantes são buscados em model.vocab para produzir os ids.

Validação

O tokenizador é verificado contra o tokenizer.json real do GPT-2. Os ids de referência conhecidos coincidem exatamente:

TextoIds de tokens
"hello world"{ 31373, 995 }
"Hello world"{ 15496, 995 }

Um ciclo completo Decode( Encode( texto ) ) == texto se mantém para frases com pontuação, contrações, dígitos, múltiplos espaços e quebras de linha. O conjunto de testes sem interface é samples/ai/hftoktest.prg.

Ponte para o Transformer

HFTokenizer é o primeiro passo de um esforço contínuo para integrar o Transformer do FWH ao ecossistema da HuggingFace, de modo que as aplicações FiveWin possam reutilizar recursos de IA do mundo real — tokenizadores hoje, datasets e (quando a arquitetura permitir) pesos pré-treinados em seguida.

O vocabulário do GPT-2 tem 50.257 tokens — muito mais do que um modelo pequeno treinado do zero precisa. Por isso a ponte constrói um vocabulário compacto contendo apenas os tokens que aparecem no seu corpus, mapeando os ids da HuggingFace para ids locais densos de base 1:

  1. Tokenize o corpus com HFTokenizer:Encode.
  2. Reúna os ids de tokens únicos em um vocabulário compacto de base 1 mais suas strings de tokens.
  3. Crie o Transformer com esse vocabulário e treine-o (ForwardSeq / BackwardSeq).
  4. Gere ids locais, mapeie-os de volta para ids da HuggingFace e faça Decode para texto.

Exemplo de ponta a ponta: samples/ai/hflmtest.prg.

Notas

  • Encode retorna ids crus da HuggingFace (base 0). Ao alimentar um vocabulário base 1 da classe Transformer do FiveWin, some 1 (ou mapeie através do seu próprio vocabulário).
  • Ambos os formatos de fusão são aceitos: strings legadas "tokA tokB" e os pares mais recentes [ "tokA", "tokB" ].
  • O tokenizer.json é um recurso para download e não é distribuído com o FiveWin; baixe-o uma vez do Hub.
  • Tokens especiais/adicionados (p.ex. <|endoftext|>) estão no vocabulário e são resolvidos como qualquer outro token quando aparecem literalmente na entrada.
