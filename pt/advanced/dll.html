DLL & Chamadas à API do Windows

O FiveWin e o Harbour fornecem múltiplos mecanismos para chamar funções da API do Windows e DLLs externas diretamente do seu código PRG. Isso vai desde os wrappers nativos do FiveWin para chamadas de API comuns, passando pelo suporte a chamadas de DLL do Harbour, até código C inline via #pragma BEGINDUMP. Esta página cobre todas as abordagens com exemplos práticos.

graph TD A[Código PRG Harbour] --> B{Chamando Código Externo} B --> C[Wrappers de API do FiveWin] B --> D[Comando DLL32 FUNCTION] B --> E["#pragma BEGINDUMP"] C --> F[API do Windows - user32, kernel32, gdi32] D --> G[Qualquer DLL Externa] E --> H[Código C Inline] H --> I["hb_retni(), hb_parc(), etc."] H --> J[Chamadas diretas à API do Windows] H --> K[Bibliotecas C personalizadas]

Wrappers de API do FiveWin

O FiveWin encapsula previamente centenas de funções da API do Windows para que você possa chamá-las diretamente do código PRG sem nenhuma declaração de DLL ou código C. Estas são implementadas como funções C HB_FUNC() dentro dos arquivos-fonte do FiveWin (em source\winapi\ e source\internal\).

Chamada de Funções de DLL

O FiveWin fornece o comando DLL FUNCTION (de DLL.ch) para declarar e chamar funções de qualquer DLL externa em tempo de execução. Isso usa o mecanismo interno de chamada de DLL do FiveWin que trata a serialização de parâmetros entre as convenções de chamada do Harbour e do C.

Sintaxe do Comando DLL.ch

#include "DLL.ch"

// Declare a DLL function
DLL FUNCTION <FuncName>( [<Params,...>] ) AS <ReturnType> ;
   [PASCAL | CDECL] ;
   FROM <ExportName> ;
   LIB <cDllName | hDll>

// Return types: LONG, DWORD, BOOL, LPSTR, VOID, DOUBLE, WORD, BYTE
// Parameter types: passed by value or by reference (@)

Exemplo: Chamar MessageBoxA de user32.dll

#include "DLL.ch"

// Declare the function
DLL FUNCTION MsgBoxA( hWnd AS LONG, cText AS LPSTR, cTitle AS LPSTR, ;
                       nType AS LONG ) AS LONG ;
   PASCAL FROM "MessageBoxA" LIB "user32.dll"

function TestMsgBox()
   local nResult

   nResult := MsgBoxA( 0, "Hello from DLL call!", "FiveWin", 0x00000004 )
   // MB_YESNO = 4

   if nResult == 6   // IDYES
      ? "User clicked Yes"
   else
      ? "User clicked No"
   endif

return nil

Exemplo: Chamar GetSystemMetrics

#include "DLL.ch"

DLL FUNCTION GetSysMetrics( nIndex AS LONG ) AS LONG ;
   PASCAL FROM "GetSystemMetrics" LIB "user32.dll"

function ScreenInfo()
   #define SM_CXSCREEN      0
   #define SM_CYSCREEN      1
   #define SM_CXFULLSCREEN 16
   #define SM_CYFULLSCREEN 17
   #define SM_CMOUSEBUTTONS 43

   ? "Screen:", GetSysMetrics( SM_CXSCREEN ), "x", GetSysMetrics( SM_CYSCREEN )
   ? "Work area:", GetSysMetrics( SM_CXFULLSCREEN ), "x", GetSysMetrics( SM_CYFULLSCREEN )
   ? "Mouse buttons:", GetSysMetrics( SM_CMOUSEBUTTONS )

return nil

Exemplo: Chamar uma DLL Personalizada

#include "DLL.ch"

// Loading DLL handle first for multiple calls
function UseCustomDLL()
   local hDll := LoadLibrary( "mymath.dll" )

   if hDll == 0
      MsgAlert( "Cannot load mymath.dll" )
      return nil
   endif

   // Declare functions using the handle
   DLL FUNCTION CalcSum( n1 AS LONG, n2 AS LONG ) AS LONG ;
      PASCAL FROM "CalcSum" LIB hDll

   DLL FUNCTION CalcProduct( n1 AS LONG, n2 AS LONG ) AS LONG ;
      PASCAL FROM "CalcProduct" LIB hDll

   ? "Sum:", CalcSum( 10, 20 )        // 30
   ? "Product:", CalcProduct( 5, 7 )  // 35

   FreeLibrary( hDll )

return nil

Exemplo: Chamar Função de DLL com Saída de String

#include "DLL.ch"

DLL FUNCTION GetTempPathA( nBufferLen AS DWORD, @cBuffer AS LPSTR ) AS DWORD ;
   PASCAL FROM "GetTempPathA" LIB "kernel32.dll"

function GetTemp()
   local cBuffer := Space( 260 )
   local nLen

   nLen := GetTempPathA( 260, @cBuffer )
   cBuffer := Left( cBuffer, nLen )

   ? "Temp path:", cBuffer

return nil

Código C Inline com #pragma BEGINDUMP

O #pragma BEGINDUMP / ENDDUMP do Harbour permite incorporar código C diretamente nos seus arquivos PRG. O código C é compilado pelo compilador C (BCC32, MSVC, MinGW) durante o processo de build. Esta é a abordagem mais poderosa e flexível para interface com APIs do Windows, criação de funções críticas em desempenho, ou encapsulamento de bibliotecas C.

sequenceDiagram participant PRG as Código PRG participant HRB as Compilador Harbour participant C as Compilador C participant Link as Linker PRG->>HRB: Compilar .prg para .c Note over HRB: Seções #pragma BEGINDUMP
copiadas literalmente para a saída .c HRB->>C: Arquivo .c de saída C->>Link: Compilar para .obj Link->>Link: Linkar com funções de hbapi.h

Como Funciona

Quando o compilador Harbour encontra #pragma BEGINDUMP, ele para de traduzir código PRG e copia tudo literalmente para o arquivo C de saída até encontrar #pragma ENDDUMP. Isso permite que você escreva funções C que podem ser chamadas do PRG usando a macro HB_FUNC().

Exemplo: HB_FUNC Básico

// myutils.prg

function Main()
   ? "Sum:", FastAdd( 100, 200 )       // 300
   ? "Upper:", FastUpper( "hello" )     // "HELLO"
   ? "CPU count:", GetCPUCount()
return nil

#pragma BEGINDUMP

#include <hbapi.h>
#include <windows.h>

// Simple function: add two numbers
HB_FUNC( FASTADD )
{
   hb_retnl( hb_parnl( 1 ) + hb_parnl( 2 ) );
}

// String function: convert to uppercase
HB_FUNC( FASTUPPER )
{
   const char * szText = hb_parc( 1 );
   int nLen = hb_parclen( 1 );
   char * szResult = ( char * ) hb_xgrab( nLen + 1 );
   int i;

   for( i = 0; i < nLen; i++ )
      szResult[ i ] = ( char ) toupper( ( unsigned char ) szText[ i ] );
   szResult[ nLen ] = '\0';

   hb_retclen( szResult, nLen );
   hb_xfree( szResult );
}

// Windows API call: get number of CPUs
HB_FUNC( GETCPUCOUNT )
{
   SYSTEM_INFO si;
   GetSystemInfo( &si );
   hb_retnl( ( long ) si.dwNumberOfProcessors );
}

#pragma ENDDUMP

function Main()

#include <hbapi.h>
#include <windows.h>

HB_FUNC( MYMESSAGEBOX )
{
   hb_retni( MessageBoxA(
      ( HWND ) hb_parnl( 1 ),   // hWnd
      hb_parc( 2 ),              // text

      hb_parni( 4 )              // type

#include <hbapi.h>
#include <hbapiitm.h>
#include <windows.h>

HB_FUNC( GETTOTALMEMORY )
{
   MEMORYSTATUSEX ms;
   ms.dwLength = sizeof( MEMORYSTATUSEX );
   GlobalMemoryStatusEx( &ms );
   hb_retnll( ( HB_LONGLONG ) ms.ullTotalPhys );
}

HB_FUNC( GETOSVERSION )
{
   OSVERSIONINFO ovi;
   PHB_ITEM pArray;

   ovi.dwOSVersionInfoSize = sizeof( OSVERSIONINFO );
   GetVersionEx( &ovi );

   pArray = hb_itemArrayNew( 3 );
   hb_arraySetNL( pArray, 1, ovi.dwMajorVersion );
   hb_arraySetNL( pArray, 2, ovi.dwMinorVersion );
   hb_arraySetNL( pArray, 3, ovi.dwBuildNumber );

   hb_itemReturnRelease( pArray );
}

#pragma ENDDUMP

Padrões Avançados

Passando Arrays Entre PRG e C

// arrays.prg

function Main()
   local aInput := { 10, 20, 30, 40, 50 }
   ? "Sum:", ArraySum( aInput )   // 150
return nil

#pragma BEGINDUMP

#include <hbapi.h>
#include <hbapiitm.h>

HB_FUNC( ARRAYSUM )
{
   PHB_ITEM pArray = hb_param( 1, HB_IT_ARRAY );
   HB_SIZE nLen, i;
   long nSum = 0;

   if( pArray )
   {
      nLen = hb_arrayLen( pArray );
      for( i = 1; i <= nLen; i++ )
         nSum += hb_arrayGetNL( pArray, i );
   }

   hb_retnl( nSum );
}

#pragma ENDDUMP

Funções de Callback (Procedimentos de Janela)

// Custom window subclassing from C
#pragma BEGINDUMP

#include <hbapi.h>
#include <windows.h>

static WNDPROC oldWndProc = NULL;

static LRESULT CALLBACK MyWndProc( HWND hWnd, UINT msg, WPARAM wParam, LPARAM lParam )
{
   switch( msg )
   {
      case WM_PAINT:
         // Custom paint handling
         break;

      case WM_KEYDOWN:
         if( wParam == VK_F5 )
         {
            MessageBoxA( hWnd, "F5 pressed!", "Custom Handler", MB_OK );
            return 0;
         }
         break;
   }
   return CallWindowProc( oldWndProc, hWnd, msg, wParam, lParam );
}

HB_FUNC( SUBCLASSWINDOW )
{
   HWND hWnd = ( HWND ) hb_parnl( 1 );
   oldWndProc = ( WNDPROC ) SetWindowLongPtr( hWnd, GWLP_WNDPROC, ( LONG_PTR ) MyWndProc );
   hb_retnl( ( long ) oldWndProc );
}

HB_FUNC( UNSUBCLASSWINDOW )
{
   HWND hWnd = ( HWND ) hb_parnl( 1 );
   SetWindowLongPtr( hWnd, GWLP_WNDPROC, ( LONG_PTR ) oldWndProc );
}

#pragma ENDDUMP

Linkando com Bibliotecas Externas

Quando seu código C chama funções de bibliotecas externas, você precisa linkar essas bibliotecas no seu script de build.

Borland C++ (BCC32)

REM In your buildh.bat or b32.bat, add import libraries:
bcc32 -c myapp.c
ilink32 myapp.obj, myapp.exe, , FiveHC.lib hbvm.lib ... ws2_32.lib wininet.lib

MSVC (64-bit)

REM In your build script:
cl /c myapp.c
link myapp.obj FiveH64.lib ... ws2_32.lib wininet.lib /OUT:myapp.exe

Dicas para #pragma BEGINDUMP

  • Sempre inclua <hbapi.h> para a macro HB_FUNC e funções de parâmetros.
  • Inclua <hbapiitm.h> para manipulação de itens do Harbour (arrays, hashes).
  • Inclua <hbapierr.h> para tratamento de erros a partir do código C.
  • Inclua <windows.h> para tipos e funções da API do Windows.
  • Use hb_xgrab()/hb_xfree() para alocação de memória gerenciada pelo Harbour.
  • Nomes de funções em HB_FUNC() devem ser em MAIÚSCULAS -- eles mapeiam para nomes de funções PRG em maiúsculas.
  • Para builds 64-bit, use hb_parnll()/hb_retnll() para valores do tamanho de ponteiros, e faça cast de handles para HB_PTRUINT.
  • Evite suposições de ponteiros 32-bit em código 64-bit: sempre use ( HWND ) hb_parnll() em vez de ( HWND ) hb_parnl() para handles.
