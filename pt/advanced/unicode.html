Unicode & Internacionalização

O FiveWin oferece um sistema abrangente de internacionalização (i18n) com dois componentes principais: um sistema de tradução de strings multi-idioma (FWString) e suporte a Unicode para exibição de caracteres não-ASCII em janelas e controles. Esta página cobre ambos os sistemas em detalhes, incluindo considerações sobre codificação e exemplos práticos.

FWString() - O Sistema de Tradução

O sistema de tradução do FiveWin é construído sobre um array estático chamado aStrings definido em source\function\strings.prg. Cada elemento é um array de strings: índice 1 é Inglês, 2 é Espanhol, 3 é Francês, 4 é Português, 5 é Alemão, 6 é Italiano. Quando você chama FWString("algum texto"), ele procura o texto em inglês no array e retorna a tradução para o idioma atual.

Como Funciona

  1. Na inicialização, FWLanguageID() detecta automaticamente o idioma a partir de HB_LangSelect() e o mapeia para um índice de idioma (1=EN, 2=ES, 3=FR, 4=PT, 5=DE, 6=IT).
  2. Todas as strings internas da interface do FiveWin (menus, botões, mensagens, rótulos do previsualizador de relatórios) passam por FWString().
  3. Quando o idioma atual é Inglês (índice 1), FWString() retorna a string de entrada imediatamente (sem necessidade de busca).
  4. Para outros idiomas, ele busca em aStrings uma correspondência sem distinção de maiúsculas/minúsculas no texto em inglês e retorna a string traduzida no índice do idioma atual.
  5. Se a string não for encontrada, ela é adicionada a uma lista de "strings ausentes" e o texto original em inglês é retornado.

Strings Embutidas

O FiveWin inclui traduções para centenas de strings comuns da interface: rótulos de botões (Ok, Cancel, Save, Print), itens de menu (File, Edit, View, Help), títulos de diálogos, mensagens de erro, rótulos do previsualizador de relatórios (First, Previous, Next, Last, Zoom), rótulos do navegador de dados (Add, Edit, Del, Search, Filter), e mais.

Funções Principais

FWLoadStrings() - Carregando Traduções Personalizadas

Você pode carregar traduções adicionais de um arquivo INI em tempo de execução. O arquivo utiliza uma seção [strings] com entradas numeradas, onde cada valor contém traduções separadas por pipe.

Formato do Arquivo INI (fwstrings.ini)

[strings]
1=Customer|Cliente|Client|Cliente|Kunde|Cliente
2=Invoice|Factura|Facture|Fatura|Rechnung|Fattura
3=Product|Producto|Produit|Produto|Produkt|Prodotto
4=Total Amount|Importe Total|Montant Total|Valor Total|Gesamtbetrag|Importo Totale
5=Due Date|Fecha Vencimiento|Date Echeance|Data Vencimento|Faelligkeitsdatum|Data Scadenza

Exemplo: Carregar Traduções Personalizadas

function Main()
   // Load application-specific translations
   FWLoadStrings( "c:\myapp\translations.ini" )

   // Set language
   FWSetLanguage( 2 )  // Spanish

   // Now custom strings are translated too
   ? FWString( "Customer" )       // "Cliente"
   ? FWString( "Invoice" )        // "Factura"
   ? FWString( "Total Amount" )   // "Importe Total"

return nil

Adicionando Traduções Personalizadas Programaticamente

FWAddString() - Adicionar Entradas Individuais

// Add a single translation (all 6 languages)
FWAddString( { "Customer", "Cliente", "Client", "Cliente", "Kunde", "Cliente" } )

// Add using pipe-delimited string
FWAddString( "Invoice|Factura|Facture|Fatura|Rechnung|Fattura" )

// Add multiple entries at once (array of arrays)
FWAddString( { ;
   { "Customer", "Cliente", "Client", "Cliente", "Kunde", "Cliente" }, ;
   { "Invoice",  "Factura", "Facture", "Fatura", "Rechnung", "Fattura" }, ;
   { "Product",  "Producto", "Produit", "Produto", "Produkt", "Prodotto" } ;
} )

FWSetString() - Definir Tradução para Idioma Específico

// Set Spanish (language 2) translations
FWSetString( 2, { "Customer", "Cliente" } )
FWSetString( 2, { "Invoice",  "Factura" } )

// Set multiple at once
FWSetString( 2, { ;
   { "Customer", "Cliente" }, ;
   { "Invoice",  "Factura" }, ;
   { "Product",  "Producto" } ;
} )

FWAddLanguage() - Adicionar um Idioma Completamente Novo

// Add Japanese as language 7
// The array must match the order of the English strings in aStrings
local aJapanese := { ;
   "Attention",    ... }  // This needs ALL strings translated

// Or more practically, add empty and fill specific strings:
local nJapanese := FWAddLanguage( {} )   // Returns the new language ID (e.g., 7)

// Then fill in translations one at a time
FWSetString( nJapanese, { "Ok", "OK" } )
FWSetString( nJapanese, { "Cancel", "Cancel" } )
FWSetString( nJapanese, { "Print", "Print" } )

FWSetLanguage( nJapanese )   // Switch to Japanese

FW_SetUnicode() - Modo Unicode

Por padrão, o FiveWin cria janelas e controles usando as versões ANSI ("A") das funções da API do Windows (por exemplo, CreateWindowExA). Quando você habilita o modo Unicode com FW_SetUnicode(.T.), o FiveWin passa a usar as funções Wide ("W") da API (por exemplo, CreateWindowExW), permitindo que janelas e controles exibam caracteres de qualquer idioma -- chinês, japonês, coreano, árabe, hindi, e mais.

Como o Modo Unicode Afeta o FiveWin

graph LR A["FW_SetUnicode(.T.)"] --> B["Criação de Janelas"] A --> C["Texto dos Controles"] A --> D["Área de Transferência"] A --> E["Criação de Diálogos"] B --> F["CreateWindowExW()"] C --> G["SetWindowTextW()"] D --> H["CF_UNICODETEXT"] E --> I["DialogBoxIndirectW()"]

Quando o modo Unicode está ativo:

  • Todas as novas janelas e controles são criados com chamadas de API de caracteres largos (wide-character).
  • O texto é tratado internamente como UTF-8 no Harbour e convertido para UTF-16 nas chamadas da API do Windows.
  • Cada TWindow/TControl possui um DATA lUnicode que herda da configuração global.
  • TClipBoard detecta automaticamente texto UTF-8 e usa o formato CF_UNICODETEXT.
  • Controles SAY, campos GET, menus e caixas de mensagem suportam texto Unicode.

Referência de Funções

FunçãoDescrição
FW_SetUnicode( [lOnOff] )Define ou obtém o modo Unicode. Chame com .T. para ativar, .F. para desativar. Chame sem parâmetro para consultar o estado atual.
FW_IsUTF8( cStr )Retorna .T. se a string contiver sequências multi-byte UTF-8 válidas.

Exemplo: Ativar Unicode

function Main()
   // Enable Unicode BEFORE creating any windows
   FW_SetUnicode( .T. )

   local oWnd
   DEFINE WINDOW oWnd TITLE "Unicode Demo"

   // These will display correctly in Unicode mode:
   @ 1, 1 SAY "English: Hello World" OF oWnd
   @ 2, 1 SAY "Chinese: " + Chr(20320) + Chr(22909) OF oWnd
   @ 3, 1 SAY "Japanese: " + Chr(12371) + Chr(12435) + Chr(12395) + Chr(12385) + Chr(12399) OF oWnd
   @ 4, 1 SAY "Arabic: " + Chr(1605) + Chr(1585) + Chr(1581) + Chr(1576) + Chr(1575) OF oWnd

   ACTIVATE WINDOW oWnd

return nil

Funções Utilitárias UTF-8

Ao trabalhar no modo Unicode, as strings no Harbour são armazenadas como UTF-8. O FiveWin fornece funções auxiliares para manipulação de strings UTF-8 que tratam corretamente caracteres multi-byte.

Funções de String UTF-8

FunçãoDescrição
FW_UTF8LEFT( cStr, nLeft )Retorna os nLeft caracteres mais à esquerda (não bytes) de uma string UTF-8.
FW_UTF8RIGHT( cStr, nLen )Retorna os nLen caracteres mais à direita de uma string UTF-8.
FW_UTF8SUBSTR( cStr, nPos, nLen )Extrai uma substring por posição de caractere (não posição de byte).
FW_UTF8STUFF( cSrc, nPos, nDelete, cInsert )Insere/substitui caracteres em uma string UTF-8 por posição de caractere.
FW_UTF8PADCHAR( cStr, nChars )Preenche uma string UTF-8 até nChars caracteres.
FW_UTF8PADBYTE( cText, nBytes )Preenche uma string UTF-8 até nBytes bytes totais.

Por Que as Funções UTF-8 São Necessárias

As funções padrão de string do Harbour (Left, Right, SubStr, Len) operam em bytes, não em caracteres. Um único caractere Unicode em UTF-8 pode ter de 1 a 4 bytes. Usar Left( cUTF8, 3 ) pode cortar um caractere multi-byte ao meio, produzindo texto ilegível. Use FW_UTF8LEFT( cUTF8, 3 ) para obter exatamente 3 caracteres, independentemente do tamanho em bytes.

// Example: UTF-8 character-safe operations
local cText := "Hello"  // Mixed ASCII + multi-byte

// WRONG: may split multi-byte characters
// local cFirst := Left( cText, 3 )

// CORRECT: character-aware substring
local cFirst := FW_UTF8LEFT( cText, 3 )
local cLast  := FW_UTF8RIGHT( cText, 2 )
local cMid   := FW_UTF8SUBSTR( cText, 2, 3 )

Codificação OEM vs ANSI vs UTF-8

Compreender os três sistemas de codificação é fundamental para a exibição correta de texto em aplicações FiveWin, especialmente ao misturar saída de console, interface gráfica do Windows e E/S de arquivos.

Visão Geral das Codificações

CodificaçãoQuando UsadaDescrição
OEM (DOS)Saída de console, arquivos DBF, dados legadosO conjunto de caracteres original do IBM PC (CP437, CP850, etc.). Caracteres acima de 127 são desenhos de linha e caracteres acentuados específicos da codepage.
ANSI (Windows)Controles do Windows, funções da API "A"Windows-1252 ou codepage específica da localidade. Caracteres acima de 127 incluem letras acentuadas para idiomas da Europa Ocidental.
UTF-8Modo Unicode, dados modernos, web/JSONCodificação de comprimento variável (1-4 bytes por caractere). Compatível com ASCII para caracteres 0-127. Usado com funções da API "W" (convertido para UTF-16).

Funções de Conversão

FunçãoDeParaObservações
hb_oemToAnsi( cStr )OEMANSIFunção nativa do Harbour. Converte dados DOS/DBF para exibição no Windows.
hb_AnsiToOem( cStr )ANSIOEMFunção nativa do Harbour. Converte texto Windows para armazenamento em DBF.

utf8toutf16( cStr )UTF-8UTF-16LEPara chamadas de API "W" do Windows. Usado internamente pelo modo Unicode do FiveWin.

Quando Usar Cada Codificação

  • Leitura de arquivos DBF: Os dados são tipicamente codificados em OEM. Para exibir em um controle SAY ou GET no modo não-Unicode, use hb_oemToAnsi(). No modo Unicode, converta via hb_oemToAnsi() e depois hb_StrToUTF8().
  • Exibição em controles do Windows: No modo ANSI (padrão), os controles esperam strings ANSI. No modo Unicode (FW_SetUnicode(.T.)), os controles aceitam UTF-8, que o FiveWin converte para UTF-16 internamente.
  • Dados de API REST / JSON: Sempre UTF-8. Para exibir no FiveWin sem Unicode, converta para ANSI primeiro. No modo Unicode, use diretamente.
  • MsgInfo / MsgAlert: Estas funções usam a configuração Unicode da janela. No modo Unicode, passe strings UTF-8. No modo ANSI, passe strings ANSI.
  • Gravação em arquivos: Escolha a codificação com base no destino: OEM para compatibilidade com DBF, UTF-8 para intercâmbio moderno, ANSI para arquivos legados do Windows.

Considerações sobre Codepage

// Set Harbour codepage for proper OEM/ANSI conversion
REQUEST HB_CODEPAGE_ESWIN   // Spanish Windows codepage
HB_CDPSELECT( "ESWIN" )     // Select it

// Or for French:
REQUEST HB_CODEPAGE_FRWIN
HB_CDPSELECT( "FRWIN" )

// Harbour language selection (affects date formats, error messages)
REQUEST HB_LANG_ES
HB_LANGSELECT( "ES" )

Aplicação Multi-Idioma Completa

Este exemplo mostra uma aplicação completa com um seletor de idioma que alterna dinamicamente o idioma da interface para todos os controles do FiveWin e strings personalizadas.

#include "FiveWin.ch"

static oWnd, oBar, oBtnSave, oBtnPrint, oSayStatus

function Main()

   // Enable Unicode for full character support
   FW_SetUnicode( .T. )

   // Add application-specific translations
   FWAddString( { ;
      { "My Application",  "Mi Aplicacion",     "Mon Application",   "Meu Aplicativo",     "Meine Anwendung",    "Mia Applicazione" }, ;
      { "Customer List",   "Lista de Clientes", "Liste des Clients", "Lista de Clientes",  "Kundenliste",        "Lista Clienti" }, ;
      { "New Customer",    "Nuevo Cliente",     "Nouveau Client",    "Novo Cliente",        "Neuer Kunde",        "Nuovo Cliente" }, ;
      { "Save Record",     "Guardar Registro",  "Enregistrer",       "Salvar Registro",     "Datensatz Speichern","Salva Record" }, ;
      { "Print Report",    "Imprimir Reporte",  "Imprimer Rapport",  "Imprimir Relatorio",  "Bericht Drucken",    "Stampa Report" }, ;
      { "Language",        "Idioma",            "Langue",            "Idioma",              "Sprache",            "Lingua" }, ;
      { "Ready",           "Listo",             "Pret",              "Pronto",              "Bereit",             "Pronto" } ;
   } )

   // Default to English
   FWSetLanguage( 1 )

   DEFINE WINDOW oWnd TITLE FWString( "My Application" )

   BuildUI()

   ACTIVATE WINDOW oWnd

return nil

//------------------------------------------------------------//

function BuildUI()

   // Toolbar / button bar
   @ 1, 1 BUTTON oBtnSave PROMPT FWString( "Save Record" ) OF oWnd ;
      SIZE 120, 28 ACTION MsgInfo( FWString( "Save Record" ) )

   @ 1, 16 BUTTON oBtnPrint PROMPT FWString( "Print Report" ) OF oWnd ;
      SIZE 120, 28 ACTION MsgInfo( FWString( "Print Report" ) )

   // Language selector
   @ 1, 32 BUTTON PROMPT FWString( "Language" ) OF oWnd ;
      SIZE 100, 28 ACTION SelectLanguage()

   // Status
   @ 4, 1 SAY oSayStatus PROMPT FWString( "Ready" ) OF oWnd SIZE 300, 20

return nil

//------------------------------------------------------------//

function SelectLanguage()
   local aLangs := { "English", "Espanol", "Francais", "Portugues", "Deutsch", "Italiano" }
   local nChoice := 0

   nChoice := Alert( FWString( "Language" ), aLangs )

   if nChoice > 0
      FWSetLanguage( nChoice )
      RefreshUI()
   endif

return nil

//------------------------------------------------------------//

function RefreshUI()

   // Update window title
   oWnd:SetText( FWString( "My Application" ) )

   // Update button captions
   oBtnSave:SetText( FWString( "Save Record" ) )
   oBtnPrint:SetText( FWString( "Print Report" ) )

   // Update status
   oSayStatus:SetText( FWString( "Ready" ) )

return nil

Adicionando Traduções Personalizadas via Arquivo INI

Para aplicações maiores ou quando as traduções são gerenciadas por não-desenvolvedores, use um arquivo INI para armazenar traduções que são carregadas na inicialização.

Passo 1: Criar o arquivo de traduções

; File: translations.ini
; Format: n=English|Spanish|French|Portuguese|German|Italian

[strings]
1=Customer|Cliente|Client|Cliente|Kunde|Cliente
2=Invoice|Factura|Facture|Fatura|Rechnung|Fattura
3=Product|Producto|Produit|Produto|Produkt|Prodotto
4=Total Amount|Importe Total|Montant Total|Valor Total|Gesamtbetrag|Importo Totale
5=Due Date|Vencimiento|Echeance|Vencimento|Faelligkeit|Scadenza
6=Payment|Pago|Paiement|Pagamento|Zahlung|Pagamento
7=Discount|Descuento|Remise|Desconto|Rabatt|Sconto
8=Tax|Impuesto|Taxe|Imposto|Steuer|Imposta
9=Shipping|Envio|Expedition|Envio|Versand|Spedizione
10=Notes|Notas|Notes|Notas|Anmerkungen|Note

Passo 2: Carregar na inicialização da aplicação

function Main()
   // Load custom translations
   FWLoadStrings( cFilePath( GetModuleFileName( GetInstance() ) ) + "translations.ini" )

   // Set language (could be read from user preferences)
   local oIni := TIni():New( "myapp.ini" )
   local nLang := oIni:Get( "Settings", "Language", 1 )
   FWSetLanguage( nLang )

   // All FWString() calls now return the correct language
   MsgInfo( FWString( "Customer" ) + ": John Doe" )
   // In Spanish: "Cliente: John Doe"

return nil

Passo 3: Salvar preferência de idioma quando o usuário a altera

function ChangeLanguage( nNewLang )
   local oIni := TIni():New( "myapp.ini" )

   FWSetLanguage( nNewLang )
   oIni:Set( "Settings", "Language", nNewLang )

   // Refresh all visible UI elements
   RefreshAllWindows()

return nil

Encontrando Traduções Ausentes

Durante o desenvolvimento, use FWMissingStrings() para descobrir quais strings na sua aplicação não possuem tradução.

// At the end of a test run:
function CheckTranslations()
   local aMissing

   // Set to a non-English language to trigger lookups
   FWSetLanguage( 2 )   // Spanish

   // ... run through your application UI ...

   // Check what's missing
   aMissing := FWMissingStrings()

   // This writes "missing.str" with ready-to-paste code:
   // FWSetString( nLang, { ;

   //    ...
   // } )

   ? "Missing translations:", Len( aMissing )

return nil

Boas Práticas

1. Sempre use FWString() para textos visíveis ao usuário

// GOOD: translatable
@ 1, 1 SAY FWString( "Customer" ) OF oDlg
MsgInfo( FWString( "Record saved successfully" ) )

// BAD: hard-coded, not translatable
@ 1, 1 SAY "Customer" OF oDlg
MsgInfo( "Record saved successfully" )

2. Ative o Unicode cedo

// Call FW_SetUnicode(.T.) BEFORE creating any windows
function Main()
   FW_SetUnicode( .T. )  // First thing!
   // ... create windows after this
return nil

3. Use a codepage correta para seus dados

// For applications using DBF with accented characters:
REQUEST HB_CODEPAGE_ESWIN
HB_CDPSELECT( "ESWIN" )

// For UTF-8 data (JSON, REST APIs, modern databases):
FW_SetUnicode( .T. )

4. Trate a codificação nas fronteiras de dados

// Reading from DBF (OEM) to display in Unicode window:
local cName := Customers->Name              // OEM encoded
cName := hb_oemToAnsi( cName )              // Convert to ANSI
// In Unicode mode, FiveWin handles ANSI->UTF-16 automatically

// Reading from JSON API (UTF-8):
local cData := hb_jsonDecode( cResponse )    // Already UTF-8
// In Unicode mode, display directly
// In ANSI mode: cData := hb_UTF8ToStr( cData )

5. Teste com scripts não-latinos

Ao construir aplicações internacionais, teste com texto em chinês, árabe ou cirílico para verificar se o modo Unicode está devidamente habilitado e se todos os controles exibem corretamente. Preste atenção especial a:

  • Campos GET (o comprimento de entrada pode diferir da largura de exibição com caracteres multi-byte)
  • Larguras de colunas no XBrowse (o dimensionamento automático pode precisar de ajuste)
  • Saída de impressão (certifique-se de que a fonte selecionada suporta os caracteres necessários)
  • E/S de arquivos (salve como UTF-8, não ANSI, se os dados contiverem caracteres não-latinos)
