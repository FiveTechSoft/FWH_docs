TParser - Máquina de Análise Dinâmica

Fonte: source/classes/tparser.prg

TParser é um esqueleto genérico de motor de regras gramaticais. Ele mantém uma lista de regras de produção e uma pilha de estados. As regras consistem em um símbolo não terminal, um array de tokens e um bloco de código de ação. Esta classe fornece a estrutura para construir analisadores de expressões, interpretadores de comandos ou processadores de linguagens específicas de domínio.

Principais Membros DATA

DATATipoDescrição
aRulesArrayArray de regras gramaticais, cada uma { cNonTerminal, aTokens, bAction }
aStatesArrayPilha de estados para análise; o estado 0 está vazio por padrão

Métodos Principais

MétodoDescrição
New()Cria um novo analisador com regras vazias e estado inicial
Add( cNonTerminal, aTokens, bAction )Adiciona uma regra de produção: não terminal -> sequência de tokens com ação

Exemplo: Adicionar Regras Gramaticais

#include "FiveWin.ch"

function Main()

   local oParser := TParser():New()

   // expr -> number
   oParser:Add( "expr", { "number" }, {|n| n } )

   // expr -> expr + expr
   oParser:Add( "expr", { "expr", "+", "expr" }, {|a,b| a + b } )

   // expr -> expr * expr
   oParser:Add( "expr", { "expr", "*", "expr" }, {|a,b| a * b } )

   // Acessa as regras
   ? Len( oParser:aRules )   // 3 regras adicionadas

return nil

Notas

  • TParser é uma classe esqueleto. O método central Add() constrói a tabela de regras; você deve implementar o tokenizador e o algoritmo de análise (shift-reduce, descida recursiva, etc.) por conta própria usando os dados aRules e aStates.
  • O array aTokens de cada regra define a sequência de tokens esperada; o bloco bAction é a ação semântica disparada quando a regra corresponde.
  • aStates começa com um único estado vazio (índice 0). Os estados podem ser empilhados/desempilhados durante a análise para lidar com construções aninhadas.
