TComObject

Fonte: source/classes/tcomobj.prg

Standalone class

TComObject provides a generic wrapper around Windows COM (Component Object Model) objects via the IDispatch interface. It stores the nIDispatch pointer and exposes methods to invoke COM methods, get/set properties, and auto-wrap returned IDispatch pointers. The class supports chained COM calls through its error handler: property names prefixed with _ set values, bare property names get values, and IDispatch return values are automatically wrapped in new TComObject instances.

Key DATA Members

DATATypeDescription
nIDispatchNumericPointer to the COM IDispatch interface

Methods

MethodDescription
New( cProgID )Create a COM object from a ProgID string (e.g. "Word.Application")
Invoke( cMethod, u1, u2, u3 )Invoke a COM method with up to three optional parameters
End()Release the COM object and free the IDispatch pointer
ClassName()Return the Harbour class name ("TComObject")

Example: Word Automation

#include "FiveWin.ch"

function Main()

   local oWord, oDoc

   // Create Word Application COM object
   oWord := TComObject():New( "Word.Application" )

   // Set property (prefix with _)
   oWord:_Visible := .T.

   // Access documents collection (returns auto-wrapped TComObject)
   oDoc := oWord:Documents

   // Add a new document
   oDoc:Add()

   // Invoke methods
   oWord:Invoke( "Activate" )

   // Set content
   oWord:Selection:TypeText( "Hello from FiveWin!" )

   MsgInfo( "Word is running. Press OK to close." )

   // Clean up
   oWord:Quit()
   oWord:End()

return nil

Notes

  • The error handler (Error()) is the core of TComObject's convenience. When you access a property without the underscore prefix, it calls IDispatch::GetIDsOfNames and Invoke with DISPATCH_PROPERTYGET. If the return value is another IDispatch pointer, it is auto-wrapped in a new TComObject, enabling chained navigation like oWord:Selection:Text.
  • Setting a property requires the underscore prefix (e.g. oWord:_Visible := .T.), which triggers DISPATCH_PROPERTYPUT.
  • Use Invoke() for methods that need explicit control over parameters, or when the auto-wrap behavior does not apply.
  • Always call End() to release the COM interface pointer and avoid resource leaks.
  • Requires the Windows COM subsystem (OLE32.dll). Works on all 32-bit and 64-bit Windows platforms.
