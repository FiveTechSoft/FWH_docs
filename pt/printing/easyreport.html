EasyReport

Fonte: source/classes/esreport.prg (motor FW_EReport), source/classes/tereport.prg (designer visual TEReport), include/easyrep.ch (comandos)

EasyReport é um designer visual WYSIWYG de relatórios totalmente integrado ao FiveWin para Harbour (FWH). Originalmente criado por Timm Sodtalbers sob o nome VRD (Visual Report Designer) entre 2000 e 2004, foi adotado e aprimorado pela FiveTech Software. O EasyReport permite que usuários finais projetem, editem e imprimam relatórios visualmente sem escrever uma única linha de código, enquanto os desenvolvedores mantêm controle programático completo sobre a vinculação de dados e a saída.

Os relatórios são armazenados como arquivos .vrd no estilo INI com arquivos de área complementares (.v01, .v02, etc.). O motor lê essas definições em tempo de execução e renderiza a saída através da classe TPrinter do FWH, suportando pré-visualização de impressão, impressão direta e saída em PDF.

Arquitetura

graph LR A[".vrd Report File"] --> B["FW_EReport Engine"] B --> C["TPrinter"] C --> D["Print Preview"] C --> E["Physical Printer"] C --> F["PDF Output"] G["TEReport Designer"] --> A

O fluxo de trabalho é simples: o designer visual (TEReport) cria e edita arquivos de definição de relatórios .vrd. No momento da impressão, o motor FW_EReport lê o arquivo .vrd, processa as áreas e itens do relatório, e renderiza tudo através do TPrinter. A saída pode ir para pré-visualização, uma impressora física ou um arquivo PDF.

Comandos

Todos os comandos estão definidos em include/easyrep.ch. Inclua-o com #include "EasyRep.ch".

EASYREPORT

EASYREPORT oVRD NAME cReportFile ;
   [ PREVIEW lPreview ] ;
   [ TO cPrinter ] ;
   [ OF oWnd ] ;
   [ MODAL ] ;
   [ PRINTIDS ] ;
   [ NOPRINT ] ;
   [ NOEXPR ] ;
   [ CHECK lCheck ] ;
   [ AREAPATH cAreaPath ] ;
   [ PRINTDIALOG lPrintDialog ] ;
   [ COPIES nCopies ] ;
   [ PRINTOBJECT oPrn ] ;
   [ PAPERSIZE aSize ] ;
   [ FILE cFile ]

Abre um arquivo de relatório e cria um objeto FW_EReport. Este é o comando inicial para qualquer trabalho de impressão com EasyReport.

CláusulaDescrição
NAME cReportFileCaminho para o arquivo de relatório .vrd (obrigatório)
PREVIEW lPreviewMostrar pré-visualização em vez de enviar para a impressora
TO cPrinterNome da impressora de destino
OF oWndJanela pai
MODALJanela de pré-visualização modal
PRINTIDSImprimir os IDs dos itens no relatório (para depuração)
NOPRINTNão imprimir de fato (execução simulada)
NOEXPRNão avaliar expressões nos itens do relatório
PRINTDIALOG lPrintDialogMostrar a caixa de diálogo de impressão do Windows
COPIES nCopiesNúmero de cópias a imprimir
PRINTOBJECT oPrnUsar um objeto TPrinter existente
PAPERSIZE aSizeArray de tamanho de papel personalizado
FILE cFileCaminho do arquivo de saída (para PDF)

PRINTAREA

PRINTAREA nArea OF oVRD ;
   [ ONLYINIT ] ;
   [ ITEMIDS aIDs ] ;
   [ ITEMVALUES aStrings ] ;
   [ PAGEBREAK ]

Imprime uma área do relatório. Use ITEMIDS e ITEMVALUES para fornecer dados a itens específicos dentro da área. Chame-o dentro de um loop DO WHILE para áreas de detalhe.

PRINTITEM

PRINTITEM nItemID AREA nArea ;
   [ VALUE cTextOrImage ] ;
   OF oVRD ;
   [ ENTRY nEntry ]

Imprime um item individual dentro de uma área. Útil quando você precisa de controle detalhado sobre itens individuais.

PRITEMLIST

PRITEMLIST AREA nArea OF oVRD ;
   ITEMIDS aIDs ITEMVALUES aStrings

Imprime uma lista de itens dentro de uma área, associando IDs a valores.

Outros Comandos

PRINTREST AREA nArea OF oVRD      // Print remaining items of an area

PAGEBREAK oVRD                    // Force a page break

END EASYREPORT oVRD               // End the report and finalize output

ER QUICK (Impressão Rápida)

ER QUICK oVRD NAME cReportFile ;
   [ PREVIEW lPreview ] ;
   [ TO cPrinter ] ;
   [ OF oWnd ] ;
   [ MODAL ] ;
   [ PRINTDIALOG lPrintDialog ] ;
   [ COPIES nCopies ] ;
   [ ACTION uAction ]

Um comando de atalho que chama FWER_PrReport() para abrir, preencher e fechar um relatório em um único comando. A cláusula ACTION recebe o objeto oVRD como parâmetro de bloco de código.

Áreas do Relatório

Um relatório EasyReport é dividido em até seis áreas lógicas. Cada área tem seu próprio arquivo INI (ex., .v01, .v02) e contém itens (texto, imagens, códigos de barras, caixas, linhas, etc.).

graph TB A["Area 1: Report Header
Printed once at the very top"] --> B B["Area 2: Page Header
Printed at the top of every page"] --> C C["Area 3: Detail
Repeated for each data record"] --> D D["Area 4: Detail Variable
Variable-height detail content (memos)"] --> E E["Area 5: Page Footer
Printed at the bottom of every page"] --> F F["Area 6: Report Footer
Printed once at the very end"]
ÁreaNomeUso Típico
1Cabeçalho do RelatórioLogo da empresa, título do relatório, data. Impresso uma vez na primeira página.
2Cabeçalho de PáginaCabeçalhos de colunas, número da página. Impresso no topo de cada página.
3DetalheLinhas de dados. Repetido para cada registro do conjunto de dados.
4Detalhe VariávelConteúdo de altura variável como campos memo, notas, descrições.
5Rodapé de PáginaTotais da página, números de página. Impresso na parte inferior de cada página.
6Rodapé do RelatórioTotais gerais, assinaturas. Impresso uma vez no final.

Cada item dentro de uma área tem um ID numérico único (ex., 101, 102, 301). Ao imprimir programaticamente, você referencia os itens por esses IDs usando os arrays ITEMIDS e ITEMVALUES.

Designer Visual (TEReport)

O designer visual é uma aplicação MDI completa que permite aos usuários criar e editar definições de relatórios. Execute-o chamando EReport() ou adicionando um botão de menu/barra de ferramentas em sua aplicação.

A interface do designer oferece:

  • Painel de áreas -- exibe todas as áreas do relatório com seus limites, arraste para redimensionar
  • Painel de itens -- adicione rótulos de texto, campos, imagens, códigos de barras, linhas, caixas a qualquer área
  • Painel de propriedades -- configure fonte, cor, alinhamento, posição, tamanho, expressões para cada item
  • Régua -- régua visual para posicionamento preciso (mm ou polegadas)
  • Pré-visualização -- pré-visualização instantânea do layout do relatório
  • Desfazer/Refazer -- suporte completo de desfazer e refazer para todas as alterações
  • Integração com banco de dados -- defina conexões de banco de dados e mapeamentos de campos dentro do designer
  • Configurações gerais -- tamanho do papel, orientação, margens, fontes, idioma

O designer suporta a criação de novos relatórios do zero, abertura de arquivos .vrd existentes, e salvamento no formato padrão do EasyReport. Também oferece funcionalidade de backup e "Salvar Como".

O EasyReport armazena os relatórios como um conjunto de arquivos de texto no estilo INI:

Exemplo: Relatório Simples a partir de DBF

#include "FiveWin.ch"
#include "EasyRep.ch"

function PrintClients( lPreview, oWnd )

   local oVRD

   USE clients

   // Open the report with preview
   EASYREPORT oVRD NAME ".\reports\clients.vrd" ;
              PREVIEW lPreview OF oWnd

   // Loop through records and print Detail area (area 3)
   DO WHILE ! Eof()
      PRINTAREA 3 OF oVRD ;
         ITEMIDS    { 101, 102, 103 } ;
         ITEMVALUES { clients->name, clients->city, clients->phone }
      SKIP
   ENDDO

   // Finalize the report
   END EASYREPORT oVRD

   USE

return nil

O array ITEMIDS contém os IDs numéricos atribuídos aos itens no designer visual. O array ITEMVALUES fornece os valores de dados correspondentes. O motor os associa por posição: o item 101 recebe o primeiro valor, o item 102 recebe o segundo, e assim por diante.

Exemplo: Formulário de Pedido com Quebras de Página

Este exemplo de samples/EasyReport/examples/SourceExample1.prg demonstra um formulário de pedido completo com cabeçalho, linhas de detalhe, conteúdo memo, quebras de página automáticas e um rodapé com totais.

// EasyReport: Order form

FUNCTION PrintOrder( lPreview )

   LOCAL i, nTotal, nVAT, oVRD, lLastPosition

   // Open the report
   EASYREPORT oVRD NAME ".\examples\EasyReportExample1.vrd" ;
              PREVIEW lPreview OF oWnd ;
              PRINTDIALOG IIF( lPreview, .F., .T. )

   IF oVRD:lDialogCancel = .T.
      RETURN .F.
   ENDIF

   // Set header data using Cargo array
   oVRD:Cargo := { "Nr. 12345  Date: 5.9.2004", ;   // 1 order number
                   "Testclient",               ;     // 2 address line 1
                   "z.H.: Timm Sodtalbers",    ;     // 3 address line 2
                   "Plaggefelder Str. 42",     ;     // 4 address line 3
                   "26632 Ihlow",              ;     // 5 address line 4
                   "257001",                   ;     // 6 barcode value
                   "Company Name" + CRLF + ;         // 7 company memo
                      "Street 42" + CRLF + "City", ;
                   MemoRead( ".\examples\EasyReportExample.txt" ) }

   // Open database and print order line items
   USE .\EXAMPLES\EXAMPLE
   nTotal := 0

   DO WHILE ! Eof()

      // Print detail area with item data
      PRINTAREA 3 OF oVRD ;
         ITEMIDS    { 104, 105, 106, 107 } ;
         ITEMVALUES { EXAMPLE->UNIT,                             ;
                      AllTrim( Str( EXAMPLE->PRICE, 10, 2 ) ),   ;
                      AllTrim( Str( EXAMPLE->TOTALPRICE, 11, 2 )),;
                      AllTrim( ".\EXAMPLES\" + EXAMPLE->IMAGE ) }

      nTotal += EXAMPLE->TOTALPRICE

      // Check if page break is needed before next record
      IF oVRD:nNextRow > oVRD:nPageBreak
         PAGEBREAK oVRD
      ENDIF

      SKIP

   ENDDO

   CLOSE

   // Print footer with totals
   nVAT := nTotal * 0.16
   AAdd( oVRD:Cargo, AllTrim( Str( nTotal,        12, 2 ) ) )  //  9
   AAdd( oVRD:Cargo, AllTrim( Str( nVAT,          12, 2 ) ) )  // 10
   AAdd( oVRD:Cargo, AllTrim( Str( nTotal + nVAT, 12, 2 ) ) )  // 11

   PRINTAREA 5 OF oVRD

   END EASYREPORT oVRD

RETURN .T.

Lógica de Quebra de Página

Ao imprimir registros de detalhe em um loop, frequentemente você precisa verificar se a próxima área caberá na página atual. Use oVRD:nNextRow e oVRD:nPageBreak junto com oVRD:aAreaHeight para controle preciso: 

DO WHILE ! Eof()

   // Check if detail area (3) will fit, considering the footer area (5)
   IF oVRD:nNextRow + oVRD:aAreaHeight[3] > ;
      oVRD:nPageBreak - oVRD:aAreaHeight[5]
      PAGEBREAK oVRD
   ENDIF

   PRINTAREA 3 OF oVRD ;
      ITEMIDS { 101, 102 } ;
      ITEMVALUES { field->name, field->value }

   SKIP

ENDDO

Dicas e Melhores Práticas

Fluxo de Trabalho de Design

  1. Comece abrindo o designer com EReport() e criando um novo relatório.
  2. Defina o tamanho do papel, orientação e margens nas Configurações Gerais.
  3. Adicione áreas (cabeçalho, cabeçalho de página, detalhe, rodapé) conforme necessário.
  4. Posicione itens em cada área e atribua IDs numéricos aos itens que receberão dados programaticamente.
  5. Salve o arquivo .vrd e anote os IDs dos itens.
  6. Escreva código usando os comandos EASYREPORT / PRINTAREA / END EASYREPORT, associando os IDs aos dados.
  7. Teste com PREVIEW .T. antes de enviar para uma impressora física.

Dicas Gerais

  • Sempre verifique oVRD:lDialogCancel após abrir um relatório com PRINTDIALOG -- o usuário pode ter cancelado.
  • Use oVRD:Cargo para passar dados estáticos (endereços, títulos, datas) e ITEMIDS/ITEMVALUES para dados dinâmicos por registro.
  • Para campos memo, use oVRD:Cargo2 e imprima-os na Área 4 (Detalhe Variável) para dimensionamento automático.
  • Implemente verificações de quebra de página antes de imprimir cada registro de detalhe para evitar que itens sejam cortados no limite da página.
  • Use PRINTIDS durante o desenvolvimento para ver os IDs dos itens impressos no relatório, facilitando o mapeamento de IDs em seu código.
  • O parâmetro lCheck permite uma execução simulada para calcular o total de páginas antes da impressão real, útil para rodapés "Página X de Y".
  • Os arquivos de relatório (.vrd e .v0x) são arquivos INI de texto puro -- podem ser versionados e comparados.
  • Distribua os arquivos de relatório com sua aplicação e permita que usuários finais personalizem os layouts usando o designer sem recompilar.

Compatibilidade com Versões Anteriores

Os nomes de classe VRD originais são suportados através de traduções do pré-processador em easyrep.ch: 

#xtranslate VRD()                        => FW_EReport()
#xtranslate VRD_PrReport( [<params,...>] ) => FWER_PrReport( <params> )
#xtranslate VRDITEM()                    => FWER_Item()
#xtranslate VRDBARCODE()                 => FWER_BarCode()

O código existente que usa a convenção de nomes VRD anterior continuará funcionando sem alterações.
