Sistema de Erros

Fonte: source/function/errsysw.prg

O FiveWin substitui o manipulador de erros padrão do Harbour por um diálogo de erro baseado em GUI que exibe informações diagnósticas detalhadas. O sistema de erros é inicializado automaticamente na inicialização da aplicação através do procedimento ErrorSys(), que define um bloco de erro chamando ErrorDialog().

Tratamento Automático de Erros

Certos tipos de erro são tratados automaticamente sem exibir o diálogo de erro:

ErrogenCodeAção Automática
Divisão por zeroEG_ZERODIVRetorna 0 silenciosamente
Erro de abertura de rede (código SO 32 ou 5)EG_OPENDefine NetErr(.T.), retorna .F.
Erro de bloqueio appendEG_APPENDLOCKDefine NetErr(.T.), retorna .F.
Erro recursivo (7+ níveis de profundidade)qualquerForça QUIT para prevenir loop infinito

Diálogo de Erro

O diálogo de erro do FiveWin é um diálogo moderno e rico em recursos que se adapta ao tema do sistema:

  • Detecção automática de modo escuro -- o diálogo lê a chave do registro "AppsUseLightTheme" do Windows e ajusta seu esquema de cores de acordo
  • Mensagem de erro -- exibida de forma proeminente no topo
  • Pilha de chamadas -- mostrada em um listbox com nomes de procedimentos, números de linha e arquivos fonte
  • Botões de ação:
    • Sair -- grava error.log e encerra
    • Tentar Novamente -- retorna .T. (se e:canRetry)
    • Padrão -- retorna .F. (se e:canDefault)
    • Depurar -- ativa o depurador (se disponível)
  • Botão Copiar -- copia o log de erro completo para a área de transferência
  • Botão Ver -- abre error.log no Bloco de Notas

Personalizando o Sistema de Erros

SetErrorPath() / SetErrorFileName()

// Alterar a localização do log de erros
SetErrorPath( "C:\logs\" )
SetErrorFileName( "myapp_error.log" )

SetErrorDialog() -- Diálogo Personalizado

// Substituir todo o diálogo de erro por um personalizado
SetErrorDialog( { |oDlg, e, cLog, aStack|
   // oDlg é o diálogo sendo criado
   // e é o objeto de erro
   // cLog é o texto do log de erro
   // aStack é o array da pilha de chamadas
   // Retorno: nil (usar botões padrão) ou tratar os botões você mesmo
} )

SetPostErrorAction() -- Gancho Pós-Erro

// Executar código após o diálogo de erro ser fechado
SetPostErrorAction( { |e, cLog|
   // Enviar relatório de erro ao servidor
   SendErrorReport( cLog )
   // ou reiniciar a aplicação
   // WinExec( GetModuleFileName( GetInstance() ) )
} )

ErrorBlock Personalizado

// Substituir completamente o manipulador de erros
ErrorBlock( { |e| MyErrorHandler( e ) } )

static function MyErrorHandler( e )

   // Registrar em arquivo
   LogFile( "errors.log", { e:Description, e:Operation, ;
      ProcName(4), ProcLine(4) } )

   // Mostrar mensagem simples
   MsgStop( e:Description + CRLF + ;
      "em " + ProcName(4) + "(" + LTrim( Str( ProcLine(4) ) ) + ")" )

   // Encerrar a aplicação
   PostQuitMessage( 0 )
   __Quit()

return nil

Exemplo: Blocos TRY/CATCH

#include "FiveWin.ch"

function Main()

   local xResult

   // TRY/CATCH impede que o diálogo de erro seja exibido
   TRY
      xResult := SomeRiskyOperation()
      MsgInfo( "Resultado: " + cValToChar( xResult ) )
   CATCH e
      MsgAlert( "Erro: " + e:Description + CRLF + ;
         "Operação: " + e:Operation )
   END

return nil

Exemplo: Manipulador de Erro Personalizado com Email

#include "FiveWin.ch"

function Main()

   // Instalar ação pós-erro personalizada
   SetPostErrorAction( { |e, cLog|
      // Salvar log de erro
      MemoWrit( "crash_" + DToS( Date() ) + "_" + StrTran( Time(), ":", "" ) + ".log", cLog )

      // Poderia enviar notificação por email aqui
      // SendMail( "admin@company.com", "App Crash", cLog )
   } )

   // Alterar localização do log de erros
   SetErrorPath( "C:\logs\" )
   SetErrorFileName( "app_errors.log" )

   // ... resto da aplicação ...
   AppMain()

return nil

Propriedades do Objeto de Erro

O objeto de erro e passado ao manipulador de erros é um objeto Error padrão do Harbour:

PropriedadeTipoDescrição
e:DescriptionCharacterDescrição legível do erro
e:OperationCharacterA operação que causou o erro
e:SubSystemCharacterNome do subsistema (BASE, DBCMD, etc.)
e:genCodeNumericCódigo genérico de erro (EG_*)
e:subCodeNumericCódigo de erro específico do subsistema
e:osCodeNumericCódigo de erro do sistema operacional
e:ArgsArrayArgumentos que causaram o erro
e:canRetryLogicalSe é possível tentar novamente
e:canDefaultLogicalSe a ação padrão é possível
e:canSubstituteLogicalSe um valor substituto pode ser retornado
e:FileNameCharacterArquivo que causou o erro (se aplicável)

Suporte Multi-Idioma

O diálogo de erro usa FWString() para todo o texto visível ao usuário, então ele se adapta automaticamente ao idioma definido por FWSetLanguage(). As strings suportadas incluem "Application", "Path and name", "Date", "Time", descrições de erro e rótulos dos botões.
