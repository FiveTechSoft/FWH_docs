TWebView2

Source: source/classes/twebview2.prg

Overview

TWebView2 embeds Microsoft Edge WebView2 in a FiveWin window or dialog. Use it to host modern HTML/CSS/JS UIs next to native FWH controls. Requires the WebView2 Runtime (Evergreen or Fixed Version).

Desktop + Web with one UI

Sample samples/DesktopWeb/login.prg shows a full pattern where desktop and browser share the same HTML/CSS/JS:

  • An embedded multi-thread HTTP server listens on port 8080 and serves login + dashboard pages generated in Harbour.
  • The desktop shell creates TWebView2 and Navigate("http://localhost:8080/").
  • Any browser opens the same URL and gets the identical UI and API.
  • Credential validation runs in PRG (ValidateLogin), not in JavaScript. Sessions use cookie DWSESS.
// Desktop shell (simplified)
StartHttpServer( 8080 )
oWeb := TWebView2():New()
oWeb:Navigate( "http://localhost:8080/" )
oWeb:Run()

Build with multi-thread VM: samples\DesktopWeb\build.bat or build_new.bat login hm64 -mt. Demo users: admin/1234, demo/demo.

FWH 26.09

The extended API, including bOnConsole and EnableConsole, is available from FWH 26.09, day 12 (12 September 2026). These are FWH library features, not features supplied by merely updating the Microsoft Runtime. Older libraries may lack the DATA setter _BONCONSOLE and the EnableConsole method.

JavaScript console

EnableConsole(.T.) wraps console.log/warn/error/info without removing the original console output and adds a JavaScript error listener. It sends an internal envelope through SendToFWH; bOnConsole receives the inner JSON string, not the outer envelope. args contains strings: objects are JSON-stringified. line is present for window error events, and is absent for ordinary console calls.

Call EnableConsole(.T.) after each top-level navigation: the wrapper is installed once per document. EnableConsole(.F.) stops delivery through the console dispatcher, but does not undo the already installed JavaScript wrapper. Its logical return is the stored flag, not proof of successful injection. Console traffic is separate from ordinary bOnBind messages.

Example payloads

{
  "type": "log",
  "args": [
    "ready",
    "{\"count\":2}"
  ],
  "url": "https://example.com/"
}

{
  "type": "error",
  "args": [
    "Uncaught ReferenceError: x is not defined"
  ],
  "url": "https://example.com/",
  "line": 12
}

Console example

oWeb := TWebView2():New( oWnd )
IF ! Empty( oWeb:hWebView )
   oWeb:bOnConsole := { | cJson, hWebView | LogConsole( cJson ) }
   oWeb:bOnNavigationCompleted := { | cUrl, hWebView | oWeb:EnableConsole( .T. ) }
   oWeb:Navigate( "https://example.com/" )
ENDIF

STATIC FUNCTION LogConsole( cJson )
   LOCAL hData
   hb_jsonDecode( cJson, @hData )
   IF ValType( hData ) == "H"
      // hData[ "type" ], hData[ "args" ], hData[ "url" ]
      // hData[ "line" ]: only for a window error
      OutputDebugString( cJson )
   ENDIF
RETURN NIL

Library compatibility

For an application that supports earlier FWH libraries, guard both the DATA assignment and EnableConsole call. Use the same check when enabling tracing after navigation. This only skips console diagnostics; ordinary SendToFWH/bOnBind traffic is unchanged.

IF __objHasMsg( oWeb, "_BONCONSOLE" ) .AND. ;
   __objHasMsg( oWeb, "ENABLECONSOLE" )
   oWeb:bOnConsole := { | cJson, hWebView | LogConsole( cJson ) }
   oWeb:EnableConsole( .T. )
ENDIF

Limits and runtime requirements

AddHostObject is not implemented. SetContextMenuExclude stores the list but does not filter menu items. Browsing-data cleanup is JavaScript-level, not a full-profile wipe, and cannot clear HttpOnly cookies. Async PNG/PDF results must be checked through their events. Runtime interface availability can limit PDF, downloads and HTTP requests. See the example samples/webview2/wvdemo.prg + pulse.html and constants WV_CONTEXT_*, WV_DIALOG_*, WV_PERM_* and WV_FAIL_* in include/WebView2.ch.

For Remote View + WebView2, see samples/RemoteView/testrvweb.prg and Remote View.
