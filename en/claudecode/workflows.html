Multi-Agent Workflows

JavaScript workflow scripts that orchestrate dozens of parallel sub-agents deterministically. Each workflow fans out, verifies, and synthesizes results.

Core Primitives

FunctionBehavior
agent(prompt, opts)Spawn sub-agent. Returns text or validated schema object.
pipeline(items, ...stages)Run items through stages independently. No barrier between stages — default for multi-stage work.
parallel(thunks)BARRIER: awaits all thunks. Use only when all results needed together.
phase(title)Group subsequent agents under progress label.
log(message)Emit progress message.

Patterns

Adversarial Verification

Spawn N skeptics per finding, each prompted to REFUTE. Kill if majority refute.

Judge Panel

N independent attempts from different angles, scored by parallel judges, synthesize best.

Loop-Until-Dry

Keep spawning finders until K consecutive rounds return nothing new.

Multi-Modal Sweep

Parallel agents searching different ways (by-container, by-content, by-entity, by-time).

FWH Workflow Example

export const meta = {
  name: 'review-changes',
  description: 'Review files across dimensions, verify each finding',
  phases: [{ title: 'Review' }, { title: 'Verify' }],
}
const DIMS = [{key:'bugs', prompt:'Find bugs'}, {key:'perf', prompt:'Find perf issues'}]
const results = await pipeline(
  DIMS,
  d => agent(d.prompt, {label: `review:${d.key}`, schema: FINDINGS_SCHEMA}),
  review => parallel(review.findings.map(f => () =>
    agent(`Adversarially verify: ${f.title}`, {schema: VERDICT_SCHEMA})))
)
return results.flat().filter(Boolean)

Scale Considerations

  • Concurrent agent cap: min(16, CPU cores - 2)
  • Lifetime cap: 1000 agents per workflow
  • Token budget: user "+500k" directive controls scale
  • Worktree isolation: --isolation worktree for parallel file mutations
