DLL & Windows API Calls

FiveWin and Harbour provide multiple mechanisms for calling Windows API functions and external DLLs directly from your PRG code. This ranges from FiveWin's built-in wrappers for common API calls, to Harbour's DLL calling support, to inline C code via #pragma BEGINDUMP. This page covers all approaches with practical examples.

graph TD A[Harbour PRG Code] --> B{Calling External Code} B --> C[FiveWin API Wrappers] B --> D[DLL32 FUNCTION Command] B --> E["#pragma BEGINDUMP"] C --> F[Windows API - user32, kernel32, gdi32] D --> G[Any External DLL] E --> H[Inline C Code] H --> I["hb_retni(), hb_parc(), etc."] H --> J[Direct Windows API calls] H --> K[Custom C libraries]

FiveWin API Wrappers

FiveWin pre-wraps hundreds of Windows API functions so you can call them directly from PRG code without any DLL declaration or C code. These are implemented as HB_FUNC() C functions inside FiveWin's source files (in source\winapi\ and source\internal\).

DLL Function Calling

FiveWin provides the DLL FUNCTION command (from DLL.ch) to declare and call functions from any external DLL at runtime. This uses FiveWin's internal DLL calling engine that handles parameter marshaling between Harbour and C calling conventions.

DLL.ch Command Syntax

#include "DLL.ch"

// Declare a DLL function
DLL FUNCTION <FuncName>( [<Params,...>] ) AS <ReturnType> ;
   [PASCAL | CDECL] ;
   FROM <ExportName> ;
   LIB <cDllName | hDll>

// Return types: LONG, DWORD, BOOL, LPSTR, VOID, DOUBLE, WORD, BYTE
// Parameter types: passed by value or by reference (@)

Example: Call MessageBoxA from user32.dll

#include "DLL.ch"

// Declare the function
DLL FUNCTION MsgBoxA( hWnd AS LONG, cText AS LPSTR, cTitle AS LPSTR, ;
                       nType AS LONG ) AS LONG ;
   PASCAL FROM "MessageBoxA" LIB "user32.dll"

function TestMsgBox()
   local nResult

   nResult := MsgBoxA( 0, "Hello from DLL call!", "FiveWin", 0x00000004 )
   // MB_YESNO = 4

   if nResult == 6   // IDYES
      ? "User clicked Yes"
   else
      ? "User clicked No"
   endif

return nil

Example: Call GetSystemMetrics

#include "DLL.ch"

DLL FUNCTION GetSysMetrics( nIndex AS LONG ) AS LONG ;
   PASCAL FROM "GetSystemMetrics" LIB "user32.dll"

function ScreenInfo()
   #define SM_CXSCREEN      0
   #define SM_CYSCREEN      1
   #define SM_CXFULLSCREEN 16
   #define SM_CYFULLSCREEN 17
   #define SM_CMOUSEBUTTONS 43

   ? "Screen:", GetSysMetrics( SM_CXSCREEN ), "x", GetSysMetrics( SM_CYSCREEN )
   ? "Work area:", GetSysMetrics( SM_CXFULLSCREEN ), "x", GetSysMetrics( SM_CYFULLSCREEN )
   ? "Mouse buttons:", GetSysMetrics( SM_CMOUSEBUTTONS )

return nil

Example: Call a Custom DLL

#include "DLL.ch"

// Loading DLL handle first for multiple calls
function UseCustomDLL()
   local hDll := LoadLibrary( "mymath.dll" )

   if hDll == 0
      MsgAlert( "Cannot load mymath.dll" )
      return nil
   endif

   // Declare functions using the handle
   DLL FUNCTION CalcSum( n1 AS LONG, n2 AS LONG ) AS LONG ;
      PASCAL FROM "CalcSum" LIB hDll

   DLL FUNCTION CalcProduct( n1 AS LONG, n2 AS LONG ) AS LONG ;
      PASCAL FROM "CalcProduct" LIB hDll

   ? "Sum:", CalcSum( 10, 20 )        // 30
   ? "Product:", CalcProduct( 5, 7 )  // 35

   FreeLibrary( hDll )

return nil

Example: Call DLL Function with String Output

#include "DLL.ch"

DLL FUNCTION GetTempPathA( nBufferLen AS DWORD, @cBuffer AS LPSTR ) AS DWORD ;
   PASCAL FROM "GetTempPathA" LIB "kernel32.dll"

function GetTemp()
   local cBuffer := Space( 260 )
   local nLen

   nLen := GetTempPathA( 260, @cBuffer )
   cBuffer := Left( cBuffer, nLen )

   ? "Temp path:", cBuffer

return nil

Inline C Code with #pragma BEGINDUMP

Harbour's #pragma BEGINDUMP / ENDDUMP allows embedding C code directly in your PRG files. The C code is compiled by the C compiler (BCC32, MSVC, MinGW) during the build process. This is the most powerful and flexible approach for interfacing with Windows APIs, creating performance-critical functions, or wrapping C libraries.

How It Works

When the Harbour compiler encounters #pragma BEGINDUMP, it stops translating PRG code and copies everything verbatim to the output C file until it sees #pragma ENDDUMP. This allows you to write C functions that are callable from PRG using the HB_FUNC() macro.

Example: Basic HB_FUNC

// myutils.prg

function Main()
   ? "Sum:", FastAdd( 100, 200 )       // 300
   ? "Upper:", FastUpper( "hello" )     // "HELLO"
   ? "CPU count:", GetCPUCount()
return nil

#pragma BEGINDUMP

#include <hbapi.h>
#include <windows.h>

// Simple function: add two numbers
HB_FUNC( FASTADD )
{
   hb_retnl( hb_parnl( 1 ) + hb_parnl( 2 ) );
}

// String function: convert to uppercase
HB_FUNC( FASTUPPER )
{
   const char * szText = hb_parc( 1 );
   int nLen = hb_parclen( 1 );
   char * szResult = ( char * ) hb_xgrab( nLen + 1 );
   int i;

   for( i = 0; i < nLen; i++ )
      szResult[ i ] = ( char ) toupper( ( unsigned char ) szText[ i ] );
   szResult[ nLen ] = '\0';

   hb_retclen( szResult, nLen );
   hb_xfree( szResult );
}

// Windows API call: get number of CPUs
HB_FUNC( GETCPUCOUNT )
{
   SYSTEM_INFO si;
   GetSystemInfo( &si );
   hb_retnl( ( long ) si.dwNumberOfProcessors );
}

#pragma ENDDUMP

function Main()

#include <windows.h>

HB_FUNC( MYMESSAGEBOX )
{

      ( HWND ) hb_parnl( 1 ),   // hWnd

Example: Working with Structures

// sysinfo.prg

function Main()
   local nMem := GetTotalMemory()
   ? "Total RAM:", nMem / 1024 / 1024, "MB"

   local aVer := GetOSVersion()
   ? "Windows:", aVer[ 1 ], ".", aVer[ 2 ], "Build", aVer[ 3 ]
return nil

#pragma BEGINDUMP

#include <hbapi.h>
#include <hbapiitm.h>
#include <windows.h>

HB_FUNC( GETTOTALMEMORY )
{
   MEMORYSTATUSEX ms;
   ms.dwLength = sizeof( MEMORYSTATUSEX );
   GlobalMemoryStatusEx( &ms );
   hb_retnll( ( HB_LONGLONG ) ms.ullTotalPhys );
}

HB_FUNC( GETOSVERSION )
{
   OSVERSIONINFO ovi;
   PHB_ITEM pArray;

   ovi.dwOSVersionInfoSize = sizeof( OSVERSIONINFO );
   GetVersionEx( &ovi );

   pArray = hb_itemArrayNew( 3 );
   hb_arraySetNL( pArray, 1, ovi.dwMajorVersion );
   hb_arraySetNL( pArray, 2, ovi.dwMinorVersion );
   hb_arraySetNL( pArray, 3, ovi.dwBuildNumber );

   hb_itemReturnRelease( pArray );
}

#pragma ENDDUMP

Advanced Patterns

Passing Arrays Between PRG and C

// arrays.prg

function Main()
   local aInput := { 10, 20, 30, 40, 50 }
   ? "Sum:", ArraySum( aInput )   // 150
return nil

#pragma BEGINDUMP

#include <hbapi.h>
#include <hbapiitm.h>

HB_FUNC( ARRAYSUM )
{
   PHB_ITEM pArray = hb_param( 1, HB_IT_ARRAY );
   HB_SIZE nLen, i;
   long nSum = 0;

   if( pArray )
   {
      nLen = hb_arrayLen( pArray );
      for( i = 1; i <= nLen; i++ )
         nSum += hb_arrayGetNL( pArray, i );
   }

   hb_retnl( nSum );
}

#pragma ENDDUMP

Callback Functions (Window Procedures)

// Custom window subclassing from C
#pragma BEGINDUMP

#include <hbapi.h>
#include <windows.h>

static WNDPROC oldWndProc = NULL;

static LRESULT CALLBACK MyWndProc( HWND hWnd, UINT msg, WPARAM wParam, LPARAM lParam )
{
   switch( msg )
   {
      case WM_PAINT:
         // Custom paint handling
         break;

      case WM_KEYDOWN:
         if( wParam == VK_F5 )
         {
            MessageBoxA( hWnd, "F5 pressed!", "Custom Handler", MB_OK );
            return 0;
         }
         break;
   }
   return CallWindowProc( oldWndProc, hWnd, msg, wParam, lParam );
}

HB_FUNC( SUBCLASSWINDOW )
{
   HWND hWnd = ( HWND ) hb_parnl( 1 );
   oldWndProc = ( WNDPROC ) SetWindowLongPtr( hWnd, GWLP_WNDPROC, ( LONG_PTR ) MyWndProc );
   hb_retnl( ( long ) oldWndProc );
}

HB_FUNC( UNSUBCLASSWINDOW )
{
   HWND hWnd = ( HWND ) hb_parnl( 1 );
   SetWindowLongPtr( hWnd, GWLP_WNDPROC, ( LONG_PTR ) oldWndProc );
}

#pragma ENDDUMP

Linking with External Libraries

When your C code calls functions from external libraries, you need to link those libraries in your build script.

Borland C++ (BCC32)

REM In your buildh.bat or b32.bat, add import libraries:
bcc32 -c myapp.c
ilink32 myapp.obj, myapp.exe, , FiveHC.lib hbvm.lib ... ws2_32.lib wininet.lib

MSVC (64-bit)

REM In your build script:
cl /c myapp.c
link myapp.obj FiveH64.lib ... ws2_32.lib wininet.lib /OUT:myapp.exe

Tips for #pragma BEGINDUMP

  • Always include <hbapi.h> for the HB_FUNC macro and parameter functions.
  • Include <hbapiitm.h> for Harbour item manipulation (arrays, hashes).
  • Include <hbapierr.h> for error handling from C code.
  • Include <windows.h> for Windows API types and functions.
  • Use hb_xgrab()/hb_xfree() for Harbour-managed memory allocation.
  • Function names in HB_FUNC() must be UPPERCASE -- they map to uppercase PRG function names.
  • For 64-bit builds, use hb_parnll()/hb_retnll() for pointer-sized values, and cast handles to HB_PTRUINT.
  • Avoid mixing 32-bit pointer assumptions in 64-bit code: always use ( HWND ) hb_parnll() instead of ( HWND ) hb_parnl() for handles.
