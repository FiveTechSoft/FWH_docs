Unicode e Internacionalización

FiveWin proporciona un sistema integral de internacionalización (i18n) con dos componentes principales: un sistema de traducción de cadenas multiidioma (FWString) y soporte Unicode para mostrar caracteres no ASCII en ventanas y controles. Esta página cubre ambos sistemas en detalle, incluyendo consideraciones de codificación y ejemplos prácticos.

FWString() - El Sistema de Traducción

El sistema de traducción de FiveWin está construido sobre un array estático llamado aStrings definido en source\function\strings.prg. Cada elemento es un array de cadenas: el índice 1 es inglés, 2 es español, 3 es francés, 4 es portugués, 5 es alemán, 6 es italiano. Cuando se llama a FWString("algún texto"), busca el texto en inglés en el array y devuelve la traducción para el idioma actual.

Cómo Funciona

  1. Al iniciar, FWLanguageID() detecta automáticamente el idioma desde HB_LangSelect() y lo mapea a un índice de idioma (1=EN, 2=ES, 3=FR, 4=PT, 5=DE, 6=IT).
  2. Todas las cadenas internas de la UI de FiveWin (menús, botones, mensajes, etiquetas del previsualizador de informes) pasan por FWString().
  3. Cuando el idioma actual es inglés (índice 1), FWString() devuelve la cadena de entrada inmediatamente (no necesita búsqueda).
  4. Para otros idiomas, busca en aStrings una coincidencia sin distinción de mayúsculas/minúsculas del texto en inglés y devuelve la cadena traducida en el índice del idioma actual.
  5. Si la cadena no se encuentra, se añade a una lista de "cadenas faltantes" y se devuelve el texto original en inglés.

Cadenas Incorporadas

FiveWin incluye traducciones para cientos de cadenas comunes de UI: etiquetas de botones (Ok, Cancel, Save, Print), elementos de menú (File, Edit, View, Help), títulos de diálogos, mensajes de error, etiquetas del previsualizador de informes (First, Previous, Next, Last, Zoom), etiquetas del navegador de datos (Add, Edit, Del, Search, Filter), y más.

FWLoadStrings() - Cargar Traducciones Personalizadas

Se pueden cargar traducciones adicionales desde un archivo INI en tiempo de ejecución. El archivo usa una sección [strings] con entradas numeradas, donde cada valor contiene traducciones separadas por pipes.

Formato del Archivo INI (fwstrings.ini)

[strings]
1=Customer|Cliente|Client|Cliente|Kunde|Cliente
2=Invoice|Factura|Facture|Fatura|Rechnung|Fattura
3=Product|Producto|Produit|Produto|Produkt|Prodotto
4=Total Amount|Importe Total|Montant Total|Valor Total|Gesamtbetrag|Importo Totale
5=Due Date|Fecha Vencimiento|Date Echeance|Data Vencimento|Faelligkeitsdatum|Data Scadenza

Ejemplo: Cargar Traducciones Personalizadas

function Main()
   // Load application-specific translations
   FWLoadStrings( "c:\myapp\translations.ini" )

   // Set language
   FWSetLanguage( 2 )  // Spanish

   // Now custom strings are translated too
   ? FWString( "Customer" )       // "Cliente"
   ? FWString( "Invoice" )        // "Factura"
   ? FWString( "Total Amount" )   // "Importe Total"

return nil

Añadir Traducciones Personalizadas Programáticamente

FWAddString() - Añadir Entradas Individuales

// Add a single translation (all 6 languages)
FWAddString( { "Customer", "Cliente", "Client", "Cliente", "Kunde", "Cliente" } )

// Add using pipe-delimited string
FWAddString( "Invoice|Factura|Facture|Fatura|Rechnung|Fattura" )

// Add multiple entries at once (array of arrays)
FWAddString( { ;
   { "Customer", "Cliente", "Client", "Cliente", "Kunde", "Cliente" }, ;
   { "Invoice",  "Factura", "Facture", "Fatura", "Rechnung", "Fattura" }, ;
   { "Product",  "Producto", "Produit", "Produto", "Produkt", "Prodotto" } ;
} )

FWSetString() - Establecer Traducción para un Idioma Específico

// Set Spanish (language 2) translations
FWSetString( 2, { "Customer", "Cliente" } )
FWSetString( 2, { "Invoice",  "Factura" } )

// Set multiple at once
FWSetString( 2, { ;
   { "Customer", "Cliente" }, ;
   { "Invoice",  "Factura" }, ;
   { "Product",  "Producto" } ;
} )

FWAddLanguage() - Añadir un Idioma Completamente Nuevo

// Add Japanese as language 7
// The array must match the order of the English strings in aStrings
local aJapanese := { ;
   "Attention",    ... }  // This needs ALL strings translated

// Or more practically, add empty and fill specific strings:
local nJapanese := FWAddLanguage( {} )   // Returns the new language ID (e.g., 7)

// Then fill in translations one at a time
FWSetString( nJapanese, { "Ok", "OK" } )
FWSetString( nJapanese, { "Cancel", "Cancel" } )
FWSetString( nJapanese, { "Print", "Print" } )

FWSetLanguage( nJapanese )   // Switch to Japanese

FW_SetUnicode() - Modo Unicode

Por defecto, FiveWin crea ventanas y controles usando las versiones ANSI ("A") de las funciones de la API de Windows (ej., CreateWindowExA). Cuando se habilita el modo Unicode con FW_SetUnicode(.T.), FiveWin cambia a las funciones de la API Wide ("W") (ej., CreateWindowExW), permitiendo que las ventanas y controles muestren caracteres de cualquier idioma -- chino, japonés, coreano, árabe, hindi, y más.

Cómo Afecta el Modo Unicode a FiveWin

graph LR A["FW_SetUnicode(.T.)"] --> B["Window Creation"] A --> C["Control Text"] A --> D["Clipboard"] A --> E["Dialog Creation"] B --> F["CreateWindowExW()"] C --> G["SetWindowTextW()"] D --> H["CF_UNICODETEXT"] E --> I["DialogBoxIndirectW()"]

Cuando el modo Unicode está activo:

  • Todas las nuevas ventanas y controles se crean con llamadas API de caracteres anchos (wide).
  • El texto se maneja internamente como UTF-8 en Harbour y se convierte a UTF-16 para las llamadas a la API de Windows.
  • Cada TWindow/TControl tiene un DATA lUnicode que hereda del ajuste global.
  • TClipBoard detecta automáticamente texto UTF-8 y usa el formato CF_UNICODETEXT.
  • Los controles SAY, campos GET, menús y cuadros de mensaje soportan texto Unicode.

Referencia de Funciones

FunctionDescripción
FW_SetUnicode( [lOnOff] )Establece u obtiene el modo Unicode. Llamar con .T. para habilitar, .F. para deshabilitar. Llamar sin parámetro para consultar el estado actual.
FW_IsUTF8( cStr )Devuelve .T. si la cadena contiene secuencias multibyte UTF-8 válidas.

Ejemplo: Habilitar Unicode

function Main()
   // Enable Unicode BEFORE creating any windows
   FW_SetUnicode( .T. )

   local oWnd
   DEFINE WINDOW oWnd TITLE "Unicode Demo"

   // These will display correctly in Unicode mode:
   @ 1, 1 SAY "English: Hello World" OF oWnd
   @ 2, 1 SAY "Chinese: " + Chr(20320) + Chr(22909) OF oWnd
   @ 3, 1 SAY "Japanese: " + Chr(12371) + Chr(12435) + Chr(12395) + Chr(12385) + Chr(12399) OF oWnd
   @ 4, 1 SAY "Arabic: " + Chr(1605) + Chr(1585) + Chr(1581) + Chr(1576) + Chr(1575) OF oWnd

   ACTIVATE WINDOW oWnd

return nil

Funciones Utilitarias UTF-8

Al trabajar en modo Unicode, las cadenas en Harbour se almacenan como UTF-8. FiveWin proporciona funciones auxiliares para la manipulación de cadenas UTF-8 que manejan correctamente los caracteres multibyte.

Funciones de Cadenas UTF-8

FunctionDescripción
FW_UTF8LEFT( cStr, nLeft )Devuelve los nLeft caracteres más a la izquierda (no bytes) de una cadena UTF-8.
FW_UTF8RIGHT( cStr, nLen )Devuelve los nLen caracteres más a la derecha de una cadena UTF-8.
FW_UTF8SUBSTR( cStr, nPos, nLen )Extrae una subcadena por posición de carácter (no posición de byte).
FW_UTF8STUFF( cSrc, nPos, nDelete, cInsert )Inserta/reemplaza caracteres en una cadena UTF-8 por posición de carácter.
FW_UTF8PADCHAR( cStr, nChars )Rellena una cadena UTF-8 hasta nChars caracteres.
FW_UTF8PADBYTE( cText, nBytes )Rellena una cadena UTF-8 hasta nBytes bytes totales.

Por Qué Se Necesitan las Funciones UTF-8

Las funciones estándar de cadenas de Harbour (Left, Right, SubStr, Len) operan sobre bytes, no sobre caracteres. Un solo carácter Unicode en UTF-8 puede ocupar de 1 a 4 bytes. Usar Left( cUTF8, 3 ) podría cortar un carácter multibyte por la mitad, produciendo texto ilegible. Use FW_UTF8LEFT( cUTF8, 3 ) en su lugar para obtener exactamente 3 caracteres independientemente de la longitud en bytes.

// Example: UTF-8 character-safe operations
local cText := "Hello"  // Mixed ASCII + multi-byte

// WRONG: may split multi-byte characters
// local cFirst := Left( cText, 3 )

// CORRECT: character-aware substring
local cFirst := FW_UTF8LEFT( cText, 3 )
local cLast  := FW_UTF8RIGHT( cText, 2 )
local cMid   := FW_UTF8SUBSTR( cText, 2, 3 )

Codificación OEM vs ANSI vs UTF-8

Comprender los tres sistemas de codificación es fundamental para la correcta visualización de texto en aplicaciones FiveWin, especialmente al mezclar salida de consola, interfaz gráfica de Windows y E/S de archivos.

Resumen de Codificaciones

CodificaciónCuándo Se UsaDescripción
OEM (DOS)Salida de consola, archivos DBF, datos heredadosEl juego de caracteres original del IBM PC (CP437, CP850, etc.). Los caracteres por encima de 127 son caracteres de dibujo de líneas y acentuados específicos de la página de códigos.
ANSI (Windows)Controles de Windows, funciones API "A"Windows-1252 o página de códigos específica del locale. Los caracteres por encima de 127 incluyen letras acentuadas para idiomas de Europa occidental.
UTF-8Modo Unicode, datos modernos, web/JSONCodificación de longitud variable (1-4 bytes por carácter). Compatible con ASCII para caracteres 0-127. Se usa con funciones API "W" (convertido a UTF-16).

Funciones de Conversión

FunciónDesdeHaciaNotas
hb_oemToAnsi( cStr )OEMANSIIntegrada en Harbour. Convierte datos DOS/DBF para visualización en Windows.
hb_AnsiToOem( cStr )ANSIOEMIntegrada en Harbour. Convierte texto de Windows para almacenamiento en DBF.

Cuándo Usar Cada Codificación

  • Lectura de archivos DBF: Los datos típicamente están codificados en OEM. Si se muestran en un control SAY o GET en modo no Unicode, use hb_oemToAnsi(). En modo Unicode, convierta mediante hb_oemToAnsi() y luego hb_StrToUTF8().
  • Visualización en controles de Windows: En modo ANSI (por defecto), los controles esperan cadenas ANSI. En modo Unicode (FW_SetUnicode(.T.)), los controles aceptan UTF-8 que FiveWin convierte a UTF-16 internamente.
  • API REST / datos JSON: Siempre UTF-8. Si se muestra en FiveWin sin Unicode, convierta primero a ANSI. En modo Unicode, use directamente.
  • MsgInfo / MsgAlert: Estos usan el ajuste Unicode de la ventana. En modo Unicode, pase cadenas UTF-8. En modo ANSI, pase cadenas ANSI.
  • Escritura en archivos: Elija la codificación según el destino: OEM para compatibilidad con DBF, UTF-8 para intercambio moderno, ANSI para archivos Windows heredados.

Consideraciones de Página de Códigos

// Set Harbour codepage for proper OEM/ANSI conversion
REQUEST HB_CODEPAGE_ESWIN   // Spanish Windows codepage
HB_CDPSELECT( "ESWIN" )     // Select it

// Or for French:
REQUEST HB_CODEPAGE_FRWIN
HB_CDPSELECT( "FRWIN" )

// Harbour language selection (affects date formats, error messages)
REQUEST HB_LANG_ES
HB_LANGSELECT( "ES" )

Aplicación Multiidioma Completa

Este ejemplo muestra una aplicación completa con un selector de idioma que cambia dinámicamente el idioma de la UI para todos los controles de FiveWin y cadenas personalizadas.

#include "FiveWin.ch"

static oWnd, oBar, oBtnSave, oBtnPrint, oSayStatus

function Main()

   // Enable Unicode for full character support
   FW_SetUnicode( .T. )

   // Add application-specific translations
   FWAddString( { ;
      { "My Application",  "Mi Aplicacion",     "Mon Application",   "Meu Aplicativo",     "Meine Anwendung",    "Mia Applicazione" }, ;
      { "Customer List",   "Lista de Clientes", "Liste des Clients", "Lista de Clientes",  "Kundenliste",        "Lista Clienti" }, ;
      { "New Customer",    "Nuevo Cliente",     "Nouveau Client",    "Novo Cliente",        "Neuer Kunde",        "Nuovo Cliente" }, ;
      { "Save Record",     "Guardar Registro",  "Enregistrer",       "Salvar Registro",     "Datensatz Speichern","Salva Record" }, ;
      { "Print Report",    "Imprimir Reporte",  "Imprimer Rapport",  "Imprimir Relatorio",  "Bericht Drucken",    "Stampa Report" }, ;
      { "Language",        "Idioma",            "Langue",            "Idioma",              "Sprache",            "Lingua" }, ;
      { "Ready",           "Listo",             "Pret",              "Pronto",              "Bereit",             "Pronto" } ;
   } )

   // Default to English
   FWSetLanguage( 1 )

   DEFINE WINDOW oWnd TITLE FWString( "My Application" )

   BuildUI()

   ACTIVATE WINDOW oWnd

return nil

//------------------------------------------------------------//

function BuildUI()

   // Toolbar / button bar
   @ 1, 1 BUTTON oBtnSave PROMPT FWString( "Save Record" ) OF oWnd ;
      SIZE 120, 28 ACTION MsgInfo( FWString( "Save Record" ) )

   @ 1, 16 BUTTON oBtnPrint PROMPT FWString( "Print Report" ) OF oWnd ;
      SIZE 120, 28 ACTION MsgInfo( FWString( "Print Report" ) )

   // Language selector
   @ 1, 32 BUTTON PROMPT FWString( "Language" ) OF oWnd ;
      SIZE 100, 28 ACTION SelectLanguage()

   // Status
   @ 4, 1 SAY oSayStatus PROMPT FWString( "Ready" ) OF oWnd SIZE 300, 20

return nil

//------------------------------------------------------------//

function SelectLanguage()
   local aLangs := { "English", "Espanol", "Francais", "Portugues", "Deutsch", "Italiano" }
   local nChoice := 0

   nChoice := Alert( FWString( "Language" ), aLangs )

   if nChoice > 0
      FWSetLanguage( nChoice )
      RefreshUI()
   endif

return nil

//------------------------------------------------------------//

function RefreshUI()

   // Update window title
   oWnd:SetText( FWString( "My Application" ) )

   // Update button captions
   oBtnSave:SetText( FWString( "Save Record" ) )
   oBtnPrint:SetText( FWString( "Print Report" ) )

   // Update status
   oSayStatus:SetText( FWString( "Ready" ) )

return nil

Añadir Traducciones Personalizadas vía Archivo INI

Para aplicaciones más grandes o cuando las traducciones son gestionadas por personas que no son desarrolladores, use un archivo INI para almacenar traducciones que se cargan al inicio.

Paso 1: Crear el archivo de traducciones

; File: translations.ini
; Format: n=English|Spanish|French|Portuguese|German|Italian

[strings]
1=Customer|Cliente|Client|Cliente|Kunde|Cliente
2=Invoice|Factura|Facture|Fatura|Rechnung|Fattura
3=Product|Producto|Produit|Produto|Produkt|Prodotto
4=Total Amount|Importe Total|Montant Total|Valor Total|Gesamtbetrag|Importo Totale
5=Due Date|Vencimiento|Echeance|Vencimento|Faelligkeit|Scadenza
6=Payment|Pago|Paiement|Pagamento|Zahlung|Pagamento
7=Discount|Descuento|Remise|Desconto|Rabatt|Sconto
8=Tax|Impuesto|Taxe|Imposto|Steuer|Imposta
9=Shipping|Envio|Expedition|Envio|Versand|Spedizione
10=Notes|Notas|Notes|Notas|Anmerkungen|Note

Paso 2: Cargar al iniciar la aplicación

function Main()
   // Load custom translations
   FWLoadStrings( cFilePath( GetModuleFileName( GetInstance() ) ) + "translations.ini" )

   // Set language (could be read from user preferences)
   local oIni := TIni():New( "myapp.ini" )
   local nLang := oIni:Get( "Settings", "Language", 1 )
   FWSetLanguage( nLang )

   // All FWString() calls now return the correct language
   MsgInfo( FWString( "Customer" ) + ": John Doe" )
   // In Spanish: "Cliente: John Doe"

return nil

Paso 3: Guardar la preferencia de idioma cuando el usuario la cambia

function ChangeLanguage( nNewLang )
   local oIni := TIni():New( "myapp.ini" )

   FWSetLanguage( nNewLang )
   oIni:Set( "Settings", "Language", nNewLang )

   // Refresh all visible UI elements
   RefreshAllWindows()

return nil

Encontrar Traducciones Faltantes

Durante el desarrollo, use FWMissingStrings() para descubrir qué cadenas en su aplicación carecen de traducciones.

// At the end of a test run:
function CheckTranslations()
   local aMissing

   // Set to a non-English language to trigger lookups
   FWSetLanguage( 2 )   // Spanish

   // ... run through your application UI ...

   // Check what's missing
   aMissing := FWMissingStrings()

   // This writes "missing.str" with ready-to-paste code:
   // FWSetString( nLang, { ;

   //    { "New Customer", }, ;
   //    ...
   // } )

   ? "Missing translations:", Len( aMissing )

return nil

Mejores Prácticas

1. Siempre use FWString() para texto visible al usuario

// GOOD: translatable
@ 1, 1 SAY FWString( "Customer" ) OF oDlg
MsgInfo( FWString( "Record saved successfully" ) )

// BAD: hard-coded, not translatable
@ 1, 1 SAY "Customer" OF oDlg
MsgInfo( "Record saved successfully" )

2. Habilitar Unicode temprano

// Call FW_SetUnicode(.T.) BEFORE creating any windows
function Main()
   FW_SetUnicode( .T. )  // First thing!
   // ... create windows after this
return nil

3. Usar la página de códigos correcta para sus datos

// For applications using DBF with accented characters:
REQUEST HB_CODEPAGE_ESWIN
HB_CDPSELECT( "ESWIN" )

// For UTF-8 data (JSON, REST APIs, modern databases):
FW_SetUnicode( .T. )

4. Manejar la codificación en los límites de datos

// Reading from DBF (OEM) to display in Unicode window:
local cName := Customers->Name              // OEM encoded
cName := hb_oemToAnsi( cName )              // Convert to ANSI
// In Unicode mode, FiveWin handles ANSI->UTF-16 automatically

// Reading from JSON API (UTF-8):
local cData := hb_jsonDecode( cResponse )    // Already UTF-8
// In Unicode mode, display directly
// In ANSI mode: cData := hb_UTF8ToStr( cData )

5. Probar con escrituras no latinas

Al construir aplicaciones internacionales, pruebe con texto chino, árabe o cirílico para verificar que el modo Unicode está correctamente habilitado y que todos los controles se muestran correctamente. Preste especial atención a:

  • Campos GET (la longitud de entrada puede diferir del ancho de visualización con caracteres multibyte)
  • Anchos de columnas de XBrowse (el auto-dimensionamiento puede necesitar ajustes)
  • Salida de impresora (asegúrese de que la fuente seleccionada soporte los caracteres requeridos)
  • E/S de archivos (guarde como UTF-8, no ANSI, si los datos contienen caracteres no latinos)
