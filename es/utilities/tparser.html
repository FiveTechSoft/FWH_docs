TParser - Motor de Análisis Dinámico

Fuente: source/classes/tparser.prg

TParser es un esqueleto de motor genérico de reglas gramaticales. Mantiene una lista de reglas de producción y una pila de estados. Las reglas constan de un símbolo no terminal, un array de tokens y un bloque de código de acción. Esta clase proporciona el marco para construir analizadores de expresiones, intérpretes de comandos o procesadores de lenguajes específicos de dominio.

Miembros DATA Principales

DATATipoDescripción
aRulesArrayArray de reglas gramaticales, cada una { cNonTerminal, aTokens, bAction }
aStatesArrayPila de estados para el análisis; el estado 0 está vacío por defecto

Métodos Principales

MétodoDescripción
New()Crea un nuevo analizador con reglas vacías y estado inicial
Add( cNonTerminal, aTokens, bAction )Añade una regla de producción: no terminal -> secuencia de tokens con acción

Ejemplo: Añadir Reglas Gramaticales

#include "FiveWin.ch"

function Main()

   local oParser := TParser():New()

   // expr -> number
   oParser:Add( "expr", { "number" }, {|n| n } )

   // expr -> expr + expr
   oParser:Add( "expr", { "expr", "+", "expr" }, {|a,b| a + b } )

   // expr -> expr * expr
   oParser:Add( "expr", { "expr", "*", "expr" }, {|a,b| a * b } )

   // Acceder a las reglas
   ? Len( oParser:aRules )   // 3 reglas añadidas

return nil

Notas

  • TParser es una clase esqueleto. El método central Add() construye la tabla de reglas; usted debe implementar el tokenizador y el algoritmo de análisis (shift-reduce, descenso recursivo, etc.) por su cuenta usando los datos aRules y aStates.
  • El array aTokens de cada regla define la secuencia de tokens esperada; el bloque bAction es la acción semántica que se dispara cuando la regla coincide.
  • aStates comienza con un único estado vacío (índice 0). Los estados pueden apilarse/desapilarse durante el análisis para manejar construcciones anidadas.
