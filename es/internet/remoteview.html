Remote View

Fuentes: source/internal/remoteview/remoteviewfw.c, server.c, capture.c

Remote View permite que cualquier navegador de la LAN vea y controle en directo una ventana FWH activa. La ventana se captura en tiempo real con GDI+, se transmite como fotogramas JPEG a través de un WebSocket y se dibuja en un canvas HTML5. Los clics del ratón, el movimiento, la rueda y la entrada de teclado regresan desde el navegador a la ventana real mediante PostMessage.

Inicio Rápido

Inicie un servidor en ON INIT y deténgalo en VALID. Apunte cualquier navegador de la LAN a http://<ip>:8080: 

#include "FiveWin.ch"

function Main()

   local oWnd, oSay, oBtn
   local nClicks := 0

   DEFINE WINDOW oWnd TITLE "FWH Remote View" ;
      FROM 4, 4 TO 22, 60

   @ 1, 2 SAY oSay PROMPT "Open http://localhost:8080" ;
      OF oWnd SIZE 300, 20

   @ 3, 2 BUTTON oBtn PROMPT "Click (local or remote)" ;
      OF oWnd SIZE 160, 30 ;
      ACTION ( nClicks++, oSay:SetText( "Clicks: " + Str( nClicks, 4 ) ) )

   ACTIVATE WINDOW oWnd ;
      ON INIT ( RemoteViewStart( oWnd:hWnd, 8080 ), ;
                oWnd:SetText( "FWH Remote View - http://localhost:8080" ) ) ;
      VALID ( RemoteViewStop(), .T. )

return nil

El navegador muestra la ventana tal cual — botones, SAYs, GETs, browses, menús, todo funciona. Los clics en el canvas se convierten en clics reales sobre la ventana real.

Referencia de la API de Harbour

RemoteViewStart( [hWnd], [nPort] ) → lOk

Inicia la captura de hWnd (por defecto: la ventana activa) y la sirve en nPort (por defecto 8080). Devuelve .T. si tiene éxito.

Estrategia de bombeo: Una ventana oculta de solo mensajes posee un WM_TIMER (16 ms) que llama a ServerTick(). Dado que el temporizador lo despacha el bucle de mensajes del hilo, sigue disparándose incluso mientras un bucle modal (MsgInfo, diálogos, menús) ha tomado el control del bucle — justo lo que FWH necesita. Sin hilos, sin -mt requerido.

RemoteViewStop()

Detiene el servidor, elimina el temporizador de bombeo, libera GDI+ y limpia el estado. Llámelo en VALID o antes del cierre.

RemoteViewSetOffset( nX, nY )

Desplaza la imagen de la ventana dentro del viewport del navegador nX píxeles a la derecha y nY píxeles hacia abajo. Por defecto 0,0. Útil durante el desarrollo para que la ventana real no cubra la imagen web en el mismo monitor. Llámelo antes de RemoteViewStart().

RemoteViewServe( hWnd, nPort [, nOffX, nOffY] )

Bloqueante. Inicia un servidor con el estado aislado mediante TLS (almacenamiento local de hilo) y bombea ServerTick() en un bucle hasta que se llama a RemoteViewStopAll(). Diseñado para ejecutarse dentro de un hilo de Harbour creado con hb_threadStart(), de modo que cada callback PRG (ACTION, bChanged…) se ejecute con la VM de Harbour ya inicializada en ese hilo. Requiere -mt (VM MT de Harbour).

RemoteViewStopAll()

Indica a todos los bucles RemoteViewServe() en ejecución que finalicen. Llámelo en VALID cuando use el enfoque multicliente MT.

Dos Modos

Modo Cliente Único (bombeo WM_TIMER)

Use RemoteViewStart() en ON INIT. Un servidor, un cliente. No se necesita -mt. El bombeo del temporizador se ejecuta en el hilo de la GUI y sobrevive a los bucles modales. Ideal para la mayoría de las aplicaciones.

EjemploDescripción

samples/RemoteView/testrv2.prg Ventana principal + diálogo hijo. La captura compone los popups propios, por lo que el diálogo también aparece en el navegador

Modo Multicliente (hilos de Harbour + -mt)

Use hb_threadStart() para lanzar N instancias de RemoteViewServe(), cada una en su propio puerto. El aislamiento de estado por TLS evita que las instancias se pisen entre sí. Varios navegadores pueden ver y controlar la misma ventana simultáneamente, cada uno en un puerto distinto. Deténgalos con RemoteViewStopAll(). 

#define N_CLIENTS  3
#define BASE_PORT  8080

STATIC FUNCTION StartServers( oWnd )

   local i

   for i := 0 TO N_CLIENTS - 1
      hb_threadStart( {| h, p | RemoteViewServe( h, p, 200, 200 ) }, ;
                      oWnd:hWnd, BASE_PORT + i )
   next

   oWnd:SetText( "FWH Remote View MT - " + LTrim( Str( N_CLIENTS ) ) + ;
                 " servers (8080.." + LTrim( Str( BASE_PORT + N_CLIENTS - 1 ) ) + ")" )

return nil

Ejemplo: samples/RemoteView/testrvmt.prg. Compílelo con build_new.bat testrvmt mt (mt como 3er argumento selecciona la VM MT de Harbour).

Protocolo Cliente-Navegador

El servidor sirve un cliente HTML/JS en línea en GET /. El cliente integrado abre un WebSocket hacia /ws y usa un protocolo binario compacto:

Byte 0MensajeCarga útil
0x01Fotograma completow(2) h(2) originX(2) originY(2) JPEG...
0x02Parche suciox(2) y(2) w(2) h(2) originX(2) originY(2) JPEG...
0x10Movimiento de ratónx(2) y(2)
0x11Botón de ratón pulsadox(2) y(2) button(1)
0x12Botón de ratón liberadox(2) y(2) button(1)
0x13Tecla pulsadavk(2) modifiers(1) char(2)
0x14Tecla liberadavk(2) modifiers(1)
0x15Rueda del ratónx(2) y(2) delta(2)
0x16Tamaño del viewportw(2) h(2) (cliente → servidor)

Todos los enteros multibyte son little-endian. Las coordenadas están en el espacio del bitmap (el servidor las asigna a coordenadas de pantalla antes de PostMessage).

Captura Inteligente

El motor de captura usa varias técnicas para minimizar el ancho de banda:

  • Captura diferencial: Solo la región cambiada de la ventana se codifica en JPEG y se envía como un parche 0x02. El navegador lo dibuja en el desplazamiento correcto, conservando el resto del canvas.
  • Hash FNV-1a: Cada fotograma se somete a hash. Los fotogramas consecutivos idénticos se omiten por completo — sin codificación JPEG, sin envío por la red.
  • Modo viewport: Cuando el navegador envía el tamaño de su viewport (0x16), el motor de captura escala el escritorio virtual para que coincida con el canvas del navegador. La ventana se centra dentro de este espacio virtual. Maximizar la ventana llena el viewport del navegador, no el monitor real.
  • Minimizar: Cuando la ventana está minimizada, se dibuja una representación icónica que se puede pulsar en el navegador.
  • Popups propios: Los diálogos y MessageBoxes propiedad de la ventana capturada se componen encima, de modo que aparecen en el navegador.

Interacción con la Barra de Título

El cliente del navegador admite la interacción completa con la barra de título:

  • Arrastrar para mover: Haga clic y arrastre el área de la barra de título para mover la ventana
  • Bordes de redimensionado: Bordes de 8 píxeles en todos los lados y esquinas para redimensionar
  • Doble clic en la barra de título: Alterna entre maximizar y restaurar
  • Botones Min/Max/Cerrar: Se pueden pulsar con realimentación visual al pasar el cursor
  • Compatible con DWM: Se ajusta a los límites extendidos del marco DWM de los Windows 10/11 modernos, de modo que la detección de pulsación de los botones funciona correctamente con las esquinas redondeadas y las sombras

Soporte de Teclado

El cliente del navegador captura los eventos de teclado y los asigna a los códigos de tecla virtual de Windows. Se admiten las teclas estándar (Enter, Escape, Retroceso, Tab, flechas, teclas de función, alfanuméricas). Las teclas modificadoras (Shift, Ctrl, Alt, Meta, BloqMayús) se rastrean y se envían con cada evento de tecla.

Nota de Seguridad

Advertencia: El servidor se enlaza a INADDR_ANY (0.0.0.0) sin autenticación. Cualquier dispositivo de la LAN puede ver y controlar la ventana. Úselo solo en redes de confianza hasta que se añada una opción de solo local o de autenticación.

Compilación

Remote View está enlazado en todas las bibliotecas FWH — no se necesitan libs adicionales. El servidor WebSocket usa Winsock (ws2_32.lib) y el motor de captura usa GDI+ (gdiplus.lib). build_new.bat enlaza ambos automáticamente para todas las variantes de compilador.

El RemoteView.exe interno en source/internal/remoteview/ es una implementación de referencia en C puro que no requiere FiveWin — una ventana Win32 mínima servida por el mismo servidor y motor de captura.

  • Cliente único: build_new.bat testrv (cualquier variante)
  • Multicliente: build_new.bat testrvmt mt (se requiere la VM MT de Harbour)

Compatibilidad con Compiladores

Se verificó que el Remote View de cliente único captura y transmite correctamente en todas las variantes de Harbour y xHarbour, de 32 y 64 bits, en los compiladores C BCC, MSVC y MinGW. El título de la ventana testrv / testrvmt informa de la compilación en ejecución en tiempo de ejecución (por ejemplo “Harbour MSVC 64”), lo que facilita confirmar qué cadena de herramientas produjo un ejecutable dado.

El modo multicliente (-mt) se basa en la VM multihilo de Harbour y su API C de hilos, por lo que está disponible en las compilaciones Harbour BCC32 / MSVC32 / MSVC64; xHarbour no proporciona esa API.

xHarbour Commercial (VC98) es la única excepción: las aplicaciones FiveWin ordinarias se compilan y ejecutan allí, pero la captura de ventanas con GDI+ de la que depende Remote View (la misma ruta usada por SaveAsImage) funciona mal en tiempo de ejecución, por lo que Remote View no es compatible con esa compilación.

Patrón de Integración

El patrón recomendado para añadir Remote View a cualquier aplicación FWH: 

ACTIVATE WINDOW oWnd ;
   ON INIT ( RemoteViewSetOffset( 200, 200 ), ;          // optional dev offset
             If( RemoteViewStart( oWnd:hWnd, 8080 ), ;
                 oWnd:SetText( "App - http://localhost:8080" ), ;
                 MsgStop( "Could not start Remote View" ) ) ) ;
   VALID ( RemoteViewStop(), .T. )

Para aplicaciones que necesitan varios clientes simultáneos, use hb_threadStart + RemoteViewServe + RemoteViewStopAll (vea Modo Multicliente más arriba).
