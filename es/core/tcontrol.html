TControl

Clase Base Hereda de TWindow source/classes/control.prg

TControl es la clase base abstracta para todos los controles de interfaz de usuario en FiveWin. Hereda de TWindow y agrega comportamiento específico de controles: enlace de datos mediante bSetGet, notificaciones de cambio, soporte de arrastrar y soltar, acoplamiento/anclaje dentro de ventanas padre, redimensionamiento en modo diseño y el patrón REDEFINE para diálogos basados en recursos. Nunca se instancia TControl directamente; en su lugar, se utilizan sus subclases concretas como TButton, TGet, TXBrowse, etc.

Jerarquía de Controles

TControl es el ancestro común de todo control visual. A continuación se muestra el árbol de herencia con las subclases principales:

Métodos Principales

Refresh()

Heredado de TWindow. Fuerza el repintado del control. Para controles enlazados a datos (aquellos con bSetGet), también re-lee el valor de la variable enlazada.

SetFocus()

Da el foco de teclado a este control. Internamente envía FM_CHANGEFOCUS y llama a la API Win32 SetFocus().

VarGet() / VarPut()

METHOD VarGet() INLINE If( ValType( ::bSetGet ) == "B", Eval( ::bSetGet ), )
METHOD VarPut( uVal ) INLINE If( ValType( ::bSetGet ) == "B", Eval( ::bSetGet, uVal ), )

Lee o escribe la variable enlazada del control a través del bloque bSetGet. Esta es la forma estándar de obtener/establecer el valor de un control programáticamente.

cToChar()

METHOD cToChar( cCtrlClass )

Genera código fuente que recrea este control. Usado por el diseñador visual para serializar diálogos.

Move()

METHOD Move( nTop, nLeft, nWidth, nHeight, lRepaint )

Reposiciona y/o redimensiona el control dentro de su padre.

End()

Destruye la ventana Win32 del control y lo elimina del array aControls del padre.

Acoplamiento y Anclaje

TControl proporciona métodos de acoplamiento que posicionan automáticamente un control para llenar regiones específicas de la ventana padre. Son esenciales para construir diseños redimensionables:

Docked to left edge"] C["oClient — AdjClient()

Docked to right edge"] B["oBottom — AdjBottom()

AdjClient()

METHOD AdjClient()

Redimensiona el control para llenar toda el área cliente del padre, menos el espacio ocupado por controles acoplados (oTop, oBottom, oLeft, oRight) y la barra de mensajes. Este es el método de acoplamiento más utilizado.

Internamente, AdjClient() inspecciona las propiedades oTop, oBar, oBottom, oMsgBar, oLeft y oRight del padre para calcular el rectángulo restante, luego llama a WndAdjClient() para posicionar el control.

AdjTop() / AdjBottom()

Acopla el control al borde superior o inferior del padre. El control se estira a todo el ancho, y su altura permanece según la definida.

AdjLeft() / AdjRight()

Acopla el control al borde izquierdo o derecho. El control se estira a toda la altura (entre los controles acoplados arriba/abajo), y su ancho permanece según el definido.

Acoplamiento en la Práctica

#include "FiveWin.ch"

function Main()

   local oWnd, oTree, oBrw, oBottom

   DEFINE WINDOW oWnd TITLE "Docking Layout"

   // Toolbar docks automatically to top via oWnd:oBar
   DEFINE BUTTONBAR oBar OF oWnd SIZE 48, 48 2007
   DEFINE BUTTON OF oBar RESOURCE "OPEN" ACTION nil

   // Status bar docks automatically to bottom via oWnd:oMsgBar
   SET MESSAGE OF oWnd TO "Ready" CENTERED

   // Left panel: tree view
   oTree := TTreeView():New( 0, 0, oWnd, , 220, 400 )
   oWnd:oLeft := oTree
   oTree:AdjLeft()

   // Client area: browse control fills the rest
   oBrw := TXBrowse():New( oWnd )
   oBrw:SetArray( GetCustomerData() )
   oBrw:CreateFromCode()
   oWnd:oClient := oBrw
   oBrw:AdjClient()

   ACTIVATE WINDOW oWnd MAXIMIZED ;
      ON RESIZE ( oTree:AdjLeft(), oBrw:AdjClient() )

return nil

El patrón clave: asigna el control al slot de acoplamiento del padre (oWnd:oLeft, oWnd:oClient), luego llama al método Adj*() correspondiente. En el handler ON RESIZE, llámalos de nuevo para que el diseño se adapte.

Enlace de Datos con bSetGet

El bloque de código bSetGet es el corazón del enlace de datos de FiveWin. Sigue la convención getter/setter de xBase:

// When creating a GET, FiveWin generates this block automatically:
local cName := Space( 30 )

@ 10, 10 GET oGet VAR cName OF oDlg   // Internally creates:
// oGet:bSetGet := { |u| If( u == nil, cName, cName := u ) }

// Reading the value:
? oGet:VarGet()       // returns cName

// Writing a value:
oGet:VarPut( "John" ) // sets cName := "John"
oGet:Refresh()        // updates the visual display

Para controles enlazados a bases de datos, bSetGet referencia un campo:

@ 10, 10 GET oGet VAR Customers->Name OF oDlg
// bSetGet := { |u| If( u == nil, Customers->Name, Customers->Name := u ) }

Ejemplo: Creación de un Control Personalizado

Puedes heredar de TControl para crear controles personalizados con pintado y comportamiento especializados:

#include "FiveWin.ch"

// A simple LED indicator control

CLASS TLed FROM TControl

   DATA lOn       INIT .F.     // LED state
   DATA nClrOn    INIT CLR_GREEN
   DATA nClrOff   INIT CLR_RED
   DATA nRadius   INIT 12

   METHOD New( nTop, nLeft, oWnd, nWidth, nHeight, lOn )
   METHOD Paint()
   METHOD Toggle() INLINE ::lOn := !::lOn, ::Refresh()

ENDCLASS

METHOD New( nTop, nLeft, oWnd, nWidth, nHeight, lOn ) CLASS TLed

   DEFAULT nWidth := 30, nHeight := 30, lOn := .F.

   ::nTop    := nTop
   ::nLeft   := nLeft
   ::nBottom := nTop + nHeight
   ::nRight  := nLeft + nWidth
   ::oWnd    := oWnd
   ::lOn     := lOn

   ::nStyle := nOR( WS_CHILD, WS_VISIBLE )

   if oWnd != nil
      ::Create( "TLed" )
      oWnd:AddControl( Self )
   endif

return Self

METHOD Paint() CLASS TLed

   local hDC  := ::BeginPaint()
   local aRect := ::GetCliRect()
   local nCx  := ( aRect[4] - aRect[2] ) / 2
   local nCy  := ( aRect[3] - aRect[1] ) / 2
   local nClr := If( ::lOn, ::nClrOn, ::nClrOff )

   // Fill background
   FillSolidRect( hDC, aRect, GetSysColor( COLOR_BTNFACE ) )

   // Draw the LED circle
   FW_FillCircle( hDC, nCy, nCx, ::nRadius, nClr )

   // Draw border
   FW_Circle( hDC, nCy, nCx, ::nRadius + 1, CLR_BLACK )

   ::EndPaint()

return 0

Uso:

function TestLed()

   local oDlg, oLed1, oLed2

   DEFINE DIALOG oDlg TITLE "LED Demo" SIZE 300, 200 TRUEPIXEL

   oLed1 := TLed():New( 30, 40, oDlg, 36, 36, .T. )   // ON
   oLed2 := TLed():New( 30, 90, oDlg, 36, 36, .F. )   // OFF

   @ 30, 140 SAY "Server"  OF oDlg SIZE 80, 22 TRUEPIXEL
   @ 30, 190 SAY "Offline" OF oDlg SIZE 80, 22 TRUEPIXEL

   @ 100, 40 BUTTON "Toggle" OF oDlg SIZE 100, 30 TRUEPIXEL ;
      ACTION ( oLed1:Toggle(), oLed2:Toggle() )

   ACTIVATE DIALOG oDlg CENTER

return nil

Modo Diseño

TControl incluye soporte integrado para el modo de diseño visual (usado por el editor de diálogos de FiveWin). Cuando lDrag se establece a .T.:

  • El control puede moverse arrastrándolo con el ratón.
  • Aparecen tiradores de redimensionamiento (puntos) alrededor del control cuando tiene el foco (ShowDots() / HideDots()).
  • El método MResize() gestiona las 8 direcciones de redimensionamiento (NO, N, NE, E, SE, S, SO, O).
  • Los bloques bDragBegin, bDrag, bPreDrag y bPostDrag se disparan en diferentes etapas del arrastre.
  • bPreDelControl y bPostDelControl se disparan antes/después de eliminar un control en el diseñador.

El Patrón REDEFINE

Para diálogos basados en recursos, los controles son creados por la plantilla de recursos del diálogo. Los comandos REDEFINE de FiveWin vinculan objetos FiveWin a esos controles Win32 existentes mediante su ID numérico:

METHOD Redefine( nId, oWnd ) CONSTRUCTOR
DEFINE DIALOG oDlg RESOURCE "MYDIALOG"

   REDEFINE GET oGet VAR cName ID 101 OF oDlg
   REDEFINE BUTTON oBtn ID 102 OF oDlg ACTION SaveData()
   REDEFINE COMBOBOX oCbx VAR cCity ID 103 OF oDlg ;
      ITEMS { "NYC", "London", "Tokyo" }

ACTIVATE DIALOG oDlg CENTER

Consejos de Uso

  • Usa lUpdate := .T. para controles que deben refrescarse al navegar registros de la base de datos. Llama a oWnd:Update() u oDlg:Update() después de un SKIP para refrescar todos los controles marcados con lUpdate.
  • Acceso lChanged — Comprueba oGet:lChanged para saber si el usuario modificó un campo antes de guardar.
  • Orden de tabulación se determina por el orden en que los controles se agregan a aControls (es decir, el orden de tus comandos @).
  • Controles transparentes — Establece lTransparent := .T. (o cláusula TRANSPARENT) al colocar controles sobre fondos de gradiente o bitmap.
  • oJump — Establece oGet1:oJump := oGet3 para saltar un campo en la secuencia de tabulación condicionalmente.
  • Redimensionamiento proporcional — Los métodos CalcSize() y SetResizeType() (añadidos en 2024) permiten diseños con coordenadas relativas donde los controles escalan proporcionalmente con el padre.
  • Colores — El método Colors( hDC ) gestiona los mensajes WM_CTLCOLOR. Sobrescríbelo en las subclases para un comportamiento de color personalizado.
