TIcon

Fuente: source/classes/icon.prg

Hereda de: TControl

TIcon es un control para mostrar iconos de Windows (.ico) desde archivos o recursos del programa. Admite acciones de clic, cambio dinámico de icono, visualización de borde y la liberación adecuada de recursos. TIcon se usa habitualmente para indicadores de barra de herramientas, iconos de estado y elementos decorativos en ventanas y diálogos.

Miembros DATA Principales

DATATipoDescripción
hIconNumérico (Handle)Handle del icono de Windows (HICON)
cIcoFileCarácterRuta al archivo .ico
cResNameCarácterNombre del recurso de icono en el ejecutable

Métodos Principales

MétodoDescripción
New( nRow, nCol, cRes, cFile, lBorder, bClick, oWnd )Crea un control de icono. Proporcione cRes (nombre del recurso) o cFile (ruta del archivo .ico).
ReDefine( nId, cRes, cFile, bClick, lUpdate, oDlg )Redefine a partir de una plantilla de recurso de diálogo
SetName( cResName )Cambia a un recurso de icono diferente por nombre. Destruye el handle del icono anterior.
SetFile( cIcoFile )Cambia a un archivo .ico diferente. Destruye el handle del icono anterior.
End()Destruye el handle del icono y llama al End() de la superclase

Comando ICON

@ nRow, nCol ICON oIcon OF oWnd FILE cFile

Ejemplo

#include "FiveWin.ch"

function Main()

   local oWnd, oIcon

   DEFINE WINDOW oWnd TITLE "Icon Demo" SIZE 300, 200

   // Muestra un icono desde un archivo
   @ 10, 10 ICON oIcon OF oWnd FILE "myapp.ico"

   // Hace el icono clicable
   oIcon:bLClicked := {|| MsgInfo( "Icon clicked!" ) }

   ACTIVATE WINDOW oWnd CENTERED

return nil

Notas

  • El icono se carga desde un archivo (cIcoFile mediante ExtractIcon()) o desde un recurso del programa (cResName mediante LoadIcon()). Se debe proporcionar uno de los dos.
  • El tamaño de icono predeterminado es de 32x32 píxeles, determinado por las constantes de clase ICO_CHARPIX_H (14) e ICO_CHARPIX_W (8) multiplicadas por las coordenadas de fila/columna.
  • Use SetName() y SetFile() para cambiar el icono mostrado en tiempo de ejecución. Ambos métodos destruyen correctamente el handle del icono anterior para evitar fugas de recursos.
  • Asigne un bloque de código a bLClicked para gestionar los eventos de clic sobre el icono.
  • El método Destroy() garantiza que el handle del icono se libere mediante DestroyIcon() cuando se destruye el control.
