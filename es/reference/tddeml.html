TDDEMLClient / TDDEMLServer

Fuentes: source/classes/tddemlcl.prg, source/classes/tddemlsv.prg

Clases independientes

Las clases de la DDE Management Library (DDEML) proporcionan una interfaz de alto nivel para el Intercambio Dinámico de Datos (DDE) de Windows mediante la API DDEML. TDDEMLClient se conecta a servidores DDE y ejecuta comandos o solicita datos; TDDEMLServer registra un servidor DDE que responde a las solicitudes de los clientes. Ambas clases gestionan las conversaciones, el registro de servicios/temas y la transferencia de datos a través del protocolo DDEML.

TDDEMLClient

TDDEMLClient se conecta a un servidor DDE existente, envía comandos y solicita datos.

Miembros DATA Principales

DATATipoDescripción
hInstNuméricoManejador (handle) de la instancia DDEML
hConvNuméricoManejador de la conversación tras una conexión correcta
cServiceCarácterCadena con el nombre del servicio
hServiceNuméricoManejador del servicio
cTopicCarácterCadena con el nombre del tema
hTopicNuméricoManejador del tema
nTimeOutNuméricoTiempo de espera en milisegundos para las operaciones DDE

Métodos Principales

MétodoDescripción
New()Crea el cliente DDE e inicializa DDEML
Connect( cSvc, cTopic )Se conecta a un servidor DDE en el servicio/tema indicado
Disconnect()Finaliza la conversación DDE
Execute( cCmd )Envía una cadena de comando al servidor para su ejecución
Request( cReq )Solicita datos al servidor; devuelve la cadena con el resultado
NetConnect( cSvr, cApp )Se conecta a un servidor DDE en una máquina remota de la red

TDDEMLServer

TDDEMLServer se registra como servidor DDE, escuchando las conexiones de los clientes y respondiendo a las operaciones de ejecución/solicitud.

Miembros DATA Principales

DATATipoDescripción
hInstNuméricoManejador (handle) de la instancia DDEML
aClientsArrayArray de manejadores de conversación de los clientes conectados
bOnConnectBloqueBloque de código evaluado cuando un cliente se conecta
bOnRequestBloqueBloque de código evaluado cuando un cliente solicita datos; devuelve el resultado
bOnDisconnectBloqueBloque de código evaluado cuando un cliente se desconecta
bOnExecuteBloqueBloque de código evaluado cuando un cliente envía un comando

Métodos Principales

MétodoDescripción
New()Crea el servidor DDE e inicializa DDEML
Connect()Registra el nombre de servicio del servidor y comienza a escuchar
ConnectConfirm( hConv )Acepta y confirma la conversación de un cliente
Disconnect( hConv )Finaliza la conversación de un cliente
Execute( cCmd )Procesa un comando enviado por un cliente
Request( cReq, cTopic )Atiende una solicitud de datos de un cliente; devuelve la cadena con el resultado
SetNetDDE( lOn )Activa o desactiva el soporte de DDE en red
_Return( cData )Devuelve datos a la solicitud de un cliente; devuelve el manejador hData

Ejemplo: Servidor y Cliente DDE

#include "FiveWin.ch"

// Lado del servidor
function DdeServer()

   local oServer := TDDEMLServer():New()

   oServer:bOnConnect := { |hConv| ;
      QOut( "Client connected: " + Str( hConv ) ) }

   oServer:bOnRequest := { |cReq, cTopic| ;
      "Server received: " + cReq }

   oServer:bOnExecute := { |cCmd| ;
      QOut( "Executing: " + cCmd ) }

   oServer:Connect()

return oServer

// Lado del cliente
function DdeClient()

   local oClient := TDDEMLClient():New()

   if oClient:Connect( "MyService", "MyTopic" )
      oClient:Execute( "[SAVE]" )
      ? oClient:Request( "GetData" )
      oClient:Disconnect()
   endif

   oClient:End()

return nil

Notas

  • Ambas clases requieren la librería DDEML de Windows (USER32.DLL). Inicialice con DdeInitialize() y libere los recursos con DdeUninitialize().
  • El método Request() en el lado del cliente devuelve una cadena de caracteres. En el lado del servidor, Request() debe devolver los datos a enviar, y _Return() los empaqueta en un manejador de datos DDEML.
  • Use NetConnect() en el cliente para conectarse entre máquinas mediante DDE en red (requiere que el DDE en red esté habilitado en ambos sistemas).
  • Los bloques de retrollamada del servidor reciben el manejador de la conversación como parámetro, lo que permite la gestión de múltiples clientes a través del array aClients.
