Sistema de Errores

Fuente: source/function/errsysw.prg

FiveWin reemplaza el manejador de errores predeterminado de Harbour con un diálogo de error basado en GUI que muestra información diagnóstica detallada. El sistema de errores se inicializa automáticamente al inicio de la aplicación a través del procedimiento ErrorSys(), que establece un bloque de error que llama a ErrorDialog().

Diálogo de Error

El diálogo de error de FiveWin es un diálogo moderno y rico en funciones que se adapta al tema del sistema:

  • Detección automática de modo oscuro -- el diálogo lee la clave del registro "AppsUseLightTheme" de Windows y ajusta su esquema de colores en consecuencia
  • Mensaje de error -- mostrado prominentemente en la parte superior
  • Pila de llamadas -- mostrada en un listbox con nombres de procedimientos, números de línea y archivos fuente
  • Botones de acción:
    • Salir -- escribe error.log y termina
    • Reintentar -- devuelve .T. (si e:canRetry)
    • Por Defecto -- devuelve .F. (si e:canDefault)
    • Depurar -- activa el depurador (si está disponible)
  • Botón Copiar -- copia el registro de error completo al portapapeles
  • Botón Ver -- abre error.log en el Bloc de Notas

Personalizar el Sistema de Errores

SetErrorPath() / SetErrorFileName()

// Cambiar la ubicación del registro de errores
SetErrorPath( "C:\logs\" )
SetErrorFileName( "myapp_error.log" )

SetErrorDialog() -- Diálogo Personalizado

// Reemplazar el diálogo de error completo con uno personalizado
SetErrorDialog( { |oDlg, e, cLog, aStack|
   // oDlg es el diálogo que se está creando
   // e es el objeto de error
   // cLog es el texto del registro de error
   // aStack es el array de la pila de llamadas
   // Devuelve: nil (usar botones por defecto) o manejar botones usted mismo
} )

SetPostErrorAction() -- Gancho Post-Error

// Ejecutar código después de que se cierre el diálogo de error
SetPostErrorAction( { |e, cLog|
   // Enviar informe de error al servidor
   SendErrorReport( cLog )
   // o reiniciar la aplicación
   // WinExec( GetModuleFileName( GetInstance() ) )
} )

ErrorBlock Personalizado

// Reemplazar el manejador de errores completamente
ErrorBlock( { |e| MyErrorHandler( e ) } )

static function MyErrorHandler( e )

   // Registrar en archivo
   LogFile( "errors.log", { e:Description, e:Operation, ;
      ProcName(4), ProcLine(4) } )

   // Mostrar mensaje simple
   MsgStop( e:Description + CRLF + ;
      "en " + ProcName(4) + "(" + LTrim( Str( ProcLine(4) ) ) + ")" )

   // Salir de la aplicación
   PostQuitMessage( 0 )
   __Quit()

return nil

Ejemplo: Bloques TRY/CATCH

#include "FiveWin.ch"

function Main()

   local xResult

   // TRY/CATCH previene que se muestre el diálogo de error
   TRY
      xResult := SomeRiskyOperation()
      MsgInfo( "Resultado: " + cValToChar( xResult ) )
   CATCH e
      MsgAlert( "Error: " + e:Description + CRLF + ;
         "Operación: " + e:Operation )
   END

return nil

Ejemplo: Manejador de Error Personalizado con Email

#include "FiveWin.ch"

function Main()

   // Instalar acción post-error personalizada
   SetPostErrorAction( { |e, cLog|
      // Guardar registro de error
      MemoWrit( "crash_" + DToS( Date() ) + "_" + StrTran( Time(), ":", "" ) + ".log", cLog )

      // Podría enviar notificación por email aquí
      // SendMail( "admin@company.com", "App Crash", cLog )
   } )

   // Cambiar ubicación del registro de errores
   SetErrorPath( "C:\logs\" )
   SetErrorFileName( "app_errors.log" )

   // ... resto de la aplicación ...
   AppMain()

return nil

Propiedades del Objeto de Error

El objeto de error e pasado al manejador de errores es un objeto Error estándar de Harbour:

PropiedadTipoDescripción
e:DescriptionCharacterDescripción legible del error
e:OperationCharacterLa operación que causó el error
e:SubSystemCharacterNombre del subsistema (BASE, DBCMD, etc.)
e:genCodeNumericCódigo genérico de error (EG_*)
e:subCodeNumericCódigo de error específico del subsistema
e:osCodeNumericCódigo de error del sistema operativo
e:ArgsArrayArgumentos que causaron el error
e:canRetryLogicalSi es posible reintentar
e:canDefaultLogicalSi es posible la acción por defecto
e:canSubstituteLogicalSi se puede devolver un valor sustituto
e:FileNameCharacterArchivo que causó el error (si aplica)

Soporte Multi-Idioma

El diálogo de error usa FWString() para todo el texto visible al usuario, por lo que se adapta automáticamente al idioma establecido por FWSetLanguage(). Las cadenas soportadas incluyen "Application", "Path and name", "Date", "Time", descripciones de error y etiquetas de botones.
