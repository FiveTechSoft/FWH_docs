ORM_Connection + ORM_Table

Fuente: source/classes/fworm.prg

Las clases ORM (Mapeo Objeto-Relacional) proporcionan una capa de abstracción multi-backend que funciona con conexiones ADO, FWH (MariaDB) y Dolphin (DLP). ORM_Connection gestiona el enlace con la base de datos y expone las tablas como objetos ORM_Table. ORM_Table proporciona una interfaz fluida de construcción de consultas con métodos encadenables Where/OrderBy/Select, funciones de agregación, navegación entre relaciones y acceso dinámico a campos mediante un manejador de errores.

Arquitectura

flowchart LR App[Aplicación] --> OC[ORM_Connection] OC --> OT[ORM_Table] OT --> RS[Conjunto de Resultados] OC --> ADO[ADO] OC --> FWH[FWMariaConnection] OC --> DLP[Dolphin]

ORM_Connection

ORM_Connection abstrae las conexiones a bases de datos a través de tres backends: ADO (para cualquier RDBMS compatible con ODBC), FWH (MariaDB nativo mediante FWMariaConnection) y DLP (la librería Dolphin para MariaDB). Acepta tanto parámetros de conexión como un objeto de conexión existente.

ORM_Table

ORM_Table proporciona navegación del recordset, construcción de consultas y manipulación de datos para una única tabla de la base de datos. Su manejador de errores expone los valores de los campos como propiedades dinámicas y las sub-tablas como objetos ORM_Table relacionados.

Acceso Dinámico a Campos

ORM_Table usa un manejador de errores para proporcionar acceso directo de tipo propiedad a los valores de los campos. Cualquier mensaje que coincida con el nombre de un campo de la tabla se traduce automáticamente a un get/set de campo: 

// En lugar de: oTable:Get( "name" )
? oTable:name        // acceso dinámico mediante el manejador de errores
oTable:city := "Madrid"   // asignar valor de campo

De forma similar, acceder a una propiedad que coincide con el nombre de otra tabla devuelve un nuevo ORM_Table para esa tabla, permitiendo una navegación fluida entre tablas relacionadas: 

// Si "orders" es una tabla, esto devuelve un ORM_Table para orders:
oTable:orders:Where( "status = 'active'" )

Ejemplo: Encadenar Consultas con Relaciones

#include "FiveWin.ch"

function Main()

   local oCn, oCustomers

   // Crear conexión a MariaDB mediante el backend FWH
   oCn := ORM_Connection():New( "FWH", "localhost", "mydb", "root", "password" )
   if oCn == nil
      MsgStop( "Connection failed" )
      return nil
   endif

   // Obtener una tabla y encadenar filtros de consulta
   oCustomers := oCn:Table( "customers" )

   oCustomers:Where( "city", "Madrid" ):OrderBy( "name" )

   oCustomers:First()
   while !oCustomers:oRs:Eof()
      ? oCustomers:name, oCustomers:email   // acceso dinámico a campos
      oCustomers:Next()
   end

   // Agregación
   ? "Total customers in Madrid:", oCustomers:Count()
   ? "Max credit:", oCustomers:Max( "credit_limit" )

   // Buscar por clave primaria
   oCustomers:Find( 101 )
   ? oCustomers:name

   // Añadir un nuevo registro
   oCustomers:Add( { "name", "email" }, { "New Client", "client@test.com" } )

   oCn:Close()

return nil

Notas

  • Los métodos Where(), OrderBy() y Select() de ORM_Table son encadenables -- cada uno devuelve el objeto Self, permitiendo una sintaxis fluida como oTable:Where(...):OrderBy(...):First().
  • El método Where() acepta varias convenciones de llamada: Where( "field = value" ), Where( "field", value ), Where( "field", "LIKE", "%pattern%" ), o Where( "field", ">=", 100 ).
  • El método Relate() enlaza dos instancias de ORM_Table de modo que al navegar por la tabla padre se filtra automáticamente el recordset de la tabla hija según el valor de la clave foránea.
  • El manejador de errores dinámico hace que el acceso a los campos se sienta como acceso nativo a propiedades: oTable:fieldname (lectura) y oTable:fieldname := value (escritura).
  • Los métodos de agregación (Count, Sum, Max, Min, Avg, Std) respetan las condiciones Where() actuales.
