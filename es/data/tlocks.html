TLocks

Fuente: source/classes/tlocks.prg

Clase independiente

TLocks proporciona un mecanismo de bloqueo de registros para tablas ODBC. Gestiona una tabla de bloqueos dentro de la base de datos que rastrea qué registros están bloqueados y por qué conexión. Esto habilita un control de concurrencia pesimista básico para orígenes de datos ODBC que no proporcionan bloqueo nativo a nivel de registro.

Miembros DATA Clave

DATATipoDescripción
oOdbcObjetoObjeto de conexión TODBC para acceso a la base de datos
cTableCarácterNombre de la tabla que se está bloqueando
nIdNuméricoIdentificador de conexión o sesión

Métodos

MétodoDescripción
New( oOdbc, cTable )Crea un nuevo gestor de bloqueos para la conexión ODBC y tabla especificadas
CreateEnviroment()Crea el entorno de seguimiento de bloqueos (tabla de bloqueos) si no existe
Lock( nRecNo )Bloquea un pseudo-registro por número de registro
UnLock( nRecNo )Libera el bloqueo de un pseudo-registro
RefreshLock( nRecNo )Refresca la marca de tiempo del bloqueo para evitar la expiración por tiempo de espera
SeekRegLock( nRecNo )Comprueba si un pseudo-registro está actualmente bloqueado

Ejemplo: Bloquear/Desbloquear un Pseudo-Registro

#include "FiveWin.ch"

function Main()

   local oOdbc, oLocks

   oOdbc := TODBC():New( "MyDSN", "user", "pass" )

   if oOdbc:lSuccess
      oLocks := TLocks():New( oOdbc, "CUSTOMERS" )

      // Asegura que el entorno de bloqueo existe
      oLocks:CreateEnviroment()

      // Bloquea el registro número 101
      if oLocks:Lock( 101 )
         MsgInfo( "Record 101 locked" )

         // Trabaja con el registro...

         // Libera el bloqueo
         oLocks:UnLock( 101 )
         MsgInfo( "Record 101 unlocked" )
      else
         MsgAlert( "Could not lock record 101" )
      endif
   endif

return nil

Notas

  • TLocks utiliza una tabla de bloqueos separada en la base de datos ODBC para rastrear los bloqueos a nivel de registro. Esta tabla se crea automáticamente mediante CreateEnviroment() y almacena información clave como el número de registro, el ID de sesión y la marca de tiempo del bloqueo.
  • El bloqueo pesimista significa que un bloqueo se adquiere antes de editar y se mantiene hasta que se libera explícitamente. Otras sesiones que intenten bloquear el mismo registro fallarán hasta que se libere el bloqueo.
  • Use RefreshLock() periódicamente durante sesiones de edición largas para evitar que el bloqueo expire por tiempo de espera.
  • SeekRegLock() permite comprobar si un registro específico está actualmente bloqueado sin intentar adquirir el bloqueo.
  • Libere siempre los bloqueos con UnLock() tan pronto como se complete la edición para evitar bloquear a otros usuarios.
