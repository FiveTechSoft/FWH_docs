TPostgreSQL + Funciones FWPG_*

Fuente: source/function/pgsuport.prg

FiveWin proporciona integración con PostgreSQL mediante el módulo pgsuport.prg, que conecta la biblioteca Harbour hbpgsql (un envoltorio de libpq) con componentes de FWH como TXBrowse y TDataRow. En lugar de requerir un enlazado en tiempo de compilación con hbpgsql, el módulo utiliza un mecanismo de carga diferida para resolver los punteros de función de libpq en tiempo de ejecución, haciendo opcional la dependencia de la biblioteca.

PGLinked() - Resolución de Funciones por Carga Diferida

La función estática interna PGLinked() se invoca automáticamente en la primera llamada a cualquier función FWPG_. Utiliza HB_FUNCPTR() para localizar los envoltorios de libpq a nivel de Harbour proporcionados por la biblioteca hbpgsql. Si se encuentra PQEXEC, los punteros se almacenan en caché para las siguientes operaciones:

Variable de PunteroFunción hbpgsqlPropósito
pPQExecPQEXECEjecución síncrona de comandos
pPQExecParamsPQEXECPARAMSEjecución parametrizada de comandos
pPQMetaDataPQMETADATAObtención del esquema del conjunto de resultados
pPQGetValuePQGETVALUEObtención de datos para una fila/columna específica
pPQResultStatusPQRESULTSTATUSComprobación de estado (Éxito / Tuplas / Error)
pPQlastrecPQLASTRECObtención del número de filas
pPQFCountPQFCOUNTObtención del número de columnas
pPQcmdTuplesPQCMDTUPLESFilas afectadas para DML
pPQresultErrorMessagePQRESULTERRORMESSAGETexto detallado del error del servidor

Estos punteros de función resueltos se invocan a través del mecanismo HB_ExecFromArray() mediante macros #xtranslate (PQ_Exec, PQ_ExecParams, PQ_MetaData, etc.).

FWPG_Execute() - Ejecución de Consultas

La función central para toda interacción con PostgreSQL es FWPG_Execute:

Firma:

FWPG_Execute( pDB, cSql, aParams )  && -> aResult | nAffected | .F.

Parámetros:

  • pDB - El objeto de conexión a la base de datos (o su manejador :pDB).
  • cSql - La sentencia SQL a ejecutar.
  • aParams - Array opcional de valores de parámetros para consultas parametrizadas.

Valores de retorno:

  • Para consultas SELECT (PGRES_TUPLES_OK): Devuelve un array 2D (filas x columnas) de valores con tipos de Harbour.
  • Para comandos DML (PGRES_COMMAND_OK): Devuelve el número de filas afectadas.
  • En caso de error: Establece el estado de error en el objeto de conexión y devuelve .F..

Cuando se suministran parámetros mediante aParams, cada valor se convierte a una cadena segura para SQL usando FW_ValToSQL(u, , "PG") y la consulta se ejecuta a través de PQ_ExecParams, evitando la inyección SQL.

Funciones de Metadatos y Estructura

FWPG_MetaStruct()

FWPG_MetaStruct( res )  && -> aStruct

Devuelve un array de metadatos de columna para un resultado de consulta. Cada elemento es un array indexado por las siguientes constantes:

ÍndiceConstanteValorDescripción
1_STRU_FIELDNAME1Nombre del campo (columna)
2_STRU_FIELDTYPE2Código de tipo Harbour
3_STRU_FIELDLEN3Longitud del campo
4_STRU_FIELDDEC4Posiciones decimales
5_STRU_TABLE5OID de la tabla
6_STRU_TABLECOL6Ordinal de la columna dentro de la tabla
7_STRU_TABLENAME7Nombre de la tabla de origen
8_STRU_COLNAME8Nombre de la columna en la tabla de origen
9_STRU_DEFAULT9Expresión del valor por defecto
10_STRU_PRI10Indicador de clave primaria ("PRI" si es clave)

FWPG_Structure()

FWPG_Structure( oQry )  && -> aStruct

Devuelve un array de estructura mejorado para un objeto de consulta PostgreSQL. Enriquece el aStruct base con el nombre de tabla, el nombre de columna y la información de clave primaria consultando information_schema.columns. Ajusta los tipos de campo para bytea (mapeado a "m"), timestamp (mapeado a "T") y columnas autoincrementales (mapeadas a "+").

FWPG_FieldGet()

FWPG_FieldGet( oQry, nFldNo )  && -> uVal

Un getter de campo especializado que maneja el formato específico de PostgreSQL:

  • Convierte los prefijos hexadecimales \x (de columnas bytea) a cadenas binarias.
  • Procesa valores timestamp con FW_STR2DT().
  • Aplica relleno Unicode mediante FW_UTF8PADCHAR() cuando el modo Unicode está activo.
  • Acepta nombres de campo (carácter) además de posiciones numéricas de campo.
  • Recurre a evaluar bloques de expresión para columnas calculadas.

FWPG_Skipper()

FWPG_Skipper( oQry, nSkip )  && -> nSkipped

Ayudante de navegación usado por los bloques de código de TXBrowse para el salto de registros. Calcula el nuevo desplazamiento de registro relativo a la posición actual, acotándolo al rango válido [1, nLastRec]. Devuelve el número real de registros saltados.

Integración con TXBrowse

TXBrowse consume conjuntos de datos de PostgreSQL a través de interfaces estándar de bloques de código. La función FWPG_Skipper proporciona el bloque de código bSkip; los bloques de código bGoTop, bGoBottom, bEof, bBof y bBookMark del objeto de consulta se establecen directamente sobre dicho objeto. La edición directa en celda se soporta mediante FWPG_XBrSaveData( oCol, xValue ), que construye y ejecuta SQL UPDATE dirigido a la clave primaria de la tabla de origen.

Integración con TDataRow

TDataRow proporciona soporte nativo de PostgreSQL a través de dos métodos internos:

  • ReadPQQ: Lee los valores de campo y los metadatos desde un objeto de consulta PostgreSQL al búfer de edición de TDataRow (aData/aOrg).
  • SavePQQ: Genera y ejecuta las sentencias SQL UPDATE o INSERT necesarias mediante FWPG_Execute para persistir los cambios realizados a través de la interfaz de la fila de datos.

Ejemplo: Conectar, Consultar y Navegar

#include "FiveWin.ch"

function Main()

   local oServer, oQry, oWnd, oBrw, aDbs

   // Abrir una conexión PostgreSQL usando hbpgsql
   oServer := TPostgreSQL():New( "localhost", "mydb", "postgres", "password", 5432 )

   if oServer:lError
      MsgStop( "Connection failed: " + oServer:cError )
      return nil
   endif

   // Listar las bases de datos disponibles
   aDbs := FWPG_ListDbs( oServer )
   XBROWSER aDbs TITLE "Databases on Server"

   // Ejecutar una consulta
   oQry := TPostgreSQLQuery():New( oServer, "SELECT id, name, email, city FROM customers ORDER BY name" )

   if oQry:nLastRec > 0
      DEFINE WINDOW oWnd TITLE "Customers"

      @ 0, 0 XBROWSE oBrw OF oWnd ;
         COLUMNS "id", "name", "email", "city" ;
         COLSIZES 50, 200, 250, 150

      oBrw:nMarqueeStyle   := 3
      oBrw:lCanPaste       := .t.

      // Conectar XBrowse a la consulta PostgreSQL mediante bloques de código
      oBrw:bSkip       := { |nSkip| FWPG_Skipper( oQry, nSkip ) }
      oBrw:bGoTop      := { || oQry:GoTop() }
      oBrw:bGoBottom   := { || oQry:GoBottom() }
      oBrw:bEof        := { || oQry:RecNo() > oQry:nLastRec }
      oBrw:bBof        := { || oQry:RecNo() == 0 }
      oBrw:bBookMark   := { || oQry:RecNo() }
      oBrw:bStrData    := { |n| FWPG_FieldGet( oQry, n ) }
      oBrw:bKeyNo      := { || oQry:RecNo() }

      oBrw:CreateFromCode()

      ACTIVATE WINDOW oWnd MAXIMIZED
   else
      MsgInfo( "No records found" )
   endif

   oQry:End()
   oServer:End()

return nil

Notas

  • El soporte de PostgreSQL requiere que la biblioteca Harbour hbpgsql esté enlazada en su aplicación. La función PGLinked() resuelve los punteros de función de la biblioteca en tiempo de ejecución; si hbpgsql no está enlazada, todas las funciones FWPG_ devuelven .F. de forma controlada.
  • Las consultas parametrizadas mediante aParams son muy recomendables para SQL dinámico con el fin de prevenir ataques de inyección. Los valores se escapan usando FW_ValToSQL( u, , "PG" ).
  • La integración con TDataRow (ReadPQQ/SavePQQ) permite la edición registro a registro con seguimiento automático de cambios y generación de SQL.
  • La edición en celda mediante XBrowse (FWPG_XBrSaveData) requiere que la tabla de origen de la consulta tenga una clave primaria definida y que se haya llamado a FWPG_Structure() para poblar los metadatos de estructura.
  • La función FWPG_Structure() consulta automáticamente information_schema.columns para resolver los nombres de tabla y columna a partir de referencias OID, proporcionando metadatos completos para consultas JOIN complejas.
