FWH Glossary

Definitions for FiveWin-specific terms, covering framework architecture, Harbour/xHarbour language features, UI control concepts, database connectivity, character encodings, and programming paradigms used throughout the FWH codebase. Terms are organized alphabetically.

ACCESS / ASSIGN

Harbour class property accessors. ACCESS defines a read-only getter method; ASSIGN defines a writeable setter method. They are used alongside DATA to control how class member variables are read and written externally, enabling validation and computed properties.

ADO (ActiveX Data Objects)

Microsoft's COM-based data access framework. FWH's TRecordSet class wraps ADO to provide client-server database access (SQL Server, Access, etc.) with cursor-style navigation and SQL execution.

ALIGN clause

A FiveWin clause in control definitions that specifies text or content alignment within the control area. Values include ALIGN LEFT, ALIGN CENTER, and ALIGN RIGHT, commonly used with SAY and BUTTON controls.

ANSI (Windows-1252)

The default Windows code page (Latin-1, CP-1252). FWH uses CP_ACP (which maps to ANSI) for dialog template text conversion in dlg2chr.c and ctrl2chr.c. See also OEM and Unicode entries in this glossary.

BITMAP / IMAGE resources

A resource type embedded in compiled executables via .res / .rc files. FWH controls reference them by name or integer ID, e.g., RESOURCE "MYBITMAP". Supported formats include BMP, ICO, PNG, and JPEG depending on the rendering context.

BOM (Byte Order Mark)

The Unicode character U+FEFF, placed at the start of UTF-16 or UTF-8 text files to indicate encoding. In FWH contexts, the BOM is relevant when reading or writing Unicode text files, particularly in Harbour file I/O operations and HTML content generation.

Buffer (aOrg / aData)

FWH's record-editing mechanism in TDataRow and TDataBase. Two parallel arrays track changes: aOrg stores the original values loaded from disk, aData holds pending user modifications. Changes are committed to the database only when the record is explicitly saved.

BWCC (Borland Windows Custom Controls)

A legacy UI library from Borland providing chiseled frames, dithered-gray backgrounds, and custom controls (BorBtn, BorCheck, BorRadio, BorStatic, BorShade). FWH includes a 64-bit clean-room reimplementation in dll/bwcc64.dll for 64-bit applications.

CLASSDATA

A Harbour keyword declaring class-level (static) data members shared across all instances of a class. Unlike DATA (which creates per-instance copies), CLASSDATA stores one value for the entire class hierarchy.

Codeblock

An anonymous, compilable chunk of Harbour code delimited by { |params| ... }. Codeblocks are the foundation of FWH's event and callback system. Properties like bAction, bChange, bWhen, and bValid are all codeblock references.

COM (Component Object Model)

Microsoft's inter-process communication and object technology. FWH uses COM through TActiveX for embedding ActiveX controls and TComObject for OLE/COM automation, such as interacting with Excel or ADO.

Connection Object

In FWH's MariaDB/MySQL integration, an instance of FWMariaConnection (created by maria_Connect()) that manages the TCP connection, authentication, and query session to a MariaDB or MySQL server.

Cue Text / Cue Banner

Placeholder text displayed inside a TGet control when it is empty and does not have focus. Set via TGet:cCueText. Implemented using the Windows EM_SETCUEBANNER message (0x1501).

DATA (class instance variable)

A Harbour keyword that declares per-instance variables in a class definition. Each object maintains its own copy. Example: DATA nValue in a class definition creates an nValue member for every instance.

Design Mode

A runtime state (TWindow:lDesign := .T.) where controls can be moved and resized interactively. Used by the Visual IDE (visualfw.exe) for drag-and-drop form layout at development time.

DSN (Data Source Name)

A Windows ODBC configuration entry specifying which database driver, server address, and authentication to use for a connection. FWH's TODBC class can connect using a predefined DSN or a DSN-less connection string.

Error Handler (ON ERROR)

Harbour's error recovery mechanism, triggered by ON ERROR or through the ErrorBlock() function. FWH's default error handler (source/function/errsysw.prg) provides a visual dialog with stack trace and variable inspection for debugging.

FiveWin.ch

The master header file for FWH applications. Defines all #xcommand and #xtranslate preprocessor translations that enable the natural-language syntax (DEFINE WINDOW, @ ... SAY, @ ... GET, etc.). Every FWH application includes this file.

FW_ prefix convention

FWH prefixes its global functions and constants with FW_ (e.g., FW_ReadImage(), FW_JsonDecode()) to avoid naming collisions with user code and Harbour/xHarbour runtime functions.

FWH abbreviation

"FiveWin for Harbour" (also "FiveWin for xHarbour"). A GUI framework that wraps the Windows API into a Clipper/xBase object-oriented programming environment, providing classes for windows, dialogs, controls, printing, database access, and AI integration.

GDI / GDI+ (Graphics Device Interface)

Windows graphics subsystems. GDI handles basic 2D drawing (lines, shapes, text). GDI+ (accessed via gdipfwh.cpp) adds alpha blending, anti-aliasing, JPEG/PNG support, and gradient fills. FWH uses GDI+ for modern rendering in TBtnBmp, TImage, and print preview.

Harbour vs xHarbour

Two open-source Clipper/xBase compilers. Harbour is the modern, actively maintained implementation used by most FWH users. xHarbour is an older fork supported for legacy compatibility; it requires a compatibility header (fwhxhb.h) for 64-bit builds.

hbcompat.ch

A Harbour compatibility header mapping xHarbour-specific functions and commands to Harbour equivalents. It is deliberately not included automatically by fivewin.ch, because its IN to $ translation would break code using patterns like BOEK->IN.

Infield Styling

A TGet display mode (lInfield := .T.) where the field caption or label is rendered inside the edit control area, overlapping or alongside the value text. Used for compact, label-less UI layouts.

Marquee Style (XBrowse)

A TXBrowse property (nMarqueeStyle) controlling how the current row selection is visually highlighted. Common values: MARQSTYLE_HIGHLROW (solid single-row), MARQSTYLE_HIGHLROWMS (multiple row selection).

MDI (Multiple Document Interface)

A windowing paradigm where child document windows are confined within a single parent MDI frame. FWH supports MDI via TMDIFrame and TChild classes, with automatic window arrangement and menu merging.

METHOD

A Harbour keyword that defines a function belonging to a class. Methods receive the implicit Self parameter referencing the object instance. FWH methods are defined as METHOD Name() inside the class definition and implemented later.

ODBC (Open Database Connectivity)

A standardized C API for database access. FWH provides TODBC for ODBC-based connections using either a named DSN or a DSN-less connection string.

OEM (Code Page 437/850)

The character encoding used by the MS-DOS console and Windows OEM font. In FWH's Unicode support code (fwunicode.c), OEM codepages (values below 1250) are skipped when bAnsiOnly is TRUE, preventing CP437/CP850 text from being mis-converted.

OLEDB

Microsoft's COM-based successor to ODBC for universal data access. FWH's TRecordSet can use OLEDB providers for database connectivity, providing an alternative to DSN-based ODBC connections.

OOP vs traditional xBase

FiveWin brings full object-oriented programming (classes, inheritance, encapsulation, polymorphism) to the Clipper/xBase world. Traditional xBase uses procedural functions and work areas (USE, SELECT), while FWH code defines and instantiates objects with methods and data.

PIXEL clause

A clause in control definitions (@ nRow, nCol ... PIXEL) that interprets coordinates in pixels rather than the default character-based grid. Essential for precise positioning, especially with DEFINE WINDOW (as opposed to DEFINE DIALOG) in pure PRG layouts.

#pragma /b+ (debugger)

A Harbour compiler directive enabling the embedded debugger. Placing #pragma /b+ at the top of a source file activates the HB_DBG engine, allowing breakpoints, variable inspection, and step-through debugging.

#pragma BEGINDUMP

A Harbour directive that transitions the compiler from Harbour syntax to C syntax within the same source file. Used in .prg files to embed inline C code that is compiled by the C compiler, enabling low-level Windows API calls without a separate .c file.

RDD (Replaceable Database Driver)

An abstraction layer in Harbour/xHarbour allowing the same code to work with different database file formats. Common RDDs: DBFNTX (Clipper-compatible), DBFCDX (FoxPro indexes), DBFDBT (memo fields). All FWH database classes sit on top of the RDD layer.

REDEFINE

A FiveWin command syntax for binding a class instance to an existing control in a dialog resource (.rc file). Example: REDEFINE GET oVar ID 101 OF oDlg connects a TGet object to a dialog control by its resource ID.

RowSet

An in-memory representation of a SQL query result, specifically in FWH's MariaDB/MySQL integration. Created by mysql_RowSet(), it provides cursor-style navigation, lazy fetching through a linked-list structure, and supports bOnMove for row-change events.

SDI (Single Document Interface)

The modern windowing paradigm where each document or view has its own independent top-level window, as opposed to MDI where children are confined within a parent frame. Most contemporary FWH applications use SDI.

SeekBar (incremental search)

An integrated UI element in TXBrowse (TXBrowse:oSeek) that displays a floating edit field. Users type filter criteria incrementally, and the browse automatically scrolls to matching rows as they type. Enabled via bSeek codeblock.

T-prefix class naming

FWH's convention of prefixing all class names with T (e.g., TWindow, TButton, TXBrowse, TGet). This distinguishes class types from traditional xBase function names and provides a consistent, recognizable naming pattern.

Themed Controls

FWH support for Windows visual styles, controlled by DATA members like TBtnBmp:lThemed, TBtnBmp:l2007, TBtnBmp:l2010, TBtnBmp:l2013, and TBtnBmp:l2015. Themed controls automatically adapt their appearance to the user's current Windows theme.

TRANSPARENT clause

A clause that sets the WS_EX_TRANSPARENT extended style on a control, making it transparent to mouse clicks and allowing parent window controls to show through the background. Used in layered UI designs.

Unicode (UTF-8 / UTF-16)

Universal character encoding standards. Windows uses UTF-16 internally; FWH converts between Harbour strings (typically ANSI or OEM) and UTF-16 for Windows API calls. UTF-8 is used for JSON communication, REST API payloads (AI classes), and the HTML documentation.

WYSIWYG

"What You See Is What You Get." FWH's report and print preview systems (TReport, TPreview) provide WYSIWYG display, showing on screen exactly how output will appear on paper, including fonts, margins, and graphics placement.

#xcommand / #xtranslate

Harbour preprocessor directives that define pattern-based text translations. FWH's FiveWin.ch uses these extensively to create the natural-language domain-specific language (DSL) for defining windows, dialogs, controls, and menus with intuitive syntax.
