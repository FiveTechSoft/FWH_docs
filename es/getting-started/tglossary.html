Glosario FWH

Definiciones de términos específicos de FiveWin, que abarcan la arquitectura del framework, las características del lenguaje Harbour/xHarbour, los conceptos de controles de interfaz de usuario, la conectividad a bases de datos, las codificaciones de caracteres y los paradigmas de programación utilizados a lo largo del código de FWH. Los términos están organizados alfabéticamente.

ACCESS / ASSIGN

Accesores de propiedades de clase de Harbour. ACCESS define un método de lectura (getter) de solo lectura; ASSIGN define un método de escritura (setter). Se usan junto con DATA para controlar cómo se leen y escriben externamente las variables miembro de una clase, permitiendo validación y propiedades calculadas.

ADO (ActiveX Data Objects)

El framework de acceso a datos de Microsoft basado en COM. La clase TRecordSet de FWH encapsula ADO para ofrecer acceso a bases de datos cliente-servidor (SQL Server, Access, etc.) con navegación tipo cursor y ejecución de SQL.

cláusula ALIGN

Una cláusula de FiveWin en las definiciones de controles que especifica la alineación del texto o contenido dentro del área del control. Los valores incluyen ALIGN LEFT, ALIGN CENTER y ALIGN RIGHT, usados habitualmente con controles SAY y BUTTON.

ANSI (Windows-1252)

La página de códigos predeterminada de Windows (Latin-1, CP-1252). FWH usa CP_ACP (que corresponde a ANSI) para la conversión del texto de las plantillas de diálogo en dlg2chr.c y ctrl2chr.c. Consulte también las entradas OEM y Unicode de este glosario.

recursos BITMAP / IMAGE

Un tipo de recurso incrustado en los ejecutables compilados mediante archivos .res / .rc. Los controles de FWH los referencian por nombre o por ID entero, p. ej., RESOURCE "MYBITMAP". Los formatos admitidos incluyen BMP, ICO, PNG y JPEG según el contexto de renderizado.

BOM (Byte Order Mark)

El carácter Unicode U+FEFF, colocado al inicio de los archivos de texto UTF-16 o UTF-8 para indicar la codificación. En el contexto de FWH, el BOM es relevante al leer o escribir archivos de texto Unicode, especialmente en las operaciones de E/S de archivos de Harbour y en la generación de contenido HTML.

Buffer (aOrg / aData)

El mecanismo de edición de registros de FWH en TDataRow y TDataBase. Dos arrays paralelos rastrean los cambios: aOrg almacena los valores originales cargados desde disco y aData contiene las modificaciones pendientes del usuario. Los cambios se confirman en la base de datos únicamente cuando el registro se guarda de forma explícita.

BWCC (Borland Windows Custom Controls)

Una biblioteca de interfaz de usuario heredada de Borland que ofrece marcos cincelados, fondos en gris difuminado y controles personalizados (BorBtn, BorCheck, BorRadio, BorStatic, BorShade). FWH incluye una reimplementación de sala limpia de 64 bits en dll/bwcc64.dll para aplicaciones de 64 bits.

CLASSDATA

Una palabra clave de Harbour que declara miembros de datos a nivel de clase (estáticos) compartidos entre todas las instancias de una clase. A diferencia de DATA (que crea copias por instancia), CLASSDATA almacena un único valor para toda la jerarquía de la clase.

Bloque de Código

Un fragmento de código Harbour anónimo y compilable, delimitado por { |params| ... }. Los bloques de código son la base del sistema de eventos y retrollamadas (callbacks) de FWH. Propiedades como bAction, bChange, bWhen y bValid son todas referencias a bloques de código.

COM (Component Object Model)

La tecnología de objetos y comunicación entre procesos de Microsoft. FWH usa COM a través de TActiveX para incrustar controles ActiveX y de TComObject para la automatización OLE/COM, como la interacción con Excel o ADO.

Objeto de Conexión

En la integración MariaDB/MySQL de FWH, una instancia de FWMariaConnection (creada por maria_Connect()) que gestiona la conexión TCP, la autenticación y la sesión de consultas con un servidor MariaDB o MySQL.

Cue Text / Cue Banner

Texto de marcador de posición que se muestra dentro de un control TGet cuando está vacío y no tiene el foco. Se establece mediante TGet:cCueText. Se implementa usando el mensaje de Windows EM_SETCUEBANNER (0x1501).

DATA (variable de instancia de clase)

Una palabra clave de Harbour que declara variables por instancia en la definición de una clase. Cada objeto mantiene su propia copia. Ejemplo: DATA nValue en la definición de una clase crea un miembro nValue para cada instancia.

Modo de Diseño

Un estado en tiempo de ejecución (TWindow:lDesign := .T.) en el que los controles se pueden mover y redimensionar de forma interactiva. Lo usa el IDE Visual (visualfw.exe) para el diseño de formularios mediante arrastrar y soltar durante el desarrollo.

DSN (Data Source Name)

Una entrada de configuración ODBC de Windows que especifica qué controlador de base de datos, dirección de servidor y autenticación usar para una conexión. La clase TODBC de FWH puede conectarse usando un DSN predefinido o una cadena de conexión sin DSN.

Manejador de Errores (ON ERROR)

El mecanismo de recuperación de errores de Harbour, activado por ON ERROR o a través de la función ErrorBlock(). El manejador de errores predeterminado de FWH (source/function/errsysw.prg) ofrece un diálogo visual con traza de pila e inspección de variables para la depuración.

FiveWin.ch

El archivo de cabecera principal para las aplicaciones FWH. Define todas las traducciones del preprocesador #xcommand y #xtranslate que habilitan la sintaxis de lenguaje natural (DEFINE WINDOW, @ ... SAY, @ ... GET, etc.). Toda aplicación FWH incluye este archivo.

convención del prefijo FW_

FWH antepone el prefijo FW_ a sus funciones y constantes globales (p. ej., FW_ReadImage(), FW_JsonDecode()) para evitar colisiones de nombres con el código del usuario y las funciones del runtime de Harbour/xHarbour.

abreviatura FWH

"FiveWin for Harbour" (también "FiveWin for xHarbour"). Un framework de interfaz gráfica que encapsula la API de Windows en un entorno de programación orientada a objetos Clipper/xBase, proporcionando clases para ventanas, diálogos, controles, impresión, acceso a bases de datos e integración con IA.

GDI / GDI+ (Graphics Device Interface)

Subsistemas gráficos de Windows. GDI gestiona el dibujo 2D básico (líneas, formas, texto). GDI+ (al que se accede a través de gdipfwh.cpp) añade mezcla alfa (alpha blending), suavizado de bordes (anti-aliasing), soporte JPEG/PNG y rellenos con degradado. FWH usa GDI+ para el renderizado moderno en TBtnBmp, TImage y la vista previa de impresión.

Harbour vs xHarbour

Dos compiladores Clipper/xBase de código abierto. Harbour es la implementación moderna, mantenida activamente y usada por la mayoría de los usuarios de FWH. xHarbour es una bifurcación más antigua que se mantiene por compatibilidad heredada; requiere una cabecera de compatibilidad (fwhxhb.h) para las compilaciones de 64 bits.

hbcompat.ch

Una cabecera de compatibilidad de Harbour que mapea funciones y comandos específicos de xHarbour a sus equivalentes en Harbour. Deliberadamente no se incluye de forma automática en fivewin.ch, porque su traducción de IN a $ rompería el código que usa patrones como BOEK->IN.

Estilo Infield

Un modo de visualización de TGet (lInfield := .T.) en el que el título o etiqueta del campo se dibuja dentro del área del control de edición, superpuesto o junto al texto del valor. Se usa para diseños de interfaz compactos y sin etiquetas independientes.

Estilo Marquee (XBrowse)

Una propiedad de TXBrowse (nMarqueeStyle) que controla cómo se resalta visualmente la selección de la fila actual. Valores habituales: MARQSTYLE_HIGHLROW (fila única sólida), MARQSTYLE_HIGHLROWMS (selección de varias filas).

MDI (Multiple Document Interface)

Un paradigma de ventanas en el que las ventanas de documentos hijos quedan confinadas dentro de un único marco MDI padre. FWH soporta MDI mediante las clases TMDIFrame y TChild, con disposición automática de ventanas y fusión de menús.

METHOD

Una palabra clave de Harbour que define una función perteneciente a una clase. Los métodos reciben el parámetro implícito Self, que referencia la instancia del objeto. Los métodos de FWH se declaran como METHOD Name() dentro de la definición de la clase y se implementan después.

ODBC (Open Database Connectivity)

Una API en C estandarizada para el acceso a bases de datos. FWH proporciona TODBC para conexiones basadas en ODBC, usando ya sea un DSN con nombre o una cadena de conexión sin DSN.

OEM (Página de Códigos 437/850)

La codificación de caracteres utilizada por la consola MS-DOS y la fuente OEM de Windows. En el código de soporte Unicode de FWH (fwunicode.c), las páginas de códigos OEM (valores inferiores a 1250) se omiten cuando bAnsiOnly es TRUE, evitando que el texto CP437/CP850 se convierta incorrectamente.

OLEDB

El sucesor de ODBC de Microsoft, basado en COM, para el acceso universal a datos. El TRecordSet de FWH puede usar proveedores OLEDB para la conectividad a bases de datos, ofreciendo una alternativa a las conexiones ODBC basadas en DSN.

OOP vs xBase tradicional

FiveWin lleva la programación orientada a objetos completa (clases, herencia, encapsulación, polimorfismo) al mundo Clipper/xBase. El xBase tradicional usa funciones procedimentales y áreas de trabajo (USE, SELECT), mientras que el código FWH define e instancia objetos con métodos y datos.

cláusula PIXEL

Una cláusula en las definiciones de controles (@ nRow, nCol ... PIXEL) que interpreta las coordenadas en píxeles en lugar de la cuadrícula basada en caracteres predeterminada. Es esencial para un posicionamiento preciso, especialmente con DEFINE WINDOW (a diferencia de DEFINE DIALOG) en diseños puramente en PRG.

#pragma /b+ (depurador)

Una directiva del compilador de Harbour que habilita el depurador integrado. Colocar #pragma /b+ al inicio de un archivo fuente activa el motor HB_DBG, permitiendo puntos de interrupción, inspección de variables y depuración paso a paso.

#pragma BEGINDUMP

Una directiva de Harbour que hace que el compilador pase de la sintaxis Harbour a la sintaxis C dentro del mismo archivo fuente. Se usa en archivos .prg para incrustar código C en línea que es compilado por el compilador de C, permitiendo llamadas de bajo nivel a la API de Windows sin un archivo .c aparte.

RDD (Replaceable Database Driver)

Una capa de abstracción en Harbour/xHarbour que permite que el mismo código funcione con distintos formatos de archivo de base de datos. RDD habituales: DBFNTX (compatible con Clipper), DBFCDX (índices de FoxPro), DBFDBT (campos memo). Todas las clases de base de datos de FWH se asientan sobre la capa RDD.

REDEFINE

Una sintaxis de comando de FiveWin para vincular una instancia de clase a un control existente en un recurso de diálogo (archivo .rc). Ejemplo: REDEFINE GET oVar ID 101 OF oDlg conecta un objeto TGet con un control de diálogo a través de su ID de recurso.

RowSet

Una representación en memoria del resultado de una consulta SQL, específicamente en la integración MariaDB/MySQL de FWH. Creado por mysql_RowSet(), ofrece navegación tipo cursor, obtención perezosa (lazy fetching) mediante una estructura de lista enlazada y soporta bOnMove para eventos de cambio de fila.

SDI (Single Document Interface)

El paradigma de ventanas moderno en el que cada documento o vista tiene su propia ventana de nivel superior independiente, a diferencia de MDI, donde los hijos quedan confinados dentro de un marco padre. La mayoría de las aplicaciones FWH contemporáneas usan SDI.

SeekBar (búsqueda incremental)

Un elemento de interfaz integrado en TXBrowse (TXBrowse:oSeek) que muestra un campo de edición flotante. Los usuarios escriben criterios de filtrado de forma incremental, y el browse se desplaza automáticamente a las filas coincidentes a medida que escriben. Se habilita mediante el bloque de código bSeek.

Nomenclatura de clases con prefijo T

La convención de FWH de anteponer el prefijo T a todos los nombres de clase (p. ej., TWindow, TButton, TXBrowse, TGet). Esto distingue los tipos de clase de los nombres de función tradicionales de xBase y proporciona un patrón de nomenclatura coherente y reconocible.

Controles con Tema (Themed)

El soporte de FWH para los estilos visuales de Windows, controlado por miembros DATA como TBtnBmp:lThemed, TBtnBmp:l2007, TBtnBmp:l2010, TBtnBmp:l2013 y TBtnBmp:l2015. Los controles con tema adaptan automáticamente su aspecto al tema actual de Windows del usuario.

cláusula TRANSPARENT

Una cláusula que establece el estilo extendido WS_EX_TRANSPARENT en un control, haciéndolo transparente a los clics del ratón y permitiendo que los controles de la ventana padre se vean a través del fondo. Se usa en diseños de interfaz por capas.

Unicode (UTF-8 / UTF-16)

Estándares universales de codificación de caracteres. Windows usa UTF-16 internamente; FWH convierte entre las cadenas de Harbour (normalmente ANSI u OEM) y UTF-16 para las llamadas a la API de Windows. UTF-8 se usa para la comunicación JSON, las cargas útiles (payloads) de las API REST (clases de IA) y la documentación HTML.

WYSIWYG

"What You See Is What You Get" (lo que ves es lo que obtienes). Los sistemas de informes y vista previa de impresión de FWH (TReport, TPreview) ofrecen una visualización WYSIWYG, mostrando en pantalla exactamente cómo aparecerá la salida en papel, incluyendo fuentes, márgenes y la ubicación de los gráficos.

#xcommand / #xtranslate

Directivas del preprocesador de Harbour que definen traducciones de texto basadas en patrones. El FiveWin.ch de FWH las usa intensamente para crear el lenguaje específico de dominio (DSL) de lenguaje natural que permite definir ventanas, diálogos, controles y menús con una sintaxis intuitiva.
