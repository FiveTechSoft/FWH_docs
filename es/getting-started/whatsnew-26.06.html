Novedades en FWH 26.06

Esta página resume los cambios y adiciones en FiveWin para Harbour/xHarbour versión 26.06 (Junio 2026), en relación con la versión anterior 26.05 (Mayo 2026).

Nuevo ejemplo: XBrowse con Tree y búsqueda

Nuevo ejemplo samples\xbrowses\xbrwtre.prg que demuestra XBrowse con modo Tree y búsqueda incremental. Características:

  • Cambia entre XBrowse normal y vista Tree (agrupado por un campo seleccionado).
  • Combo para seleccionar el campo de búsqueda/agrupación (First, Last, Street, City, State).
  • La búsqueda funciona en modo normal y tree mediante XbrTreeSeek().
  • Nodos del tree expandibles/colapsables con agrupación visual.

Nuevo ejemplo: Diálogo con recursos y zoom proporcional

Nuevo ejemplo samples\dialog\resdlg.prg que demuestra diálogos basados en recursos con zoom proporcional. Cuando se redimensiona el diálogo, todos los controles (etiquetas, campos de edición, botones) se redimensionan proporcionalmente, incluyendo posiciones, anchos, alturas y tamaños de fuente.

  • Escalado DPI — el tamaño inicial del diálogo se adapta al DPI del sistema usando GetDeviceCaps(LOGPIXELSX).
  • Zoom uniforme — los factores de escala nSX = nW / 300 y nSY = nH / 180 se aplican a todas las propiedades de los controles.
  • Escalado de fuente — el tamañoo de fuente se recrea con el tamañoo escalado via SetFont() en cada redimensionamiento.
  • Recurso RC — la plantilla del diálogo se define en resdlg.rc con directivas #define para los IDs de los controles.

Clase Agent — Mejoras Importantes

La clase Agent (source\classes\agent.prg) recibió mejoras sustanciales desde su introducción en 26.05:

  • Streaming SSE — Step() ahora envía "stream": true con stream_options.include_usage para métricas de tokens en tiempo real. La respuesta se analiza desde fragmentos SSE mediante AG_SseParse().
  • Tool_Shell() — completamente implementado: ejecuta vía cmd.exe (Windows) o /bin/sh (Unix), captura stdout+stderr, trunca a 30 KB, informa el código de salida. Anteriormente un stub.
  • Tool_Python() — completamente implementado: busca el intérprete python3/python/py, escribe archivo .py temporal, ejecuta, captura salida. Anteriormente delegaba al stub Tool_Shell().
  • Tool_WebSearch() — implementado: curl a DuckDuckGo HTML, extrae fragmentos de resultados vía AG_ExtractDdgResults(). Anteriormente un stub.
  • Tool_WebFetch() — implementado: curl a URL, elimina etiquetas HTML vía AG_StripHtml(), trunca a 40 KB. Anteriormente un stub.
  • ExecTool() manejo de errores — BEGIN SEQUENCE / RECOVER envuelve cada llamada a herramienta para que un fallo no bloquee el bucle del agente.
  • Run() interrupt/inject — codeblock bInterrupt verificado antes de cada paso y cada tool call; codeblock bInject inyecta mensajes de usuario en medio de la ejecución. Permite cancelación externa e interjecciones.
  • BuildToolsArray() — ahora incluye descripción y esquema de parámetros para cada herramienta integrada (antes solo tenía nombre).
  • ToggleSkill() — bug corregido: el filtro ASort no eliminaba elementos; ahora usa hb_ADel() con .T. para eliminación in-place.
  • ExecUserTool() — corregido: la construcción de sys.argv ahora tokeniza correctamente argumentos separados por espacios en una lista Python.
  • SendToLLM() — sincronizado con Step(): streaming + parseo SSE.

Nuevas funciones helper: AG_SseParse(), AG_UrlEncode(), AG_ExtractDdgResults(), AG_StripHtml(), AG_ToolDesc(), AG_ToolParams().

AgenticAI — Aplicación GUI de Escritorio

Una completa aplicación de escritorio para el motor agente ccharbour, portada desde la versión Agents Web a una app FiveWin nativa usando un WebView2 Edge incrustado (TWebView2):

  • Razonamiento en vivo ("thinking mode") — eventos reasoning_delta fluyen en una caja de vidrio púrpura mientras el modelo piensa (ej. /model deepseek-reasoner).
  • Chip de estado — cabecera muestra tiempo transcurrido, flujo de tokens de sesión (subida/bajada) y tok/s, actualizado 5 veces por segundo.
  • Markdown en vivo — las burbujas del asistente renderizan markdown MIENTRAS se transmite (re-parseo throttled vía marked.js), no solo al final del turno.
  • /goal /plan /run — sistema de plan de acción. /plan pide al modelo 3-6 pasos JSON y los muestra como tarjeta "Plan de Acción" editable (ciclar estado de cada paso, editar títulos, eliminar/añadir pasos); /run ejecuta el plan un paso por turno del agente.
  • /btw — interjección "¿qué estás haciendo?" mientras el agente trabaja; entregada entre acciones sin interrumpir la ejecución. Usa el nuevo hook CC_AgentRun hOpts["inject"].
  • /cost — tarjeta de métricas de sesión con precios DeepSeek conscientes de caché (prompt_cache_hit_tokens con 98% descuento).
  • /compact + monitor de ventana de contexto — pasado el 85% de la ventana de 128k aparece tarjeta "Ventana de Contexto Crítica" ofreciendo Comprimir / Limpiar; /compact pliega la mitad del historial en un mensaje de resumen.
  • /init + AGENTS.md — el agente escribe el archivo de reglas del proyecto; AGENTS.md (alternativa CLAUDE.md) se inyecta en el system prompt cada turno.
  • Nuevas tarjetas — ejecución-abortada (Stop), límite de pasos alcanzado con botón "Continuar", /help como cuadrícula de botones.
  • Permitir/rechazar — tarjeta por acción para herramientas mutantes (shell/write/edit) cuando "Auto-approve" está desactivado; el turno del agente se bloquea hasta que decidas.
  • ask_user — tarjeta de opción múltiple conectada al webview.
  • Visor Diff — barra "Código generado" con toggle "Ver Cambios (Diff)" mostrando líneas rojas/verdes.
  • UX — historial de prompts Arriba/Abajo, Esc para detener, Ctrl+K para limpiar, prompt permanece habilitado mientras se ejecuta para poder usar /btw. Comando /key integrado para establecer la clave LLM en tiempo de ejecución.

El transporte es libcurl en proceso (hbcurl), la misma ruta que TOpenAI:SendStream, conectado a ccharbour mediante hOpts["transport"]. Ejemplo: samples\AgenticAI\ (build multi-módulo con agenticai.hbp + build.bat).

Motor ccharbour y Consola

  • CC_AgentRun — acepta un codeblock opcional hOpts["inject"], consultado al inicio de cada iteración; cuando retorna una cadena no vacía se añade como mensaje de usuario antes de la siguiente solicitud al modelo (interjección en medio de la ejecución que no interrumpe el bucle).
  • Tarjetas de consola (cc.exe) — las respuestas ahora se renderizan como "tarjetas" estilo GUI: filas con fondo tintado como las burbujas de AgenticAI. Respuestas en slate, razonamiento en caja púrpura, errores en rojo oscuro, /cost en tarjeta esmeralda con precios DeepSeek conscientes de caché. La salida plana no cambia cuando el color está desactivado.

Clase Transformer — Multi-Head, GELU, LR Scheduler y Padding

  • LRScheduler — nueva clase que implementa warmup + decrecimiento inverso de raíz cuadrada del paper Transformer: lr = d_model^(-0.5) * min(step^(-0.5), step*warmup^(-1.5)). Métodos: New(d_model, warmup_steps, base_lr), GetLR(step), Update(optimizer, step).
  • MultiHeadAttention — valida d_model % n_heads == 0 en la construcción con ALERT() si no es divisible. Usa división entera exacta para head_dim en lugar de Int() para evitar truncamiento.
  • FeedForward — activación GELU reemplaza ReLU (aproximación tanh: 0.5*x*(1+tanh(√(2/π)*(x+0.044715*x³)))). La derivada de GELU usa fórmula CDF+PDF para flujo de gradientes correcto. ff_dim ahora configurable (default 4*d_model). Valida d_model > 0 y ff_dim > 0.
  • EmbeddingLookup — el token PAD (índice 0) ahora devuelve un vector de ceros en lugar de fallar con "Bound error: array access" en aVocab[0].
  • Backward — omite la acumulación de gradientes para tokens PAD (índice 0 en src_indices y pos_indices). Corrige el entrenamiento con secuencias de longitud variable rellenadas a max_seq_len.
  • transxbrowse.prg ahora usa nHeads=2 y LRScheduler para demostrar attention multi-head con programación de warmup.
  • transxbrowse.prg ahora usa nHeads=2 para demostrar attention multi-head.

    • Remote View — Multi-Cliente y Login

    • Multi-cliente — cada espectador obtiene su propio servidor en su propio puerto, completamente aislado, para que varios navegadores puedan ver/controlar la misma ventana simultáneamente. Estado por hilo mediante TLS (sockets, frame diff, viewport, cursor) — sin globales compartidas.
      • Cliente único, SIN multihilo (sin -mt): RemoteViewStart()/Stop() impulsado por un WM_TIMER oculto en el hilo GUI.
      • Multi cliente, multihilo (-mt): lanza un hilo Harbour por puerto con hb_threadStart, cada uno llamando al bloqueante RemoteViewServe(); detenerlos todos con RemoteViewStopAll().

    • Título de página personalizado — RemoteViewStart([hWnd], [nPort], [cTitle]) ahora acepta un parámetro de título opcional. Por defecto "FWH Remote View".
    • Ejemplo de login — samples\RemoteView\testrvauth.prg muestra cómo autenticar a un usuario remoto antes de que se abra la UI de la app. El login es un diálogo FiveWin normal owned por la ventana servida, compuesto por RemoteView encima. Detalle clave: NO lanzar UI modal dentro de ON INIT (la ventana aún no se ha pintado). El ejemplo difiere el login con un TTimer.
    • Corrección zero-init — el CRT de VC98/xHarbour no pone a cero variables __declspec(thread); el estado de captura por hilo ahora se reinicia explícitamente en CaptureInit y el rect del monitor recurre a la pantalla principal en caso de fallo.

    Sistema de Build

    Limpieza de Warnings del Compilador

    Todos los warnings emitidos por los builds de librería GCC32, GCC64, MSVC32 y MSVC64 (~170 sitios) han sido eliminados preservando el comportamiento en todos los toolchains soportados (BCC32/64, MSVC32/64, GCC32/64, Harbour y xHarbour). Cubre:

    • -Wcast-function-type — casts GetProcAddress/FARPROC ahora usan el intermedio portátil ( void (*)( void ) ).
    • -Wdangling-else, -Wimplicit-fallthrough, -Wsign-compare, -Wunused-function (callbacks vtable COM IDataObject solo 32-bit protegidos con #ifndef _WIN64), -Wold-style-declaration, -Wmisleading-indentation.
    • Macros redefinidos y MSVC C4996.

    Dos bugs reales encontrados: un buffer overflow en BlankQuotes() (vstrfun1.prg) cuando su segundo argumento excede 3 caracteres, y una sobre-lectura de 3 bytes del bloque de control gráfico GIF en fwgif.c. Las nueve variantes de librería ahora compilan sin warnings.

    xHarbour Commercial Restaurado

    El target xHB Commercial (xhbc) — abandonado desde 2016 — ahora compila, enlaza y ejecuta de nuevo con el toolchain VC98:

    • La librería C (Fivehcm.lib) pasó de stub vacío al motor C completo de FiveWin; la librería PRG (Fivehmx.lib) fue reconstruida completamente.
    • source/internal/xhbcompat.c + include/xhbcompat.h: API C de arrays "vector" de Harbour-3.x implementada sobre lo que xHarbour proporciona.
    • Correcciones de compilación VC98/xHarbour por archivo (themes, msgs, files, elevation, winsock, calendar, scintilc, richedit, brushes, ribbon, odbc32x, ...), cada una detrás de un guard __XHARBOUR__.
    • Todos los shims protegidos por __XHARBOUR__ — los builds Harbour compilan byte-por-byte igual que antes.

    Scripts de build: makes/build_fivehcm.ps1 + makes/build_fivehmx.ps1.

    Proyectos de Prueba makes/

    Cada carpeta makes/<compilador>/ ahora compila, enlaza y ejecuta una app FiveWin mínima para su combinación Harbour/xHarbour + compilador C (11 variantes confirmadas). Se añadieron dos variantes faltantes (xhb_bcc64, xhb_msvc32). Cada go.bat respeta FW_NORUN=1 y usa el toolchain VS 18.

    Correcciones Destacadas

    TGet — Caracteres ANSI (Turco, CP1250-1258)

    La entrada de teclado de caracteres ANSI con punto de código Unicode superior a 255 (Turco ş-cedilla, ğ-breve, İ con punto; Polaco, Checo, Báltico, Cirílico y Griego) mostraba "?" en aplicaciones no Unicode (FW_SetUnicode(.F.)) usando codepages de un solo byte CP1250–CP1258.

    Regresión introducida cuando is2byteansi() comenzó a tratar todas las secuencias de 2 bytes como pares ANSI en esos codepages: WideKey2Asc() construía UTF-8 genuino desde el código ancho WM_CHAR pero la heurística isutf8() de fw_Utf8ToStr() se negaba a convertirlo, rechazando la tecla.

    WideKey2Asc() ahora convierte con codepages explícitos mediante FW_CdpTranslate(cUtf8, 65001, -1), evitando la heurística. El comportamiento de visualización de is2byteansi() no cambia.

    Nuevos ejemplos: samples\test\trwincdp.prg (verificación de cadena de conversión) y samples\test\trwinget.prg (envía códigos WM_CHAR ş ğ İ a un GET y verifica que el buffer recibe bytes CP1254 FE F0 DD).

    TGraph ADD SERIE / SET Y LABELS

    Ambas reglas #xcommand expandían a un oGraph: hard-codeado en lugar del matchmarker <oGraph>, por lo que ADD SERIE TO oMyGraph / SET Y LABELS OF oMyGraph llamaban a una variable oGraph inexistente a menos que el objeto se llamara casualmente oGraph. Ahora expanden a <oGraph>:AddSerie() / <oGraph>:SetYVals().

    Nuevas Funcionalidades

    TRichEdit5 y TRichEdit — SetTextColor()

    SetTextColor(nColor) aplica color de texto a la selección actual (SCF_WORD | SCF_SELECTION) usando solo la máscara CFM_COLOR, preservando todo el demás formato (negrita, cursiva, subrayado, fuente, tamaño). Si no hay texto seleccionado, el color se aplica a la palabra bajo el cursor. Funciona tanto en TRichEdit5 (RichEdit 5.0) como en TRichEdit (RichEdit 2.0 via riched20.dll).

    Ejemplos: samples\test\testchclr.prg (Azul/Rojo/Negro + Negrita/Cursiva), samples\test\testreclr.prg (lo mismo para RichEdit 2.0).

    TRichEdit5 — Modo Oscuro

    Nuevo METHOD SetDarkMode(nClrText, nClrBack), aplicado en cascada automáticamente por TDialog:SetDarkMode / FW_SetDarkMode como los demás controles. Usa la misma paleta oscura que TMultiGet/TGet.

    TURLLink — Alineación de Texto

    Nuevo DATA nAlign y METHOD AlignText(nAlign). Method Default() ahora auto-detecta la alineación desde los estilos de ventana (SS_RIGHT, SS_CENTER) cuando ::nAlign es nil. Method EraseBkGnd() ahora acepta el parámetro hDC. Gracias a Carlos Sincuir.

    fwhxhb.h — Compatibilidad C Harbour/xHarbour

    include/fwhxhb.h mapea la API C exclusiva de Harbour (hb_parvc/parvni/parvnl/parvnll/parvnd/parvl, hb_storvc/storvni/storvnl/storvnll/storvnd/storvl, hb_vmCDP, hb_retclen_buffer, hb_rettdt, hb_timeStampStrGetDT) a primitivas comunes a ambas VMs. Un solo conjunto de archivos objeto C enlaza contra Harbour o xHarbour.

    Nuevos Ejemplos

    transxbrowse — Clasificador de Texto Transformer en XBrowse

    samples\ai\transxbrowse.prg entrena una red neuronal Transformer para clasificar frases en español en 6 categorías (Saludo, Despedida, Agradecimiento, Pregunta, Comando, Respuesta) usando un vocabulario de 25 tokens. Muestra todas las predicciones en una cuadrícula XBrowse con porcentaje de confianza y estado OK/FAIL. El título de la ventana muestra la precisión. Usa LRScheduler para programación de warmup.

    transsave — Guardar/Cargar Modelo Transformer

    samples\ai\transsave.prg demuestra el ciclo de vida completo del modelo: entrena un clasificador Transformer, lo guarda a disco con Save() (hb_Serialize), lo carga de vuelta con Load(), y verifica que las predicciones coincidan. Resultados en XBrowse.

    transgen — Generación de Texto Transformer

    samples\ai\transgen.prg entrena un Transformer en secuencias de caracteres y genera nuevo texto autoregresivamente desde tokens semilla. Usa Generate() con muestreo por temperatura. Resultados en XBrowse con puntajes de confianza.

    githubdb — githubDB + XBrowse

    samples\githubdb\githubdb.prg navega un fork githubDB (SQL+base de datos vectorial en GitHub Actions) desde FiveWin usando dos rutas HTTP:

    • Lectura rápida (CDN) — obtiene data/<db>.json desde raw.githubusercontent.com, sub-segundo, sin token.
    • Action query — envía SQL mediante repository_dispatch, sondea resultados, 10-30 s, necesita token GitHub con Contents R/W.

    Transporte HTTP mediante objeto COM WinHttp (sin dependencia curl/DLL). Compilado con build_new.bat (todas las variantes). Documentación en githubdb.

    testrsz — Redimensión de XBrowse sin Parpadeo

    samples\testrsz.prg demuestra cómo redimensionar un XBrowse en tiempo de ejecución sin parpadeo. El método correcto: añadir WS_CLIPCHILDREN al estilo del diálogo, congelar el diálogo con WM_SETREDRAW durante el redimensionamiento, luego repintar ambos. Incluye botones del "método antiguo" lado a lado para comparar. También documentado en la documentación HTML de TXBrowse.

    seqedit y xbrseqed — Edición Secuencial en XBrowse

    samples\seqedit.prg y samples\ui\xbrowse\xbrseqed.prg demuestran edición secuencial guiada por teclado para fuentes de datos Array en XBrowse. Presiona ENTER en una fila para comenzar a editar la primera columna de la secuencia; cada ENTER posterior valida la columna actual y auto-avanza; ESC cancela. Totalmente configurable mediante array estático aEditSeq (por defecto {3,5,7}). Usa avance de columna basado en PostMessage (sin timers).

    Correcciones de Errores

    • TFolder crash "No exported method: MOVE" — AdjustRect() llamaba oDlg:Move() sobre elementos de ::aDialogs sin verificar si eran NIL. Se agregó verificación de NIL para ::aDialogs[1] y cada oDlg en el callback de AEval, consistente con el patrón usado en el resto de la clase.

    • Tareas VS Code — vscode/tasks.json con cinco tareas: Clean, Format (hbformat), Resources (editor RC PellesC), Build64, y Run. Todas con problem matcher Harbour y etiquetas en barra de estado. Gracias a Jose Vte. Cheto.

    Resumen

    FWH 26.06 ofrece madurez importante de la clase Agent (streaming SSE, herramientas reales, manejo de errores, interrupt/inject), dos nuevas clases de integración de sistema (TGit, TSSH), el port GUI de escritorio AgenticAI, soporte multi-cliente de Remote View, una limpieza completa de warnings del compilador (~170 sitios, dos bugs reales encontrados y corregidos), restauración del target xHarbour Commercial, y expansión significativa de la documentación a más de 36 páginas HTML.
