EasyReport

Fuente: source/classes/esreport.prg (motor FW_EReport), source/classes/tereport.prg (diseñador visual TEReport), include/easyrep.ch (comandos)

EasyReport es un diseñador visual WYSIWYG de informes totalmente integrado en FiveWin para Harbour (FWH). Creado originalmente por Timm Sodtalbers bajo el nombre VRD (Visual Report Designer) entre 2000 y 2004, fue adoptado y mejorado por FiveTech Software. EasyReport permite a los usuarios finales diseñar, editar e imprimir informes visualmente sin escribir una sola línea de código, mientras que los desarrolladores mantienen control programático completo sobre la vinculación de datos y la salida.

Los informes se almacenan como archivos .vrd de estilo INI con archivos de área complementarios (.v01, .v02, etc.). El motor lee estas definiciones en tiempo de ejecución y genera la salida a través de la clase TPrinter de FWH, soportando vista previa de impresión, impresión directa y salida PDF.

Arquitectura

graph LR A[".vrd Report File"] --> B["FW_EReport Engine"] B --> C["TPrinter"] C --> D["Print Preview"] C --> E["Physical Printer"] C --> F["PDF Output"] G["TEReport Designer"] --> A

El flujo de trabajo es sencillo: el diseñador visual (TEReport) crea y edita archivos de definición de informes .vrd. Al momento de imprimir, el motor FW_EReport lee el archivo .vrd, procesa las áreas y elementos del informe, y renderiza todo a través de TPrinter. La salida puede ir a vista previa, una impresora física o un archivo PDF.

Comandos

Todos los comandos están definidos en include/easyrep.ch. Inclúyalo con #include "EasyRep.ch".

EASYREPORT

EASYREPORT oVRD NAME cReportFile ;
   [ PREVIEW lPreview ] ;
   [ TO cPrinter ] ;
   [ OF oWnd ] ;
   [ MODAL ] ;
   [ PRINTIDS ] ;
   [ NOPRINT ] ;
   [ NOEXPR ] ;
   [ CHECK lCheck ] ;
   [ AREAPATH cAreaPath ] ;
   [ PRINTDIALOG lPrintDialog ] ;
   [ COPIES nCopies ] ;
   [ PRINTOBJECT oPrn ] ;
   [ PAPERSIZE aSize ] ;
   [ FILE cFile ]

Abre un archivo de informe y crea un objeto FW_EReport. Este es el comando inicial para cualquier trabajo de impresión con EasyReport.

CláusulaDescripción

OF oWndVentana padre
MODALVentana de vista previa modal

NOEXPRNo evaluar expresiones en los elementos del informe
PRINTDIALOG lPrintDialogMostrar el diálogo de impresión de Windows

PRINTAREA

PRINTAREA nArea OF oVRD ;
   [ ONLYINIT ] ;
   [ ITEMIDS aIDs ] ;
   [ ITEMVALUES aStrings ] ;
   [ PAGEBREAK ]

Imprime un área del informe. Use ITEMIDS e ITEMVALUES para suministrar datos a elementos específicos dentro del área. Llámelo dentro de un bucle DO WHILE para áreas de detalle.

PRINTITEM

PRINTITEM nItemID AREA nArea ;
   [ VALUE cTextOrImage ] ;
   OF oVRD ;
   [ ENTRY nEntry ]

Imprime un elemento individual dentro de un área. Útil cuando necesita control detallado sobre elementos individuales.

PRITEMLIST

PRITEMLIST AREA nArea OF oVRD ;
   ITEMIDS aIDs ITEMVALUES aStrings

Imprime una lista de elementos dentro de un área, haciendo coincidir IDs con valores.

Otros Comandos

PRINTREST AREA nArea OF oVRD      // Print remaining items of an area

PAGEBREAK oVRD                    // Force a page break

END EASYREPORT oVRD               // End the report and finalize output

ER QUICK (Impresión Rápida)

ER QUICK oVRD NAME cReportFile ;
   [ PREVIEW lPreview ] ;
   [ TO cPrinter ] ;
   [ OF oWnd ] ;
   [ MODAL ] ;
   [ PRINTDIALOG lPrintDialog ] ;
   [ COPIES nCopies ] ;
   [ ACTION uAction ]

Un comando de atajo que llama a FWER_PrReport() para abrir, llenar y cerrar un informe en un solo comando. La cláusula ACTION recibe el objeto oVRD como parámetro de bloque de código.

Áreas del Informe

Un informe EasyReport se divide en hasta seis áreas lógicas. Cada área tiene su propio archivo INI (ej., .v01, .v02) y contiene elementos (texto, imágenes, códigos de barras, cuadros, líneas, etc.).

graph TB A["Area 1: Report Header
Printed once at the very top"] --> B B["Area 2: Page Header
Printed at the top of every page"] --> C C["Area 3: Detail
Repeated for each data record"] --> D D["Area 4: Detail Variable
Variable-height detail content (memos)"] --> E E["Area 5: Page Footer
Printed at the bottom of every page"] --> F F["Area 6: Report Footer
Printed once at the very end"]
ÁreaNombreUso Típico
1Encabezado del InformeLogo de la empresa, título del informe, fecha. Se imprime una vez en la primera página.
2Encabezado de PáginaEncabezados de columnas, número de página. Se imprime en la parte superior de cada página.
3DetalleFilas de datos. Se repite para cada registro del conjunto de datos.
4Detalle VariableContenido de altura variable como campos memo, notas, descripciones.
5Pie de PáginaTotales de página, números de página. Se imprime en la parte inferior de cada página.
6Pie del InformeTotales generales, firmas. Se imprime una vez al final.

Cada elemento dentro de un área tiene un ID numérico único (ej., 101, 102, 301). Al imprimir programáticamente, se referencian los elementos por estos IDs usando los arrays ITEMIDS e ITEMVALUES.

Diseñador Visual (TEReport)

El diseñador visual es una aplicación MDI completa que permite a los usuarios crear y editar definiciones de informes. Ejecútelo llamando a EReport() o agregando un botón de menú/barra de herramientas en su aplicación.

La interfaz del diseñador proporciona:

  • Panel de áreas -- muestra todas las áreas del informe con sus límites, arrastre para redimensionar
  • Panel de elementos -- agregue etiquetas de texto, campos, imágenes, códigos de barras, líneas, cuadros a cualquier área
  • Panel de propiedades -- configure fuente, color, alineación, posición, tamaño, expresiones para cada elemento
  • Regla -- regla visual para posicionamiento preciso (mm o pulgadas)
  • Vista previa -- vista previa instantánea del diseño del informe
  • Deshacer/Rehacer -- soporte completo de deshacer y rehacer para todos los cambios
  • Integración con bases de datos -- defina conexiones de base de datos y mapeo de campos dentro del diseñador
  • Configuración general -- tamaño de papel, orientación, márgenes, fuentes, idioma

El diseñador soporta la creación de nuevos informes desde cero, la apertura de archivos .vrd existentes, y el guardado en el formato estándar de EasyReport. También proporciona funcionalidad de respaldo y "Guardar Como".

EasyReport almacena los informes como un conjunto de archivos de texto de estilo INI:

Ejemplo: Informe Simple desde DBF

#include "FiveWin.ch"
#include "EasyRep.ch"

function PrintClients( lPreview, oWnd )

   local oVRD

   USE clients

   // Open the report with preview
   EASYREPORT oVRD NAME ".\reports\clients.vrd" ;
              PREVIEW lPreview OF oWnd

   // Loop through records and print Detail area (area 3)
   DO WHILE ! Eof()
      PRINTAREA 3 OF oVRD ;
         ITEMIDS    { 101, 102, 103 } ;
         ITEMVALUES { clients->name, clients->city, clients->phone }
      SKIP
   ENDDO

   // Finalize the report
   END EASYREPORT oVRD

   USE

return nil

El array ITEMIDS contiene los IDs numéricos asignados a los elementos en el diseñador visual. El array ITEMVALUES proporciona los valores de datos correspondientes. El motor los empareja por posición: el elemento 101 recibe el primer valor, el elemento 102 recibe el segundo, y así sucesivamente.

Ejemplo: Formulario de Pedido con Saltos de Página

Este ejemplo de samples/EasyReport/examples/SourceExample1.prg demuestra un formulario de pedido completo con encabezado, líneas de detalle, contenido memo, saltos de página automáticos y un pie con totales.

// EasyReport: Order form

FUNCTION PrintOrder( lPreview )

   LOCAL i, nTotal, nVAT, oVRD, lLastPosition

   // Open the report
   EASYREPORT oVRD NAME ".\examples\EasyReportExample1.vrd" ;
              PREVIEW lPreview OF oWnd ;
              PRINTDIALOG IIF( lPreview, .F., .T. )

   IF oVRD:lDialogCancel = .T.
      RETURN .F.
   ENDIF

   // Set header data using Cargo array
   oVRD:Cargo := { "Nr. 12345  Date: 5.9.2004", ;   // 1 order number
                   "Testclient",               ;     // 2 address line 1
                   "z.H.: Timm Sodtalbers",    ;     // 3 address line 2
                   "Plaggefelder Str. 42",     ;     // 4 address line 3
                   "26632 Ihlow",              ;     // 5 address line 4
                   "257001",                   ;     // 6 barcode value
                   "Company Name" + CRLF + ;         // 7 company memo
                      "Street 42" + CRLF + "City", ;
                   MemoRead( ".\examples\EasyReportExample.txt" ) }

   // Open database and print order line items
   USE .\EXAMPLES\EXAMPLE
   nTotal := 0

   DO WHILE ! Eof()

      // Print detail area with item data
      PRINTAREA 3 OF oVRD ;
         ITEMIDS    { 104, 105, 106, 107 } ;
         ITEMVALUES { EXAMPLE->UNIT,                             ;
                      AllTrim( Str( EXAMPLE->PRICE, 10, 2 ) ),   ;
                      AllTrim( Str( EXAMPLE->TOTALPRICE, 11, 2 )),;
                      AllTrim( ".\EXAMPLES\" + EXAMPLE->IMAGE ) }

      nTotal += EXAMPLE->TOTALPRICE

      // Check if page break is needed before next record
      IF oVRD:nNextRow > oVRD:nPageBreak
         PAGEBREAK oVRD
      ENDIF

      SKIP

   ENDDO

   CLOSE

   // Print footer with totals
   nVAT := nTotal * 0.16
   AAdd( oVRD:Cargo, AllTrim( Str( nTotal,        12, 2 ) ) )  //  9
   AAdd( oVRD:Cargo, AllTrim( Str( nVAT,          12, 2 ) ) )  // 10
   AAdd( oVRD:Cargo, AllTrim( Str( nTotal + nVAT, 12, 2 ) ) )  // 11

   PRINTAREA 5 OF oVRD

   END EASYREPORT oVRD

RETURN .T.

Lógica de Salto de Página

Al imprimir registros de detalle en un bucle, frecuentemente necesita verificar si la siguiente área caberá en la página actual. Use oVRD:nNextRow y oVRD:nPageBreak junto con oVRD:aAreaHeight para un control preciso: 

DO WHILE ! Eof()

   // Check if detail area (3) will fit, considering the footer area (5)
   IF oVRD:nNextRow + oVRD:aAreaHeight[3] > ;
      oVRD:nPageBreak - oVRD:aAreaHeight[5]
      PAGEBREAK oVRD
   ENDIF

   PRINTAREA 3 OF oVRD ;
      ITEMIDS { 101, 102 } ;
      ITEMVALUES { field->name, field->value }

   SKIP

ENDDO

Consejos y Mejores Prácticas

Flujo de Trabajo de Diseño

  1. Comience abriendo el diseñador con EReport() y creando un nuevo informe.
  2. Defina el tamaño de papel, orientación y márgenes en la Configuración General.
  3. Agregue áreas (encabezado, encabezado de página, detalle, pie) según sea necesario.
  4. Coloque elementos en cada área y asigne IDs numéricos a los elementos que recibirán datos programáticamente.
  5. Guarde el archivo .vrd y anote los IDs de los elementos.
  6. Escriba código usando los comandos EASYREPORT / PRINTAREA / END EASYREPORT, haciendo coincidir los IDs con los datos.
  7. Pruebe con PREVIEW .T. antes de enviar a una impresora física.

Consejos Generales

  • Siempre verifique oVRD:lDialogCancel después de abrir un informe con PRINTDIALOG -- el usuario puede haber cancelado.
  • Use oVRD:Cargo para pasar datos estáticos (direcciones, títulos, fechas) e ITEMIDS/ITEMVALUES para datos dinámicos por registro.
  • Para campos memo, use oVRD:Cargo2 e imprímalos en el Área 4 (Detalle Variable) para auto-dimensionamiento.
  • Implemente verificaciones de salto de página antes de imprimir cada registro de detalle para evitar que los elementos se corten en el límite de la página.
  • Use PRINTIDS durante el desarrollo para ver los IDs de los elementos impresos en el informe, facilitando el mapeo de IDs en su código.
  • El parámetro lCheck permite una ejecución en seco para calcular el total de páginas antes de la impresión real, útil para pies de página "Página X de Y".
  • Los archivos de informe (.vrd y .v0x) son archivos INI de texto plano -- pueden ser versionados y comparados.
  • Distribuya los archivos de informe con su aplicación y permita a los usuarios finales personalizar los diseños usando el diseñador sin recompilar.

Compatibilidad con Versiones Anteriores

Los nombres de clase VRD originales son soportados a través de traducciones del preprocesador en easyrep.ch: 

#xtranslate VRD()                        => FW_EReport()
#xtranslate VRD_PrReport( [<params,...>] ) => FWER_PrReport( <params> )
#xtranslate VRDITEM()                    => FWER_Item()
#xtranslate VRDBARCODE()                 => FWER_BarCode()

El código existente que usa la convención de nombres VRD anterior seguirá funcionando sin cambios.
