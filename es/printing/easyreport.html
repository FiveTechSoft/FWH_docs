EasyReport

Fuente: source/classes/esreport.prg (FW_EReport engine), source/classes/tereport.prg (TEReport visual designer), include/easyrep.ch (commands)

EasyReport is a visual WYSIWYG report designer fully integrated into FiveWin for Harbour (FWH). Originally created by Timm Sodtalbers under the name VRD (Visual Report Designer) between 2000 and 2004, it was adopted and enhanced by FiveTech Software. EasyReport allows end-users to design, edit, and print reports visually without writing a single line of code, while developers retain full programmatic control over data binding and output.

Reports are stored as .vrd INI-style files with companion area files (.v01, .v02, etc.). The engine reads these definitions at runtime and renders output through FWH's TPrinter class, supporting print preview, direct printing, and PDF output.

Architecture

graph LR A[".vrd Report File"] --> B["FW_EReport Engine"] B --> C["TPrinter"] C --> D["Print Preview"] C --> E["Physical Printer"] C --> F["PDF Output"] G["TEReport Designer"] --> A

The workflow is straightforward: the visual designer (TEReport) creates and edits .vrd report definition files. At print time, the FW_EReport engine reads the .vrd file, processes report areas and items, and renders everything through TPrinter. Output can go to preview, a physical printer, or a PDF file.

Commands

All commands are defined in include/easyrep.ch. Include it with #include "EasyRep.ch".

EASYREPORT

EASYREPORT oVRD NAME cReportFile ;
   [ PREVIEW lPreview ] ;
   [ TO cPrinter ] ;
   [ OF oWnd ] ;
   [ MODAL ] ;
   [ PRINTIDS ] ;
   [ NOPRINT ] ;
   [ NOEXPR ] ;
   [ CHECK lCheck ] ;
   [ AREAPATH cAreaPath ] ;
   [ PRINTDIALOG lPrintDialog ] ;
   [ COPIES nCopies ] ;
   [ PRINTOBJECT oPrn ] ;
   [ PAPERSIZE aSize ] ;
   [ FILE cFile ]

Opens a report file and creates an FW_EReport object. This is the starting command for any EasyReport print job.

PRINTAREA

PRINTAREA nArea OF oVRD ;
   [ ONLYINIT ] ;
   [ ITEMIDS aIDs ] ;
   [ ITEMVALUES aStrings ] ;
   [ PAGEBREAK ]

Prints a report area. Use ITEMIDS and ITEMVALUES to supply data for specific items within the area. Call this inside a DO WHILE loop for detail areas.

PRINTITEM

PRINTITEM nItemID AREA nArea ;
   [ VALUE cTextOrImage ] ;
   OF oVRD ;
   [ ENTRY nEntry ]

Prints a single item within an area. Useful when you need fine-grained control over individual items.

PRITEMLIST

PRITEMLIST AREA nArea OF oVRD ;
   ITEMIDS aIDs ITEMVALUES aStrings

Prints a list of items within an area, matching IDs to values.

Other Commands

PRINTREST AREA nArea OF oVRD      // Print remaining items of an area

PAGEBREAK oVRD                    // Force a page break

END EASYREPORT oVRD               // End the report and finalize output

ER QUICK (Quick Print)

ER QUICK oVRD NAME cReportFile ;
   [ PREVIEW lPreview ] ;
   [ TO cPrinter ] ;
   [ OF oWnd ] ;
   [ MODAL ] ;
   [ PRINTDIALOG lPrintDialog ] ;
   [ COPIES nCopies ] ;
   [ ACTION uAction ]

A shortcut command that calls FWER_PrReport() to open, fill, and close a report in a single command. The ACTION clause receives the oVRD object as a code block parameter.

Report Areas

An EasyReport report is divided into up to six logical areas. Each area has its own INI file (e.g., .v01, .v02) and contains items (text, images, barcodes, boxes, lines, etc.).

graph TB A["Area 1: Report Header
Printed once at the very top"] --> B B["Area 2: Page Header
Printed at the top of every page"] --> C C["Area 3: Detail
Repeated for each data record"] --> D D["Area 4: Detail Variable
Variable-height detail content (memos)"] --> E E["Area 5: Page Footer
Printed at the bottom of every page"] --> F F["Area 6: Report Footer
Printed once at the very end"]
AreaNameTypical Use
1Report HeaderCompany logo, report title, date. Printed once on the first page.
2Page HeaderColumn headers, page number. Printed at the top of every page.
3DetailData rows. Repeated for each record in your dataset.
4Detail VariableVariable-height content such as memo fields, notes, descriptions.
5Page FooterPage totals, page numbers. Printed at the bottom of every page.
6Report FooterGrand totals, signatures. Printed once at the end.

Each item within an area has a unique numeric ID (e.g., 101, 102, 301). When printing programmatically, you reference items by these IDs using ITEMIDS and ITEMVALUES arrays.

Visual Designer (TEReport)

The visual designer is a full MDI application that lets users create and edit report definitions. Launch it by calling EReport() or adding a menu/toolbar button in your application.

The designer interface provides:

  • Area panel -- displays all report areas with their boundaries, drag to resize
  • Items panel -- add text labels, fields, images, barcodes, lines, boxes to any area
  • Properties panel -- set font, color, alignment, position, size, expressions for each item
  • Ruler -- visual ruler for precise positioning (mm or inches)
  • Preview -- instant preview of the report layout
  • Undo/Redo -- full undo and redo support for all changes
  • Database integration -- define database connections and field mappings within the designer
  • General settings -- paper size, orientation, margins, fonts, language

The designer supports creating new reports from scratch, opening existing .vrd files, and saving in the standard EasyReport format. It also provides backup and "Save As" functionality.

Report File Format

EasyReport stores reports as a set of INI-style text files:

FileDescription
ReportName.vrdMain report definition: general settings, paper size, orientation, margins, fonts, colors, database references, number of areas.
ReportName.v01Area 1 definition (Report Header): item positions, sizes, types, fonts, colors, expressions.
ReportName.v02Area 2 definition (Page Header)
ReportName.v03Area 3 definition (Detail)
ReportName.v04Area 4 definition (Detail Variable)
ReportName.v05Area 5 definition (Page Footer)
ReportName.v06Area 6 definition (Report Footer)

The .vrd file and its companion area files are plain text and can be distributed alongside your application. The engine reads them at runtime using standard INI file Funciones.

Example: Simple Report from DBF

#include "FiveWin.ch"
#include "EasyRep.ch"

function PrintClients( lPreview, oWnd )

   local oVRD

   USE clients

   // Open the report with preview
   EASYREPORT oVRD NAME ".\reports\clients.vrd" ;
              PREVIEW lPreview OF oWnd

   // Loop through records and print Detail area (area 3)
   DO WHILE ! Eof()
      PRINTAREA 3 OF oVRD ;
         ITEMIDS    { 101, 102, 103 } ;
         ITEMVALUES { clients->name, clients->city, clients->phone }
      SKIP
   ENDDO

   // Finalize the report
   END EASYREPORT oVRD

   USE

return nil

The ITEMIDS array contains the numeric IDs assigned to items in the visual designer. The ITEMVALUES array provides the corresponding data values. The engine matches them by position: item 101 gets the first value, item 102 gets the second, and so on.

Example: Order Form with Page Breaks

This example from samples/EasyReport/examples/SourceExample1.prg demonstrates a complete order form with header, detail lines, memo content, automatic page breaks, and a footer with totals.

// EasyReport: Order form

FUNCTION PrintOrder( lPreview )

   LOCAL i, nTotal, nVAT, oVRD, lLastPosition

   // Open the report
   EASYREPORT oVRD NAME ".\examples\EasyReportExample1.vrd" ;
              PREVIEW lPreview OF oWnd ;
              PRINTDIALOG IIF( lPreview, .F., .T. )

   IF oVRD:lDialogCancel = .T.
      RETURN .F.
   ENDIF

   // Set header data using Cargo array
   oVRD:Cargo := { "Nr. 12345  Date: 5.9.2004", ;   // 1 order number
                   "Testclient",               ;     // 2 address line 1
                   "z.H.: Timm Sodtalbers",    ;     // 3 address line 2
                   "Plaggefelder Str. 42",     ;     // 4 address line 3
                   "26632 Ihlow",              ;     // 5 address line 4
                   "257001",                   ;     // 6 barcode value
                   "Company Name" + CRLF + ;         // 7 company memo
                      "Street 42" + CRLF + "City", ;
                   MemoRead( ".\examples\EasyReportExample.txt" ) }

   // Open database and print order line items
   USE .\EXAMPLES\EXAMPLE
   nTotal := 0

   DO WHILE ! Eof()

      // Print detail area with item data
      PRINTAREA 3 OF oVRD ;
         ITEMIDS    { 104, 105, 106, 107 } ;
         ITEMVALUES { EXAMPLE->UNIT,                             ;
                      AllTrim( Str( EXAMPLE->PRICE, 10, 2 ) ),   ;
                      AllTrim( Str( EXAMPLE->TOTALPRICE, 11, 2 )),;
                      AllTrim( ".\EXAMPLES\" + EXAMPLE->IMAGE ) }

      nTotal += EXAMPLE->TOTALPRICE

      // Check if page break is needed before next record
      IF oVRD:nNextRow > oVRD:nPageBreak
         PAGEBREAK oVRD
      ENDIF

      SKIP

   ENDDO

   CLOSE

   // Print footer with totals
   nVAT := nTotal * 0.16
   AAdd( oVRD:Cargo, AllTrim( Str( nTotal,        12, 2 ) ) )  //  9
   AAdd( oVRD:Cargo, AllTrim( Str( nVAT,          12, 2 ) ) )  // 10
   AAdd( oVRD:Cargo, AllTrim( Str( nTotal + nVAT, 12, 2 ) ) )  // 11

   PRINTAREA 5 OF oVRD

   END EASYREPORT oVRD

RETURN .T.

Page Break Logic

When printing detail records in a loop, you often need to check if the next area will fit on the current page. Use oVRD:nNextRow and oVRD:nPageBreak together with oVRD:aAreaHeight for precise control: 

DO WHILE ! Eof()

   // Check if detail area (3) will fit, considering the footer area (5)
   IF oVRD:nNextRow + oVRD:aAreaHeight[3] > ;
      oVRD:nPageBreak - oVRD:aAreaHeight[5]
      PAGEBREAK oVRD
   ENDIF

   PRINTAREA 3 OF oVRD ;
      ITEMIDS { 101, 102 } ;
      ITEMVALUES { field->name, field->value }

   SKIP

ENDDO

Tips and Best Practices

Design Workflow

  1. Start by opening the designer with EReport() and creating a new report.
  2. Define your paper size, orientation, and margins in General Settings.
  3. Add areas (header, page header, detail, footer) as needed.
  4. Place items in each area and assign numeric IDs to items that will receive data programmatically.
  5. Save the .vrd file and note the item IDs.
  6. Write code using EASYREPORT / PRINTAREA / END EASYREPORT commands, matching IDs to data.
  7. Test with PREVIEW .T. before sending to a physical printer.

General Tips

  • Always check oVRD:lDialogCancel after opening a report with PRINTDIALOG -- the user may have cancelled.
  • Use oVRD:Cargo for passing static data (addresses, titles, dates) and ITEMIDS/ITEMVALUES for dynamic per-record data.
  • For memo fields, use oVRD:Cargo2 and print them in Area 4 (Detail Variable) for auto-sizing.
  • Implement page break checks before printing each detail record to avoid items being cut off at the page boundary.
  • Use PRINTIDS during development to see item IDs printed on the report, making it easy to map IDs in your code.
  • The lCheck parameter allows a dry run to calculate total pages before the actual print, useful for "Page X of Y" footers.
  • Report files (.vrd and .v0x) are plain text INI files -- they can be version-controlled and diff'd.
  • Distribute the report files with your application and let end-users customize layouts using the designer without recompiling.

Legacy Compatibility

The original VRD class names are supported through preprocessor translations in easyrep.ch: 

#xtranslate VRD()                        => FW_EReport()
#xtranslate VRD_PrReport( [<params,...>] ) => FWER_PrReport( <params> )
#xtranslate VRDITEM()                    => FWER_Item()
#xtranslate VRDBARCODE()                 => FWER_BarCode()

Existing code using the older VRD naming convention will continue to work without changes.
