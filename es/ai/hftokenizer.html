HFTokenizer - Tokenizador BPE de HuggingFace

Fuente: source/classes/hftokenizer.prg

HFTokenizer es una implementación en Harbour puro del tokenizador BPE a nivel de bytes (byte-level Byte-Pair-Encoding) de HuggingFace, el que usan GPT-2 y muchos modelos derivados. Carga un archivo tokenizer.json estándar (descargado del Hub de HuggingFace) y reproduce la tokenización de GPT-2 bit a bit: el mismo texto produce exactamente los mismos ids de tokens.

Esto conecta la clase Transformer de FiveWin con vocabularios reales, de modo que un modelo se pueda entrenar o ejecutar sobre texto real en vez de ids de tokens de juguete.

Tubería de Tokenización

Obtener un tokenizer.json

Descarga un tokenizador del Hub de HuggingFace. Para GPT-2:

https://huggingface.co/gpt2/resolve/main/tokenizer.json

El archivo contiene un objeto model con un mapa vocab (token → id) y una lista merges (reglas de fusión BPE ordenadas). El archivo de GPT-2 pesa unos 1,35 MB con 50 257 tokens y 50 000 fusiones.

Métodos

MétodoDescripción
New( cFile )Construye los mapas byte → unicode y, si se indica cFile, carga ese tokenizer.json.
Load( cFile )Analiza un tokenizer.json: lee model.vocab y model.merges (acepta formato de cadena o de par). Devuelve NIL si el archivo es inválido.
Encode( cText )Tokeniza el texto en un array de ids de tokens (base 0, ids crudos de HuggingFace).
Decode( aIds )Reconstruye el texto original a partir de un array de ids de tokens.
Size()Número de tokens del vocabulario cargado.

Ejemplo

#include "FiveWin.ch"

FUNCTION Main()
   LOCAL oTok, aIds, cBack

   oTok := HFTokenizer():New( "gpt2.tokenizer.json" )

   ? oTok:Size()                       // 50257

   aIds := oTok:Encode( "hello world" )
   ? hb_ValToExp( aIds )               // { 31373, 995 }

   cBack := oTok:Decode( aIds )
   ? cBack                             // hello world

RETURN NIL

Cómo Funciona

1. Mapa byte → unicode

El byte_to_unicode de GPT-2 asigna cada uno de los 256 valores de byte a un carácter Unicode imprimible, de modo que ningún byte sea no imprimible ni espacio dentro del paso BPE. El byte de espacio (0x20) se convierte célebremente en U+0120 (mostrado como Ġ). La clase construye este mapa una sola vez en New(), junto con su inverso exacto para Decode().

2. Pre-tokenizador

Antes del BPE, el texto se divide en piezas siguiendo la expresión regular de GPT-2, que mantiene unidas las contracciones ('s 't 're 've 'm 'll 'd) y adjunta un único espacio inicial al grupo de palabra, número o símbolo que le sigue (el conocido comportamiento " ?\p{L}+"). La implementación cubre letras ASCII, dígitos, símbolos y secuencias de espacios; cualquier byte no ASCII se maneja de forma transparente mediante el mapeo a nivel de bytes.

3. Fusiones BPE

Cada pre-token se convierte a sus caracteres Unicode mapeados y luego se fusiona de forma voraz: en cada paso se une el par de símbolos adyacente con el menor rango de fusión (su posición en model.merges), hasta que no queda ningún par conocido. Los tokens resultantes se buscan en model.vocab para producir los ids.

Validación

El tokenizador se verifica contra el tokenizer.json real de GPT-2. Los ids de referencia conocidos coinciden exactamente:

TextoIds de tokens
"hello world"{ 31373, 995 }
"Hello world"{ 15496, 995 }

Un ciclo completo Decode( Encode( texto ) ) == texto se cumple para frases con puntuación, contracciones, dígitos, múltiples espacios y saltos de línea. El banco de pruebas sin interfaz es samples/ai/hftoktest.prg.

Puente hacia el Transformer

HFTokenizer es el primer paso de un esfuerzo continuo para integrar el Transformer de FWH con el ecosistema de HuggingFace, de modo que las aplicaciones FiveWin puedan reutilizar recursos de IA del mundo real — tokenizadores hoy, datasets y (cuando la arquitectura lo permita) pesos preentrenados después.

El vocabulario de GPT-2 tiene 50 257 tokens — mucho más de lo que necesita un modelo pequeño entrenado desde cero. Por eso el puente construye un vocabulario compacto que contiene sólo los tokens que aparecen en tu corpus, mapeando los ids de HuggingFace a ids locales densos de base 1:

  1. Tokeniza el corpus con HFTokenizer:Encode.
  2. Recoge los ids de tokens únicos en un vocabulario compacto de base 1 más sus cadenas de tokens.
  3. Crea el Transformer con ese vocabulario y entrénalo (ForwardSeq / BackwardSeq).
  4. Genera ids locales, mapéalos de vuelta a ids de HuggingFace y haz Decode a texto.

Ejemplo de extremo a extremo: samples/ai/hflmtest.prg.

Notas

  • Encode devuelve ids crudos de HuggingFace (base 0). Al alimentar un vocabulario base 1 de la clase Transformer de FiveWin, suma 1 (o mapea a través de tu propio vocabulario).
  • Se aceptan ambos formatos de fusión: cadenas heredadas "tokA tokB" y los pares más nuevos [ "tokA", "tokB" ].
  • El tokenizer.json es un recurso descargable y no se distribuye con FiveWin; descárgalo una vez del Hub.
  • Los tokens especiales/añadidos (p.ej. <|endoftext|>) están en el vocabulario y se resuelven como cualquier otro token cuando aparecen literalmente en la entrada.
