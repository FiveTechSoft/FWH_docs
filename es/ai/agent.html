Class Agent

Fuente: source/classes/agent.prg

source\classes\agent.prg

An agente IA de codificación autónomo for Harbour/FiveWin. Implements the same motor agentic que impulsa Agents Web: chat streaming, herramientas reales, tools dinámicas, skills y multi-agente vía hb_threadStart().

Métodos Principales

New( cKey, [cModel] ) → Agent

Constructor. Inicializa tools, skills, carga estado guardado. Modelo por defecto: deepseek-v4-pro.

Run( cPrompt ) → lastAssistantMessage

Bucle principal: observar → decidir → actuar. Máx nMaxSteps iteraciones (defecto 14). Devuelve la última respuesta de texto. Las tool calls intermedias se ejecutan y sus resultados se incorporan a la conversación.

Step() → cResponse

Envía la conversación actual a DeepSeek (POST api.deepseek.com/chat/completions), devuelve la respuesta bruta. Actualiza métricas de tokens. Es el RPC central del LLM.

BuildSystemPrompt()

Construye el system prompt: instrucciones base + skills activos + lista de user tools + objetivo/plan.

BuildToolsArray() → aTools

Devuelve el array completo de tools en formato OpenAI (integradas + usuario) para la petición LLM.

Herramientas Dinámicas

Las tools persisten en agent_state/user_tools.json. Las integradas son fijas; las del usuario son dinámicas y sobreviven entre sesiones.

Hooks

Los hooks son callbacks que se ejecutan antes/después de cada tool call, permitiendo logging, auditoría, validación y cancelación sin modificar el código de las tools.

MethodDescription
RegisterHook(cName,cEvent,bBlock,[nPriority])Registra un hook. Eventos: pre_tool_use, post_tool_use, on_error, on_complete. Pre-hooks devuelven .F. para cancelar.
UnregisterHook(cName)Elimina un hook por nombre.
ListHooks()Lista todos los hooks registrados con evento, prioridad y estado.
RunHooks(cEvent,hContext)Ejecuta todos los hooks de un evento. Llamado internamente por ExecTool().
LLMRegisterHook(cName,cEvent,cAction,[nPriority])Registra hook desde el LLM usando acciones predefinidas: log, audit, block_shell, block_delete, block_write.

El hash de contexto hContext contiene: {name, args, result}. Los pre-hooks reciben el nombre de la tool y sus argumentos; devuelven .F. para cancelar. Los post-hooks reciben el resultado y pueden modificar hContext["result"].

Skills

MethodDescription
CreateSkill(cName,cContent,[cDir])Escribe archivo skill en skills/name.md
ToggleSkill(cName,lOn)Activa/desactiva sin borrar el archivo
ActiveSkillsPrompt()Devuelve string de prompt con skills activos

5 skills integrados: reviewer, summarizer, refactor, documenter, tester. Los skills inyectan instrucciones reutilizables en el system prompt. Moldean CÓMO el agente piensa, no QUÉ puede hacer (eso lo manejan las tools).

Orquestación Multi-Agente

La clase Agent proporciona un framework completo de orquestación con 8 métodos para coordinar múltiples agentes: despacho paralelo, pipelines secuenciales, roles especializados, contexto compartido, reintentos, timeout, agregación y monitoreo.

Roles

Cada Agent tiene una propiedad cRole y cRolePrompt. Los roles definen la especialización del agente. El prompt del rol se inyecta en el system prompt.

oDev := Agent():New( cKey )
oDev:cRole       := "developer"
oDev:cRolePrompt := "Eres desarrollador senior. Escribe código limpio y documentado."

DispatchAgents( aTasks, cContract ) → aResults

Fan-out paralelo: lanza hasta 4 sub-agentes simultáneamente. Cada sub-agente hereda el rol, contexto compartido y modelo del padre. Los resultados se recolectan sincrónicamente.

DispatchAgentsPipeline( aTasks, cContract ) → aResults

Pipeline secuencial: la salida de cada agente alimenta al siguiente. Útil para cadenas de tareas dependientes donde el paso N necesita el resultado del paso N-1.

aResults := oAgent:DispatchAgentsPipeline( { ;
   "Analiza los requisitos de la app", ;
   "Diseña el schema de la base de datos", ;
   "Genera el código backend", ;
   "Escribe los tests unitarios" }, cContract )

DispatchAgentsWithRoles( aAgentDefs, cContract ) → aResults

Fan-out con roles especializados. Cada definición es un hash con: task, role, rolePrompt, model, nMaxSteps. Los agentes corren en paralelo con su propia configuración.

aDefs := { ;
   { "task" => "Diseña el schema", "role" => "analyst", ;
     "rolePrompt" => "Eres analista de datos.", "nMaxSteps" => "8" }, ;
   { "task" => "Implementa la API", "role" => "developer", ;
     "model" => "gpt-4o", "nMaxSteps" => "10" }, ;
   { "task" => "Escribe tests", "role" => "tester", ;
     "rolePrompt" => "Eres tester QA.", "nMaxSteps" => "6" } }
aResults := oAgent:DispatchAgentsWithRoles( aDefs, cContract )

Contexto Compartido (Patrón Blackboard)

Los agentes se comunican vía un hash compartido. Los cambios se sincronizan de vuelta al padre tras completar cada sub-agente. El contexto se inyecta en el system prompt.

MethodDescription
GetSharedContext([cKey])Obtener todo el contexto o una clave específica.
SetSharedContext(cKey, xValue)Establecer una clave en el contexto compartido.
oAgent:SetSharedContext( "schema", "CREATE TABLE users..." )
// los sub-agentes verán esto en su system prompt

AggregateResults( aResults, cMethod ) → cCombined

Combinar resultados de múltiples agentes. Métodos:

  • "join" — concatenar con cabeceras (por defecto)
  • "json" — codificar como array JSON
  • "summary" — resumen en bullets vía LLM

RetrySubAgent( cTask, cContract, nMaxRetries ) → cResult

Reintentar un sub-agente fallido hasta nMaxRetries veces (por defecto 3). Cada intento corre en una instancia nueva con recuperación de errores.

SubAgentRunWithTimeout( cTask, cContract, nTimeout ) → cResult

Ejecutar un sub-agente con límite de tiempo en segundos (por defecto 120). Usa el mecanismo de interrupción para abortar si excede el timeout.

NotifyProgress( cAgentName, cStatus, cMsg )

Enviar notificaciones de progreso. Configurar bOnAgentProgress para recibir callbacks.

oAgent:bOnAgentProgress := {| cName, cStatus, cMsg | ;
   ? cName + ": " + cStatus + " — " + cMsg }

SubAgentRun( cTask, cContract ) → cResult

Ejecución individual de sub-agente. Llamado por DispatchAgents() en su propio hilo.

Planificación

GeneratePlan( cGoal ) → aPlan

Pide al LLM que divida el objetivo en 3-6 pasos JSON. Devuelve un array de {title, state} where the first step is "active" and the rest "pending".

ExecutePlan()

Ejecuta el plan secuencialmente: para cada paso "active", llama a Run() con la descripción, lo marca "done", activa el siguiente. Para cuando todos están completos.

Persistencia

MethodDescription
SaveState(cDir)Guarda user tools y skills activos en user_tools.json
LoadState(cDir)Restaura del disco al iniciar. También carga skills del directorio skills/.

Ejemplo Completo

PROCEDURE Main()
   LOCAL oAgent, cResult

   oAgent := Agent():New( "sk-xxxx" )

   // Registrar una tool personalizada
   oAgent:RegisterTool( "contar", ;
      "Cuenta lineas, palabras y caracteres de un archivo", ;
      "contar.py" )

   // Crear y activar un skill
   oAgent:CreateSkill( "prueba", ;
      "Responde siempre en español." + CRLF + ;
      "Verifica el disco antes de escribir código." + CRLF + ;
      "Escribe tests automáticamente." )
   oAgent:ToggleSkill( "prueba", .T. )

   // Registrar un hook para auditar todas las tool calls
   oAgent:RegisterHook( "audit_log", "post_tool_use", ;
      {| h | ? "AUDIT:", h["name"], hb_ValToStr( h["args"] ) }, 50 )

   // Registrar un hook para bloquear comandos shell (pre-hook)
   oAgent:RegisterHook( "safe_mode", "pre_tool_use", ;
      {| h | iif( h["name"] == "shell", .F., .T. ) }, 10 )

   // O usar presets predefinidos para el LLM
   oAgent:LLMRegisterHook( "llm_audit", "post_tool_use", "audit" )

   // Generate and execute a plan
   oAgent:GeneratePlan( "Crea una app TODO en PHP+SQLite" )
   oAgent:ExecutePlan()

   // Or run directly
   cResult := oAgent:Run( "Explica qué hay en el disco" )
   ? cResult

   // === Orquestación multi-agente ===
   oAgent:nSubAgentTimeout := 60

   // Despacho paralelo con roles
   aDefs := { ;
      { "task" => "Diseña el schema", "role" => "analyst", ;
        "rolePrompt" => "Eres analista de datos." }, ;
      { "task" => "Implementa la API", "role" => "developer", ;
        "model" => "gpt-4o" }, ;
      { "task" => "Escribe tests", "role" => "tester" } }
   aResults := oAgent:DispatchAgentsWithRoles( aDefs, cContract )

   // Agregar resultados
   cSummary := oAgent:AggregateResults( aResults, "summary" )
   ? cSummary

   // Pipeline: tareas dependientes secuenciales
   aResults := oAgent:DispatchAgentsPipeline( { ;
      "Analiza requisitos", "Diseña schema", "Implementa API" }, cContract )

   oAgent:UsageReport()
RETURN

Notas

  • Requiere Harbour MT VM for DispatchAgents(). Enlazar contra libhbvmmt.
  • API Key: configurar vía variable de entorno DEEPSEEK_API_KEY o constructor.
  • Streaming: Step() usa streaming SSE con stream_options para métricas de tokens en tiempo real.
  • Orquestación: DispatchAgents() paralelo, DispatchAgentsPipeline() secuencial, DispatchAgentsWithRoles() con roles especializados. Contexto compartido vía SetSharedContext(). Reintentos, timeout y agregación incluidos.
  • Roles: configurar cRole y cRolePrompt para especializar cada agente. El prompt del rol se inyecta en el system prompt automáticamente.
  • Hooks: callbacks pre/post en la ejecución de tools. Usar RegisterHook() para codeblocks personalizados, o LLMRegisterHook() con presets (log, audit, block_*).
  • Contrato: el parámetro cContract en DispatchAgents() es crítico. Sin él, los sub-agentes paralelos divergen en convenciones de nombres. Proporciona siempre nombres exactos de tablas, columnas, funciones y rutas de archivos.
  • Ejemplo: samples\agenticai\agenticai2.prg — una app FiveWin GUI completa usando la Class Agent con panel de chat TWebView2.
