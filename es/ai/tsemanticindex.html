TSemanticIndex - Búsqueda Semántica sobre DBF/SQL

Fuente: source/classes/tsemanticindex.prg

TSemanticIndex lleva la búsqueda por significado a las apps de datos FiveWin. En vez de LIKE '%palabra%', encuentra los registros cuyo texto está más cerca en significado de una consulta — p.ej. buscar "descontento por entrega tardía" recupera una nota que dice "el pedido llegó dos semanas tarde y el cliente está furioso", aunque no compartan palabras.

Funciona convirtiendo el texto en vectores de embedding y ordenando los registros por similitud coseno. Es la primera de las clases utilitarias "FWAI" — ver la hoja de ruta PyTorch-lite.

Cómo funciona

flowchart LR subgraph Indexar F[Campo de texto DBF/SQL] --> E1[Embed por registro] --> N1[Normalizar] --> S[(vectores + ids)] end subgraph Consulta Q[Texto consulta] --> E2[Embed] --> N2[Normalizar] --> D[Producto punto vs todos] --> R[Top-N registros por score] end S --> D

Los vectores se guardan unit-normalizados, así la similitud coseno es un simple producto punto. Los scores van de 1.0 (significado idéntico) hacia abajo.

Agnóstico de backend

New( bEmbed ) recibe un codeblock { |cText| -> vector }, así los embeddings pueden venir de cualquier fuente — la Inference API de HuggingFace, un modelo local, o tu propia función. Para usar MiniLM de HuggingFace vía TEmbeddings: 

oEmb := TEmbeddings():New()                 // necesita HF_API_KEY (MiniLM 384-dim)
oIdx := TSemanticIndex():New( { |c| oEmb:GetEmbeddings( c ) } )

Para datos privados/offline, enchufa un modelo de embeddings local tras el mismo codeblock (ver guía local-vs-cloud de la hoja de ruta) — el código del índice no cambia.

Métodos

MétodoDescripción
New( bEmbed )Crea un índice usando el codeblock de embedding dado.
Add( cText, uId )Hace embedding de cText y lo guarda bajo el id uId.
AddVector( aVec, uId )Guarda un vector precalculado bajo uId (sin embedding).
IndexDbf( cField, bId )Recorre el área de trabajo actual indexando cField; el id por defecto es RecNo() (o Eval(bId)).
Search( cQuery, nTop )Devuelve { { uId, nScore }, ... } con las nTop mejores coincidencias, la mejor primero.
Size()Número de registros indexados.
Save( cFile ) / Load( cFile )Persiste / restaura el índice (ids + vectores).

Ejemplo: buscar en notas de clientes

USE customers
oEmb := TEmbeddings():New()
oIdx := TSemanticIndex():New( { |c| oEmb:GetEmbeddings( c ) } )
oIdx:IndexDbf( "NOTES" )                     // un vector por registro, id = RecNo()
oIdx:Save( "customers.idx" )                 // construir una vez, reutilizar

aHits := oIdx:Search( "descontento por entrega tardía", 10 )
for each h in aHits
   ( customers )->( dbGoto( h[ 1 ] ) )       // h[1] = RecNo, h[2] = score
   ? customers->NAME, h[ 2 ]
next

Notas

  • Construye el índice una vez y haz Save; recárgalo al arrancar. Re-embebe sólo los registros que cambian.
  • Los embeddings cloud (TEmbeddings/HF) son lo más fácil para empezar; para datos sensibles o alto volumen, un modelo de embeddings local evita el coste por llamada y mantiene el dato en la máquina.
  • La búsqueda coseno aquí es un barrido lineal en Harbour — bien para miles de registros. Para conjuntos muy grandes, agrupa los vectores en una matriz FW_Tensor y ordena con una sola multiplicación de matrices.
  • El codeblock embedder debe devolver un array numérico; Add ignora registros cuyo embedding falla (p.ej. error de API).
